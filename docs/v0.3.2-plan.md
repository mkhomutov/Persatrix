## Why this plan exists

Three reasons v0.3.2 deserves an umbrella rather than two parallel RFC PR plans:

1. **RFC 0023 carries Phase 0 blockers that go non-additive once Phase 1 lands.** [RFC 0023 §Open Questions](rfcs/0023-llm-call-leasing.md#open-questions) #1 (transport) and #5 (tokeniser parity) both change the proto contract and the Python client surface, so they must close before Phase 1. [v0.3.x-sequencing.md §Decision/next steps](v0.3.x-sequencing.md#decision--next-steps) step 3 asked for resolution before v0.3.1 shipped; v0.3.1 shipped with both still open. This plan makes their resolution a tracked hard gate on the RFC 0023 PR plan's PR 1.
2. **The facade freeze is load-bearing for v0.4.0.** RFC 0029 Phase 1 freezes the `MemoryStore` facade signature, and [RFC 0028](rfcs/0028-agent-decision-policy-engine.md) (v0.4.0) is hard-blocked on it — it *"must not begin until Phase 1 ships — otherwise `DecisionRecord` schema lands against the legacy facade …"* ([RFC 0029 §Phased Implementation Plan](rfcs/0029-personal-society-storage-split.md#phased-implementation-plan)). Promoting "facade frozen" to a plan-level acceptance gate makes the v0.4.0 prerequisite explicit.
3. **The per-version one-story contract needs an arbiter.** v0.3.2's story is *"cost is structurally bounded, and the memory facade is frozen for the v0.4.0 Postgres split"* ([§Version Map](../ROADMAP.md#version-map)). RFC 0030 Phase 1 becomes shippable once RFC 0023 Phase 1 lands; the umbrella resolves that pressure against the contract instead of mid-implementation.

The two RFCs are independent — disjoint surfaces (wallet / LLM-call path vs. memory facade); [RFC 0029](rfcs/0029-personal-society-storage-split.md#phased-implementation-plan) confirms its Phase 1 is independent of everything except the shipped RFC 0011. The umbrella owns "what order, in what step, by what gate" — nothing else.

## Decision on the uncommitted v0.3.x rows

The [v0.3.x-sequencing.md §Amendment 2026-05-12 §Updated decision](v0.3.x-sequencing.md#updated-decision) table left one row — *"v0.3.x — uncommitted: RFC 0030 Phase 1; RFC 0031 Phases 2–4"* — marked **"Deferred to v0.3.2 plan opening."** This plan is that opening; the decision:

- **RFC 0030 Phase 1 is not absorbed into v0.3.2.** It is unblocked the moment RFC 0023 Phase 1 lands (the [Layer 1 gate](rfcs/0030-multi-agent-conversation-governance.md#phased-implementation-plan)), but absorbing it dilutes the v0.3.2 story into "cost + facade + governance" — three deliverables, not one. Same call the [v0.3.1 plan](v0.3.1-plan.md#risk-and-mitigations) made. Re-homed to the v0.3.3 plan opening or a dedicated v0.3.x plan.
- **RFC 0031 Phases 2–4 are not absorbed into v0.3.2.** Recall filtering, the `persatrix session …` CLI, and the operator guide are session-ergonomics work with no dependency on either v0.3.2 RFC. Same deferral as RFC 0030 Phase 1.

Both rows stay `v0.3.x — uncommitted` in the sequencing doc until the plan that absorbs them opens.

## Acceptance for v0.3.2

The user-facing promise — *"every LLM call in the system passes through a wallet lease before issuing, and the `MemoryStore` facade is the single, frozen path to agent memory"* — is met when:

- All five LLM-call origins — workflow task, chat, autonomous TICK, sub-agent spawn ([RFC 0023 §Goal #1](rfcs/0023-llm-call-leasing.md#goals)), and channel-message reply ([§Phased Implementation Plan](rfcs/0023-llm-call-leasing.md#phased-implementation-plan) Phase 6) — acquire a server-issued lease before invoking the provider.
- New manual tests `MT-COST-003` (chat budget exceed) and `MT-COST-004` (TICK budget exhaustion → idle) ship green ([RFC 0023 §Test Strategy](rfcs/0023-llm-call-leasing.md#test-strategy)).
- The README known-limitations line on chat traffic bypassing `BudgetEnforcer` is deleted; the CHANGELOG `[0.3.2]` section calls out the closed bypass ([v0.3.x-sequencing.md §v0.3.2 gates](v0.3.x-sequencing.md#v032--cost-gate)).
- Wallet acquire+settle round-trip measures p99 ≤ 5 ms on loopback ([RFC 0023 §Goal #6](rfcs/0023-llm-call-leasing.md#goals)) — informational, not a build gate, but recorded in the release-prep MT report.
- `MemoryStore` is the only path callers reach `EpisodicMemory` / `RelationshipMemory` through; a lint rule blocks new direct-`aiosqlite` imports outside `agents/memory/` ([RFC 0029 §Phased Implementation Plan](rfcs/0029-personal-society-storage-split.md#phased-implementation-plan)).
- No regression on the persona hot path: the [RFC 0029 perf gate](rfcs/0029-personal-society-storage-split.md#test-strategy) (`tests/perf/personal_tier_latency.py`) passes against the Phase 1 post-merge baseline.

Out of acceptance: per-call lease *policy* differences by cause (RFC 0023 Phase 7+); capability tokens, Postgres society backend, migration tooling (RFC 0029 Phases 2–6); RFC 0024 idle-cost work; RFC 0030 Phase 1 conversation governance; RFC 0031 Phases 2–4 recall filtering and CLI.

## Dependency Graph (RFC-level)

Source of truth lives in [v0.3.x-sequencing.md §New dependency chain](v0.3.x-sequencing.md#new-dependency-chain). This is the v0.3.2 slice:

```
v0.3.1 complete (✅ released 2026-05-17)
    │
    ├── RFC 0023 (LLM Call Leasing — full, Phases 1–6)
    │       ├── depends on RFC 0006 (closed) + RFC 0017 (closed)
    │       ├── hard gate: RFC 0023 OQ #1 (transport) + OQ #5 (tokeniser parity)
    │       │             resolved before the PR plan's PR 1 (proto + skeleton) opens
    │       └── Phase 6 (channel-message origin) lands in-window — RFC 0011 has shipped
    │
    └── RFC 0029 Phase 1 (MemoryStore facade promotion — no Postgres)
            ├── depends on RFC 0011 (closed) — channel-history caller migrates to MemoryStore
            ├── consumes RFC 0031 Phase 1 (shipped v0.3.1) — facade carries session_id
            └── routes RFC 0026 facts-tier calls (shipped v0.3.1) through the new facade
                 │
                 →  v0.3.2 — Cost Gate + Facade Freeze
```

**Ordering**: the two RFCs are mutually independent and implement in parallel. The only internal sequencing is *within* RFC 0023 — PR 1 (proto + wallet skeleton) does not open until the Phase 0-blocker open questions resolve.

> **Maintenance**: if you edit dependency direction here, update [v0.3.x-sequencing.md §New dependency chain](v0.3.x-sequencing.md#new-dependency-chain) in the same commit.
