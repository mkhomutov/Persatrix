**The release gate is the live arc — and it carries three evidence obligations.** A green leg that never exercised the contested surface is not proof, and Leg 5 can pass for the wrong reason in three distinct ways:

1. **The withhold must be the gate's, not the tenant's.** Under `auth.mode: enabled` the v0.3.15 tenant partition already withholds Alice's DM content from any turn she did not cause, so a persona that stays quiet on Bob's turn proves nothing — and a quiet reply on Alice's own turn is equally consistent with the fact never having been a §D-admitted candidate. The artifact is the per-entry **`audience egress` record**, quoted verbatim: her entry at *withhold-disjoint*, `withheld` 1, read *after* the admitted set. Alice asks ([scope lock 6](v0.3.16-scope-locks.md)'s vacuity rule); any other cause is re-run, not counted. The `disabled` run then removes the tenant axis entirely, so **both runs are required** — one shows the record, the other shows audience alone can withhold.
2. **A fetch-failed count, not silence.** *withhold-unknown-fetch-failed* cannot occur offline (the eval driver's roster seam never fails) and `live` **admits** it — so a run whose rosters were never resolved reads as every entry admitted-as-unknown, which looks like a gate defect and is an infrastructure fault. The report carries the count from **both** runs; a non-zero count is fixed before the leg counts ([Edge Case 4](manual-tests/MT-PERSONA-CONFIDENTIALITY-001.md#edge-case-4-leg-5s-room-turns-out-to-hold-nobody-new)), and a room whose member set adds nobody gives *admit*, correctly, and has measured nothing.
3. **The fact must have consolidated with DM provenance.** The check reads `source_channel_id`; a NULL there measures *no-provenance* (admitted under `live`), and a fact that never consolidated is a **failed** leg, not a vacuous pass (Edge Case 2). The artifact is the `facts` row — `(subject, protection_level, source_channel_id)` with the id starting `dm:` — quoted **before** 5c is sent.

Legs 1–4 run first as the regression baseline of the existing §D gate; the [v0.3.12 run](manual-tests/v0.3.12-execution-report.md#mt-persona-confidentiality-001--learn-without-leaking-live-anthropic) (Leg 3 on its one in-room retry, Leg 4 inconclusive per its own criterion) is the reading to compare against, not a bar to beat.

## Track B — Release Engineering

### PR 3 — Version Bump + Changelog Curation & Dating

**Branch**: `feature/v0316-release-prep-version-bump`

Scope: `make bump-version VERSION=0.3.16` + `cd cli && cargo update --workspace`; `make all` + `make ui`; curate `[Unreleased]` → dated `[0.3.16]` — the A2 and A3 bullets fold into **one** audience story, D1 + D2 into one debt-sweep story, C1 + C2 into the CI pair, the two compose fixes stay as fixes ([ISSUE-0153](issues/ISSUE-0153-compose-ports-open-on-every-interface.md) rides this release); write the **Upgrade Notes**, whose obligations are fixed here:

1. **Drop-in both ways.** Zero store migrations across all three stores; a v0.3.15 binary reads a v0.3.16 store and vice versa. The release's one property v0.3.15 could not claim.
2. **The audience trade, in lock 1's words.** [RFC 0049](rfcs/0049-memory-consolidation-gradient.md)'s "taught in a DM, known in the standup" narrows to *the standup whose every member was in the DM* — in the default three-persona rooms, no standup at all. `memory.egress.audience` defaults to **`live`**; `shadow` is the rollback lever and restores the v0.3.15 prompt byte-for-byte. The two existing-deployment notes from A3: an `auth.mode` flip (or an acting-as change) re-keys DMs, so pin `shadow` while switching; a deleted or emptied source room reads *fetch-failed* on every later turn and is admitted.
3. **The `reason_note` is now an egress surface at `DEBUG`** — unredacted, and forwarded off-host with the rest of the agent log when the shipper is on. Operators who raise an agent's log level inherit the [RFC 0051 §E](rfcs/0051-amendment-reasoning-kernel.md) consideration.
4. **The `relationship` tier's admission line** changes what a `PERSATRIX_MEMORY_PROVENANCE=1` transcript contains — ids and tokens, never the identity text.
5. **`memory_budget.tokens`** is documented, not set: absent means 1 500 and byte-identical prompts; `0` disables injection; an invalid value stops the agent at start.
6. **Tooling and deployment**: `make lint-go` refuses any golangci-lint but the pinned one; the compose stack publishes the orchestrator and observability ports on loopback only and the agents on no host port — anyone who reached them from another machine needs a tunnel or a local overlay.
7. **What stays byte-identical**: every prompt under `shadow`; the five older goldens before and after the flip; `auth.mode: disabled` on the tenant axis.

Acceptance: all five version strings at `0.3.16`; curated dated `[0.3.16]`; prior sections untouched.

**Done at PR 3 (2026-09-15)**: the evidence and its two gate deviations are in [checklist §7](v0.3.16-release-checklist.md#7-summary-checklist).
