### 3.1 Required Upgrade Notes

1. **Drop-in both ways — zero store migrations.** Channel store **v13**, persona-memory
   **19**, accounts **1**: all unchanged since the v0.3.15 tag. A v0.3.15 binary opens a
   store a v0.3.16 binary wrote, and the reverse, because neither stamps a new
   `user_version`. The one property v0.3.15 could not claim; the forward-only caution
   does not apply.
2. **The audience trade, in lock 1's words.** [RFC 0049](rfcs/0049-memory-consolidation-gradient.md)'s
   "taught in a DM, known in the standup" narrows to *the standup whose every member was in
   the DM* — in the default three-persona rooms, no standup at all. `memory.egress.audience`
   defaults to **`live`**; `shadow` is the rollback lever and restores the v0.3.15 prompt
   byte-for-byte (still trace-emitting). The persona's `recall_channel_messages` tool
   carries the same condition when `live` ([ISSUE-0158](issues/ISSUE-0158-recall-filter-audience-blind.md))
   — the side door the injection gate alone left open. Two existing-deployment notes: an
   `auth.mode` flip (or an acting-as change) **re-keys DMs**, so pin `shadow` while
   switching; a **deleted or emptied source room** reads *fetch-failed* on every later
   injection turn and is admitted (on the recall path the same room fails closed).
3. **The `reason_note` is now an egress surface at `DEBUG`** — verbatim, **unredacted**,
   and forwarded off-host with the rest of the agent log when the shipper is on (the
   orchestrator drops it on arrival). Operators who raise an agent's log level inherit the
   [RFC 0051 §E](rfcs/0051-amendment-reasoning-kernel.md) consideration. The stock compose
   files pass no `--log-level`; the default `INFO` emits nothing.
4. **The `relationship` tier's admission line** changes what a `PERSATRIX_MEMORY_PROVENANCE=1`
   transcript contains — one `persatrix.memory.tier_admitted` line with `tier=relationship`,
   the `item_id` and the tokens charged; never the identity text.
5. **`memory_budget.tokens`** is documented in `config/optimization.yaml`, not set: absent
   means 1 500 and byte-identical prompts; `0` disables injection (and, via the TICK skip,
   idle ticks); an invalid value stops the agent at start, naming the file.
6. **Tooling and deployment**: `make lint-go` refuses any golangci-lint but the pinned one
   (`make golangci-lint-install`); the compose stack publishes the orchestrator and
   observability ports on loopback only and the agents on no host port — anyone who reached
   them from another machine needs a tunnel or a local overlay; the orchestrator image
   builds on `golang:1.26-alpine` (every `make demo-*` stack was unbootable on the RC tip
   before that fix); installing the web console's dependencies needs Node `^22.22.2`,
   `^24.15.0` or `>=26` since jsdom 30, the range `web/package.json` declares since #958.
7. **What stays byte-identical**: every prompt under `shadow`; the five older goldens
   before and after the flip; `auth.mode: disabled` on the tenant axis (the audience axis
   is *allowed* to differ there — Leg 5d's whole point).

> **v0.3.16 — The persona knows who is listening**
>
> The persona weighs who is in the room before it speaks from memory.
>
> v0.3.12 let a fact taught in one room inform every other room the persona belongs to,
> and a classification gate kept confidential rooms confidential. That gate read the
> room's *label* — not its *members*: a fact learned from one person in a DM was
> admissible in an equally-classified room where a different person was present.
> Audience is now an AND-condition on the same gate: an entry is withheld from any room
> whose member set adds someone its source room did not hold, the verdict is recorded per
> entry, and the persona's own channel-recall tool obeys the same rule. Operators can
> also read *why* — the identity tier's admission line under the provenance switch, and
> the verbatim silence reason at `DEBUG`.
>
