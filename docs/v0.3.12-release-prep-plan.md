### Version state

All version-carrying components are at `0.3.11` — bump to `0.3.12` via [`bump_version.py`](../scripts/bump_version.py): `agents/pyproject.toml`, `agents/observability/{metrics,tracing}.py` (`_DEFAULT_SERVICE_VERSION` + the tracing docstring restatement), `cli/Cargo.toml` (+ `cargo update --workspace` for the lock), `internal/server/ui_handlers.go` (`defaultServiceVersion`). `web/package.json` stays `0.0.0` by design.

### Schema / migration state

**v0.3.12 advances two stores — the migration gate returns** (v0.3.11 had none):

- **Channel store v10 → v11** ([`sqlite_schema.go`](../internal/channels/sqlite_schema.go)): per-channel `classification`, backfill `internal` (RFC 0037 §C's conservative default). A newer store refuses to open under an older binary (the standing version check) — downgrade caution for the upgrade notes.
- **Persona-memory migration 16** ([`migrations.py`](../agents/memory/migrations.py) / `_migration_protection.py`): `protection_level TEXT NOT NULL DEFAULT 'internal'` + §C provenance columns on episodes/facts/notes.

Both automatic, in-transaction, versioned per the shipped discipline; migration tests run on populated pre-migration stores in CI. PR 4 additionally confirms a populated pre-v0.3.12 store pair opens and migrates cleanly on the bumped binaries.

### Wire-compatibility state

v0.3.12 adds **one additive protobuf field** to `ChannelMessageEvent` ([`proto/task.proto`](../proto/task.proto)): `classification = 31` (the §A stamp). Mixed-version skew degrades **conservatively in both directions**: an absent stamp resolves to `internal` on a v0.3.12 receiver; a pre-v0.3.12 receiver ignores the stamp entirely (its stores carry no levels until it upgrades and backfills `internal`). The auth REST surface (`/api/v1/auth/*`) is additive and inert under the default `disabled`. **One deliberate break**: the recall endpoint **4xx-rejects** a body `epoch_id` override (ISSUE-0106(b) — silent acceptance would imply isolation that does not exist); no callers exist outside tests, but any external tooling sending it breaks. The `make proto && git diff --exit-code` gate (PR 4) verifies stub sync.

### Manual test state

All three release-gating MTs are **authored**; live execution is this workstream (PR 1):

- **[MT-MEMORY-CROSSROOM-001](manual-tests/MT-MEMORY-CROSSROOM-001.md)** — the headline scenario: a project fact taught in a DM ("Atlas ships Friday") is captured as `topic.*` knowledge at close, recalled in a group channel via the live L2 widening, recalled again on the DM re-ask; a fresh-epoch leg confirms the walls that stay absolute. **The headline gate.**
- **[MT-PERSONA-CONFIDENTIALITY-001](manual-tests/MT-PERSONA-CONFIDENTIALITY-001.md)** — the confidentiality half: learn in `restricted`, act in `internal` (withheld or §E-projected — "informed by, doesn't disclose"), act back at `restricted` (verbatim), plus the §G leg that deliberately **seeds** a verbatim leak and asserts the tripwire audit record + metric.
- **[MT-AUTH-001](manual-tests/MT-AUTH-001.md)** — bootstrap on an empty `accounts.db` → the §E 401/403/200 matrix (including the agent-ingress carve-out asserted **as-expected**, with an optional non-loopback WARN sub-step) → the verified §F claim (operators also 403 cross-user) → the browser cookie session (`document.cookie` empty, foreign-Origin 403) → logout → the `disabled`-mode no-delta.

**Live-run guidance** (from implementation-phase live work): machine-pace each MT arc in one script — governance windows race idle operators; restart agents **after** the orchestrator (registry wipes on orchestrator restart); the memory-store projection column is named `text`, not `projection` (leg-verification sqlite queries); the browser leg needs loopback plain-HTTP (the `Secure` cookie is dropped elsewhere — expected, documented); `MT-AUTH-001` credentials-file token extraction: `jq -r '."http://localhost:8080".token'`.

The carried-forward v0.3.11 surface (autonomous channels, four-vendor providers, governance, cost attribution) regression-checks via the offline `make demo-autonomous` smoke + spot checks — human-channel and disabled-mode postures are pinned byte-for-byte by regression suites throughout both workstreams.
