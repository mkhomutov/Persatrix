**Out of scope**: new feature work. The three v0.3.1 RFC workstreams are fully landed — RFC 0026 `✅ Implemented`, RFC 0031 Phase 1 and RFC 0034 Phase 1 `⚠️ Partially Implemented` — with **no outstanding implementation or closeout PRs** (see [§Current state](#current-state-baseline-2026-05-16)). **Documentation timing policy** (carry-forward from [v0.3.0 release-prep plan](v0.3.0-release-prep-plan.md)): public docs updated *before* tag for everything that ships in `v0.3.1`; release artifacts that only exist post-tag (version/tag links, release URL, published-date references) handled by [v0.3.1-plan Phase 5](v0.3.1-plan.md#phase-5--tag-and-post-release-follow-up).

  - **[Breaking]** `ChatRequest.session_id` / `ChatResponse.session_id` JSON key renamed to `chat_session_id` (RFC 0031 OQ #8 — proto field numbers preserved, JSON / proto-text consumers must migrate). Preserve the seeded `[Unreleased]` row verbatim.

  - New `PERSATRIX_SESSION_ID` env var — read at orchestrator + persona-runtime boot, stamped on every storage write; unset ⇒ `legacy` carve-out with an INFO boot line. Set the **same value in both processes** to keep a run coherent.

  - **`make reset` deprecation breadcrumb** — `make reset` remains the supported cross-run storage-isolation path; RFC 0031 Phase 3's `persatrix session …` CLI will succeed it in a later v0.3.x patch.
