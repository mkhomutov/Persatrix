**Goal**: make the v0.3.12 promise hold everywhere it was made. v0.3.12 shipped on three explicit maintainer calls, each recorded in the published release body's Known Gaps: [ISSUE-0118](issues/ISSUE-0118-tool-recall-bypasses-epoch-session-scopes.md) (agent-initiated memory-tool recalls bypass the per-request epoch/session scopes — the F-3 leak class through the tool side door, found live), [ISSUE-0121](issues/ISSUE-0121-crossroom-person-identity-legs-never-run-live.md) (the person-identity half of the cross-room headline has never been verified live — [MT-MEMORY-CROSSROOM-001](manual-tests/MT-MEMORY-CROSSROOM-001.md) v1.1 legs 1b/2b), and [ISSUE-0114](issues/ISSUE-0114-per-channel-cascade-depth-override.md) (per-channel cascade-depth override, cut at release-prep PR 2). This release closes all three; the scope was ratified by the [sequencing Amendment 2026-08-02](v0.3.x-sequencing.md#amendment-2026-08-02--v0313--v0314-the-two-release-tail-to-v040), whose next-steps item 2 this plan executes.

Unlike v0.3.11/v0.3.12 this is an issue-driven release with no RFC workstreams, so there are no subordinate RFC PR plans: **this doc owns the per-PR breakdown directly**, plus the release gates and cut lines.

## Scope decisions locked at plan opening (2026-08-03)

The amendment fixed the scope; these lock the open calls it deferred to plan opening (its next-steps item 2 names all three):

- **The three named issues *are* the release — scope creep is refused by construction.** The amendment's risk table says it outright: everything else open is low/medium severity and slotted v0.4.0+ or as the one fold-in below. Nothing boards mid-release.
- **ISSUE-0118 fix shape confirmed: thread the scopes the classification way.** Epoch and session ride `event.metadata` (they already reach the servicer), are lifted structurally in `DispatchContext.for_event`, and re-enter (or pass as resolved ids) around tool execution in the action executor's task — the exact pattern RFC 0037 PR 7 proved for acting classification across the same asyncio-task hop. Pre-picked at the 2026-07-31 maintainer call; confirmed here as the scope lock.
- **ISSUE-0121 is a release-prep deliverable, not an implementation PR.** Per the amendment's dependency chain, the whole `MT-MEMORY-CROSSROOM-001` arc runs live **after** the 0118 fix lands, so one run verifies both the threading fix (Leg 4, the exact shape that leaked on 2026-07-30) and legs 1b/2b. A red leg becomes in-release fix work, not a further deferral. The MT v1.1 protocol — leg-1b row keyed on the *sender id* (`alex`) typed `user`; wiring-vs-reasoning triage before filing — is documented in the MT and is the run contract.
- **ISSUE-0114 step-4 default reconfirmed: option (c).** The Python dispatcher cap stays a per-process global backstop; per-channel caps must be ≤ it (raising one channel above the fleet default means raising the backstop too). Recorded at the v0.3.12 plan opening, unchanged since; still the first decision the implementing PR must take, revisitable there with the issue's alternatives. The RFC 0050 PATCH-vs-config-as-code call is made in that PR too.
- **ISSUE-0116 fold-in: IN, as the release's only fold-in — cuttable.** The in/out call the amendment deferred to this plan opening is exercised: in. Direction **2** (render the `Known facts about <subject>:` header from a bounded template, keeping the full canonical form in the row) is the release-sized mitigation, per the default recorded on the issue 2026-08-03; direction 3 (subject namespaces with per-namespace validation) remains the principled home but belongs with the future predicate registry. Revisitable in the fold-in PR.

**Out of scope** — explicitly deferred so they don't pressure the cut:

- **Everything v0.3.14** — [ISSUE-0082](issues/ISSUE-0082-orchestrator-per-request-session-principal-emission.md) Part 2 (the principal axis), [ISSUE-0081](issues/ISSUE-0081-session-id-process-global-not-task-local.md) residuals, RFC 0040 Phase 1. Its plan opens after the v0.3.13 tag.
- **The v0.4.0 on-ramp** — RFC 0038 §C–§E, RFC 0049 Phases 2–4, RFC 0039 Phase 3, RFC 0041 (drafts un-gated but not boarding).
- **[ISSUE-0111](issues/ISSUE-0111-anonymous-wallet-rpcs-share-rate-limit-bucket.md) remainder** — rides as its own code PR per the v0.3.12 checklist §6 disposition; it may land during this window but is not a release scope item and does not gate the tag.
- **A deterministic identity-capture path** — the durable fix if legs 1b/2b prove capture unreliable across providers (the issue names it); a finding on the live run scopes it then, most likely v0.4.0-adjacent.

## Acceptance for v0.3.13

The release ships when **all** hold:

- **ISSUE-0118 is closed** — an agent-initiated tool recall carries the same per-request epoch/session scopes as the injection path: deterministic CI pins the executor-hop threading (the classification-precedent test shape), and the live MT fresh-epoch leg passes **with a tool round evidenced in the execution report** — a memory-tool invocation visible in provenance on that turn, so the exact leaked shape from 2026-07-30 now holds the wall. The tool round is model-elected (the issue's exposure note), so a green leg *without* one proves only the injection wall and is not the 0118 proof — re-probe until a round occurs. The v0.3.12 `--epoch`/`--session` caveat is retired in the v0.3.13 release notes.
- **ISSUE-0121 is closed** — the whole `MT-MEMORY-CROSSROOM-001` v1.1 arc runs live at release-prep with legs 1b/2b recorded explicitly in the execution report; Leg 1b's row is keyed on the sender id and typed `user`; Leg 2b's recognition lands. Red legs were fixed in-release, not re-deferred.
- **ISSUE-0114 is closed** — optional per-channel `max_cascade_depth` resolves like `ResolveInteractionBudgetTokens` (zero/absent → fleet value; never silently disabled) through a synchronized per-channel map (the `endVoteThresholds` precedent) read at the fanout-suppression and clamp sites; `closeOnCascadeBound` and the arming validation read the per-channel value; the RFC 0050 PATCH decision and the Go/Python alignment posture are recorded; the channels guide's tuning section and RFC 0052's structural-close wording gain the per-channel qualifier.
- **ISSUE-0116 is closed (or explicitly cut)** — the facts-section header renders through a bounded template; the topic amendment's write-boundary invariants are untouched.
- **Docs are edited, not just verified** — the guides and issue files the three fixes touch carry the new behaviour.
- **The full gate sweep is green live on host** — Go `-race`, the Python suites, Vitest, Rust, ruff/mypy (both legs)/clippy/go-vet, `make validate`, eval-replay, the license gate; no store migrations are expected this cycle, and the release checklist states that explicitly rather than silently omitting the migration section.

## Phase 1 — Implementation PRs

### PR 1 — `feature/v0313-issue0118-tool-recall-scopes`

The release's load-bearing fix, and the gate on the live arc. Stamp the per-request epoch and session on the event's `metadata` (the servicer already receives them), lift them structurally in `DispatchContext.for_event`, and carry them into tool execution across the executor's task hop — re-entering the ContextVar scopes around the action-processing task or passing resolved ids explicitly, whichever reads cleaner against `agents/persona_runtime/` as found. TDD: a red test pinning today's fallback (tool recall in a spawned task resolves the construction snapshot, not the request scope), then the threading; plus a drift guard tying this path to the classification threading so the two axes cannot diverge again. The issue's live-diagnosis recipes (provenance env, direct gRPC probes with a `persatrix-epoch` header) become the PR's manual verification notes.

### PR 2 — `feature/v0313-issue0114-cascade-depth`

The issue's five steps, in order: (1) optional `max_cascade_depth` on `ChannelConfig` + schema + `config_validate.go` (zero/absent → inherit; negatives rejected; never config-disabled); (2) a synchronized per-channel map on the router (the `endVoteThresholds`/`endVoteWindows` mutex pattern) read at the fanout-suppression and inbound-clamp sites; (3) the RFC 0050 decision — PATCHable via `ChannelConfigOverrides` (then mirror the `SetEndVoteParams` warn-don't-reject posture) or config-as-code only; (4) the alignment posture — default option (c), per-channel caps validated ≤ the Python global backstop; (5) the autonomous coupling — `closeOnCascadeBound` + arming validation read the per-channel value; guide + RFC 0052 wording gain the qualifier. CLI/web surfaces follow the knob-parity lockstep the config suites enforce.

### PR 3 — `feature/v0313-issue0116-subject-header` *(cuttable)*

Direction 2: `render_facts_section` heads each block with a bounded template of the subject (truncation to a conservative word/char bound in the *header only*), the full canonical form staying on the row and in recall matching. No storage or write-boundary change; the amendment's blast-radius invariants (length cap, control-character collapse, envelope-delimiter rejection) are asserted unchanged. If the template proves awkward against real subjects, cutting this PR drops cleanly — nothing else references it.

Findings from the Phase 3 live arc become additional in-release fix PRs as needed (the amendment's risk table pre-authorizes this for red legs).
