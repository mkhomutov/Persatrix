## Wire-compatibility state

**No protobuf changes** — `git diff v0.3.15..main -- proto/` is empty; PR 4 still confirms with `make proto && git diff --exit-code` under the CI-pinned protoc. **No REST shape change**: A1 re-sequenced two calls the turn already made (`/api/v1/channels/{id}` public, `/api/v1/agents` authenticated) and reads the same responses.

Three **new log surfaces** ride the release, each a release-note obligation:

1. The per-turn `audience egress` record on the persona container log (A2), which Leg 5 quotes.
2. `persatrix.memory.tier_admitted` now emitted for `tier=relationship` under `PERSATRIX_MEMORY_PROVENANCE=1` (B1) — ids and tokens, never the identity text.
3. `agent.deliberation.reason_note` at `DEBUG` on the suppression path (B2) — verbatim, **unredacted**, forwarded off-host with the agent log when the shipper is on; the orchestrator drops it on arrival.

Two deliberate **behaviour** changes: `memory.egress.audience` defaults to **`live`**, so a DM-taught `internal`-or-above fact is withheld in every default group room (the lock 1 trade); `memory_budget.tokens` exists as a key but, absent, resolves to the same 1 500. Under `shadow` every prompt is byte-identical to v0.3.15 across both auth modes; under `live` one request hash moved in `EVAL-MEMORY-005` and none elsewhere.
