# v0.3.1 Release Checklist

> **Status**: 🚧 Release prep — gates filled in by PR 3 (version bump + changelog) and PR 4 (final pre-tag verification) of the [v0.3.1 release-prep plan](v0.3.1-release-prep-plan.md). PR 4 flips this line to `✅ Released` and checks off every gate.

> v0.3.1 — "Memory Quality + Session Plumbing + Conversational Working Memory" — ships the combined deliverable of RFC 0026 (declarative facts tier — full, Phases 1–3), RFC 0031 Phase 1 (per-session namespacing — `sessions` table + `session_id` columns + `PERSATRIX_SESSION_ID` env-var plumbing), and RFC 0034 Phase 1 (persona conversational working memory — DM channels). The user-facing promise: *the persona remembers stated facts about you across interactions and follows the conversation it is currently having.*

### 3.1 Required Upgrade Notes in Changelog

This is the canonical source for Upgrade Notes text; the `[Unreleased]` section already contains the seeded rows and must be preserved when reshaped into `[0.3.1]`.

| Notable change | Detail |
|----------------|--------|
| **[Breaking]** chat-session wire-field rename | `ChatRequest.session_id` / `ChatResponse.session_id` JSON keys renamed to `chat_session_id` ([RFC 0031 OQ #8](rfcs/0031-per-session-namespacing-channels.md#open-questions)) to disambiguate from RFC 0031's operator-namespace `session_id`. Proto field numbers are preserved; JSON / proto-text consumers must migrate. The Rust CLI and the in-tree REST flow are already updated. |
| `channels.db` schema bump (v2→v3) | Adds the `sessions` table and `session_id` columns on channel/message rows. Forward-only migration; existing rows pick up the `legacy` session carve-out. |
| `memory.db` schema bump (v6→v8) | Two forward-only migrations: v7 adds `session_id` on `episodes` and `relationships`; v8 creates the RFC 0026 `facts` table (which carries `session_id` from creation). Existing rows pick up the `legacy` carve-out. |
| New `PERSATRIX_SESSION_ID` env var | Read at orchestrator + persona-runtime boot, stamped on every storage write. Unset ⇒ the `legacy` carve-out with an INFO boot line. Set the **same value in both processes** to keep a run coherent. Phase 1 is write-path only — recall does not yet filter by session. |
| New declarative facts tier (RFC 0026) | The persona extracts stated `(subject, predicate, object)` facts at interaction close and injects them into the persona prompt via a new `facts_context` section. Out-of-tree prompt evaluators will see a new tier in the system prompt. `memory.facts.enabled: false` disables fact recall/injection per-agent; the close-path extractor keeps writing facts regardless. |
| New `conversation_window` config block (RFC 0034) | A top-level `conversation_window` block lands in `config/agents.yaml` + `config/optimization.yaml`, validated by the new `schemas/optimization.schema.json`. The persona LLM `messages` array now carries the in-progress DM transcript instead of a single isolated message. Operator escape hatch: `conversation_window.enabled: false`. DM channels only in v0.3.1. |
| `make reset` deprecation breadcrumb | `make reset` remains the supported cross-run storage-isolation path. RFC 0031 Phase 3's `persatrix session …` CLI (`persatrix session new --activate`) will succeed it for run isolation in a later v0.3.x patch; `make reset` then becomes the deprecated nuclear option for clearing all volumes across all sessions. |

## 6. Known Gaps to Document in Release Notes

These items remain intentionally incomplete and should be described as deferred scope, not regressions. Seeded from [v0.3.1-plan §Out of scope](v0.3.1-plan.md) and the [release-prep plan PR 4 scope](v0.3.1-release-prep-plan.md#pr-4--final-pre-tag-verification--release-notes).

### v0.3.1-scope gaps

| Area | Description | Deferred to |
|------|-------------|-------------|
| Per-session recall isolation | RFC 0031 Phase 1 is **write-path only** — every storage row is tagged with a `session_id`, but recall still surfaces every session. Cross-run isolation continues to rely on `make reset`. | RFC 0031 Phase 2 (v0.3.x) |
| `persatrix session …` operator CLI | No `session new / use / list / archive / current` verbs yet; `PERSATRIX_SESSION_ID` is the only way to set a session. `make reset` remains the operator path for cross-run isolation. | RFC 0031 Phase 3 (v0.3.x) |
| Sessions operator guide | `docs/guides/sessions.md` is not written — it lands only after all three session mechanisms (env var, active-session file, `--session` flag) are wired, so the docs never describe a setting that does not work yet. | RFC 0031 Phase 4 (v0.3.x) |
| Conversational memory for group channels | RFC 0034 Phase 1 reconstructs the conversation transcript for **DM channels only**. Group channels keep today's single-message behaviour. | RFC 0034 Phase 2 (v0.3.x) |
| Conversation-window instrumentation / tuning | Per-window metrics and tuning of `max_turns` / `max_tokens` against observed workload are not in Phase 1. | RFC 0034 Phase 3 (v0.3.x) |
| `MT-CHAT-003` / `MT-CHAT-004` recipes are stale | Both assert the v0.3.0 per-turn memory-write model; RFC 0020 moved persona-memory writes to interaction-close. The user-facing capability (conversation continuity, trust evolution) works — the recipes need a rewrite for the interaction-close model. | MT recipe rewrite follow-up ([execution report F-2](manual-tests/v0.3.1-execution-report.md#follow-ups)) |
| `code-writer` `Max LLM call iterations exceeded` | `feature-builder` runs terminate on the `implement` step — same standing issue observed in the v0.3.0 report. Not a v0.3.1 regression. | Standing follow-up ([execution report F-3](manual-tests/v0.3.1-execution-report.md#follow-ups)) |
| `MT-COST-002` (budget-exceed workflow abort) | Carried forward from v0.2.x; no budget-enforcement changes in v0.3.1. Enforcement here is via agent-side LLM truncation, not the scheduler `ErrBudgetExceeded` sentinel. | Future RFC |

### Carried forward from v0.3.0

These v0.3.0-scope gaps remain open in v0.3.1. Full detail is in the [v0.3.0 release checklist §6](v0.3.0-release-checklist.md#6-known-gaps-to-document-in-release-notes); the still-relevant items:

| Area | Description | Deferred to |
|------|-------------|-------------|
| Channels REST surface is unauthenticated | `sender_id` is body-trusted; orchestrator emits a one-shot startup `WARN`. Run behind your own ingress/auth proxy on shared networks. | RFC 0009 Phase 4 (v0.4.0) |
| External bridges (Slack / Discord / email) | Channels are internal-only. The bridge surface is RFC 0011's deferred external scope. | v0.5.0 (RFC 0011 external scope) |
| Sandbox isolation + token auth (RFC 0009 Phases 3–4) | v0.3.0 ships audit + redactor + rate-limit + sanitization (Phases 1–2). Process/container isolation and an authenticated REST surface are deferred. | v0.4.0 (RFC 0009 Phases 3–4) |
| Persona temporal awareness — Phases 2–4 | now-anchor + relative-time rendering shipped in v0.3.0 (Phase 1). Structured commitment tracking, scheduled callbacks, and conversation-thread temporal grounding are deferred — surfaces in `MT-MEMORY-005` Leg 3. | v0.4.0 (RFC 0021 Phases 2–4) |
| Eviction-parameter calibration (RFC 0008) | RFC 0008 ships per-eviction instrumentation. Calibration of the eviction parameters is a forward-looking follow-up that fires when production-like workload telemetry exists. | v0.3.x follow-up gated on observed-workload data |
| Watermark-based catch-up + per-tick recovery | At-most-once delivery with on-startup last-50 replay only. Watermark `?since=<message_id>` and per-tick recovery are deferred. | v0.3.x (RFC 0011 OQ #8) |
| SSE streaming for `channel watch` | `channel watch` polls every 5 s. SSE is deferred. | v0.3.x (RFC 0011 OQ #6) |
| `persatrix logs` restart durability | Disk-store warm-load is unit-tested but production never calls `Buffer.Seal` — restart mid-run leaves no queryable history. `MT-LOGS-001` Step 4 footnote. | RFC 0018 PR 7 follow-up |

> **Closed in v0.3.1**: the v0.3.0 "persona named-entity recall after idle-gap closure" gap (`MT-MEMORY-005` Leg 1) is closed by the RFC 0026 declarative facts tier — `MT-MEMORY-005` is promoted from a baseline measurement to a pass/fail acceptance gate this release.
