### 1.1 Live-run guidance (for any re-run of the tenant arc)

- **Machine-pace the whole arc in one script** — governance windows race idle operators.
- **Restart agents *after* the orchestrator.** The registry is in-memory and agents never re-register ([ISSUE-0125](issues/ISSUE-0125-agents-never-reregister-after-orchestrator-restart.md)). On `persatrix chat` this fails loudly (`404 agent not found`); on the channel-publish seam it is **silent**.
- **Read `principal_id` off `memory.db` — provenance is not the evidence.** `PERSATRIX_MEMORY_PROVENANCE=1` is silent for the `relationship` tier ([ISSUE-0122](issues/ISSUE-0122-relationship-tier-emits-no-provenance.md)), which is exactly the cross-room identity read the absence bar cares about. The image ships no `sqlite3` CLI, so queries ride the agent runtime's `python3`, in-container with the stack **up** (`docker cp` against a stopped container fails on the read-only config mount).
- **Rotate `accounts.db` with its WAL sidecars** — `rm` of the database alone leaves `-wal`/`-shm` and the next bootstrap fails `disk I/O error (522)`.
- **Apply the fresh-room rule** (MT v1.1): Legs 4 and 5 must be re-asked in an **empty-transcript** room, because the RFC 0034 conversation window is rebuilt from channel history and is *not* principal-scoped. Leg 3 is exempt — Bob's DM is a distinct, empty channel by construction.
- [ ] **Capture live spend on a surface that actually works.** The PR 1 run recorded cost as **not measured** — a gap, not an estimate: `persatrix cost` answers `Command 'cost' not yet implemented`, no wallet/lease metric is registered in Prometheus, no lease settlement is logged, and `docker compose down -v` purged the ledger before a reading was taken. **Before tearing the stack down**, read the wallet ledger directly out of `orchestrator-data` (the RFC 0021 lease/settlement rows the v0.3.13 run counted as "25 settled wallet leases, $0.3038"), or run the arc with the volume preserved and read it after. A re-run that reports no figure has not met the v0.3.13 bar.

| **[No migrations — but NOT a transparent upgrade under `enabled`]** | **No store migrations this cycle.** Channel store stays v11, persona-memory at migration 17, both already at the v0.3.13 tag; nothing to run and no downgrade caution. **This is the one release where drop-in schema does not imply drop-in behaviour**: on a deployment already running `auth.mode: enabled`, every pre-existing row reads `'local'` and the strict-equality predicate has no carve-out, so each person's accumulated memory goes quiet the day emission lands. **A partition, not a deletion** — the corpus is still there under `'local'`. | **[Behaviour — the release]** memory is partitioned per authenticated person | Under `enabled`, the orchestrator emits a per-request principal derived from the RFC 0039 §F verified `participant_id` — the same value the chat surface stamps as `user_id`, so the tenant dimension and the conversation surface name one identity and an account rename never re-partitions anyone's memory. |
| **[Shared-room semantics]** | Two authenticated people in one channel get **per-speaker persona memory**: neither turn recalls the other's disclosures, including through the deliberately cross-room tiers (travelling facts, person identity). **Room continuity is unaffected** — transcript and verbatim history are *not* principal-scoped, so both people still see the same conversation. |

| **[Scope bound — the boundary is per-TURN]** | A write *derived* from a turn does not always inherit the principal. **R-1 (aggregate close)**: the RFC 0020 interaction scope is the ROOM, not the speaker, so in a group channel every speaker's turns accumulate into one record whose close-time summary and extracted facts land under whichever principal closed it — and facts are cross-room by default. **R-2 (agent cascades)**: a persona's reply re-enters as a fresh unauthenticated publish, so orchestrator-mediated cascade turns dispatch under `'local'` (the in-process `EventDispatcher` cascade *does* forward the axis; only the REST hop loses it). Both **v0.3.15**. Neither is covered by `MT-MEMORY-MULTIUSER-001`, which drives a single-persona DM. |
| **[Behaviour]** a restart no longer derives memory from replayed history | Catch-up replay carries no principal, so a replayed span now derives **nothing** rather than filing one person's content under the shared `'local'` tenant ([ISSUE-0130](issues/ISSUE-0130-catchup-replay-rederives-memory-under-default-principal.md)). **Cost, stated**: an interaction that closed entirely during downtime is no longer summarised at boot, and because auth mode is not exposed to agents the skip **also fires under `disabled`**, where `'local'` would have been correct. The persist-and-seed completion is **v0.3.15**. |
| **[Behaviour — agent traffic]** agent-origin turns stay `local` | Personas hold no accounts and drive the publish/convene REST seams anonymously (RFC 0039 §Non-Goals), so autonomous and agent-authored traffic writes `'local'` **by design**, even under `enabled`. |
| **[Behaviour — erasure]** `delete_by_subject` is principal-scoped | A caller now erases exactly the rows it could read, **counts included**. `session_id`/`epoch_id` stay unscoped by design (an erasure traversal must reach earlier rooms and runs). | **[`auth.mode: disabled` is byte-identical]** | No header is emitted, every request resolves `'local'`, deterministic tests pin the no-delta — **including on the erasure path**. Single-tenant and CLI deployments see no change. |
| **[Fixed in prep]** `persatrix chat` under `enabled` | v0.3.13's CLI could not authenticate on the chat verb at all (`401` with a valid token) — the one unauthenticated verb on the surface. Fixed before the tag; no operator action. |

## 6. Known Gaps to Document in Release Notes

Deferred scope, not regressions. Seeded from the [prep plan §Out of scope](v0.3.14-release-prep-plan.md) and the execution report.

| Area | Description | Deferred to |
|------|-------------|-------------|
| **[ISSUE-0082](issues/ISSUE-0082-orchestrator-per-request-session-principal-emission.md) R-1 — aggregate close** (accepted-and-stated at #820 review) | The RFC 0020 interaction scope is the **room**, not the speaker, so a group channel's close-time summary **and extracted facts** land under whichever principal closed it — and facts are cross-room by default, so a fact derived from B's disclosure can be written under A's principal. Consistently stamping either way would make the aggregate systematically single-tenant or put a person's own summaries out of their own reach, so the asymmetry is left **visible**. Real fix = per-speaker interaction scope (RFC 0020 §G). **Required in the release notes** so the isolation claim reads at the right scope. | v0.3.15 |
| **[ISSUE-0082](issues/ISSUE-0082-orchestrator-per-request-session-principal-emission.md) R-2 — agent cascades** | A persona's reply re-enters as a fresh unauthenticated publish, so orchestrator-mediated cascade turns dispatch under `'local'` even inside an authenticated person's interaction. Having the persona send the principal back is **not** the fix — trusting an agent-supplied claim would hand an unauthenticated caller a cross-tenant *read* primitive; the safe shape is server-side causal tracking. **Required in the release notes.** | v0.3.15 |
| **[ISSUE-0130](issues/ISSUE-0130-catchup-replay-rederives-memory-under-default-principal.md) shape (b) — persist and seed** | The leak-stopper shipped; the completion (persist `principal_id` on `messages`, channel store v11 → v12, stamp at publish, surface on history, seed in the replay builder) rides v0.3.15 **co-designed with R-2**, which needs a column on the same table — so `messages` migrates once. Until then a replayed span derives nothing at all, including under `disabled` where `'local'` would have been correct. | v0.3.15 |
| **Per-principal capacity sweeps** | Episode TTL, size-cap eviction, procedural decay and note prune stay **agent-global** by the residuals lock — capacity policy, not read-confidentiality; recall stays principal-filtered either way. | v0.4.0 |
| **[ISSUE-0127](issues/ISSUE-0127-cross-principal-erasure-verb.md)** (low) | The principal predicate has no `"*"` sentinel by design, so a subject cannot be erased across tenants — and an operator-initiated traversal has no principal of its own.
