### Schema / migration state

**None — the migration gate is empty this cycle** (unlike v0.3.12's two stores): the channel store is untouched at v11 and persona-memory at migration 17, both shipped by the v0.3.12 tag. All three fixes are runtime/config/render-side. The only schema-adjacent change is **config**, not storage: `channels[].max_cascade_depth` on the channel-config JSON schema plus the RFC 0050 `ChannelConfigOverrides` PATCH surface (the ninth flat knob, conditional adopt/first-edit capture so pre-v0.3.13 override rows keep their drift hashes). The checklist replaces v0.3.12's populated-store migration gates with the explicit no-migration statement.

### Wire-compatibility state

**No protobuf changes this cycle** (`make proto && git diff --exit-code` still re-verified at PR 4). The REST surface gains the additive per-channel knob on `PATCH …/config`; old clients are unaffected. The recall wire surfaces are unchanged — ISSUE-0118's fix threads scopes internally (`event.metadata` → `DispatchContext.for_event` → the executor task). One deliberate **behaviour** change rides it: an agent-initiated tool recall no longer returns rows outside the request epoch/session (the foreign-epoch wall) — that is the fix working, not skew, and the release notes say so when retiring the v0.3.12 caveat.
