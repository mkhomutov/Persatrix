**Scope**: the release-prep workstream for the v0.3.10 surface — **personas that think before they speak**. One landed feature RFC owns the headline, with two invisible fold-ins riding along:

1. **The headline — reasoning before posting** ([RFC 0051](rfcs/0051-reasoning-before-posting.md)). A private, per-turn deliberation a persona runs *before* it publishes into a channel. It generalizes the shipped [RFC 0030](rfcs/0030-multi-agent-conversation-governance.md) Tier-B salience bid from a scalar `speak/score` into a structured `{ should_post, plan }` verdict on the same leased `fast`-model seam (metered against the same `interaction_id`; idle stays free). `should_post=false` ends the turn in `DO_NOTHING` *before* the expensive compose — **semantic silence**, a net saving on pile-on, **on by default once a channel is governed** (`mode: bid`); `should_post=true` threads a private `CompositionPlan` (intent / key points / addressed-to / avoid-restating) into the existing Tier-C compose — the **considered, plan-threaded post**, a one-rung-up per-channel operator opt-in (`mode: plan`). On top of `plan`, an opt-in critic→revise **reflexion** loop (`reasoning.revise: 1|2`, default `0`) sharpens a draft before it ships, fail-soft. The whole trace — the plan, the silence `reason_note`, and any discarded reflexion draft + critic note — is **walled**: never a channel message, never the channel store, never a peer's RFC 0034 working memory ([RFC 0051 §E](rfcs/0051-reasoning-before-posting.md#e-privacy-boundary--the-trace-is-walled)); the operator-debug **agent log** is the only egress, and the audit trail is count-only. Tuned per channel by the `reasoning.{mode,model,depth,revise}` knob on the [RFC 0050](rfcs/0050-extensible-channel-configuration.md) config surface.
2. **(fold-in) RFC 0034 Phase 3 — working-memory instrumentation + cache LRU bound** ([RFC 0034](rfcs/0034-persona-conversational-working-memory.md), [Phase 3 PR plan](rfcs/0034-phase3-pr-plan.md)). The in-process cache fronting the per-turn transcript fetch is now a **bounded LRU** (it was unbounded), and the conversation window is instrumented (`conversation_window.{cache_access,cache_evictions,fetch_duration,fallback}`) so the `max_turns`/`max_tokens` defaults become data-tunable. No user-visible behaviour change; the defaults are unchanged and their retune is a deferred follow-up gated on collecting this telemetry. Synergistic with RFC 0051, which leans directly on the RFC 0034 transcript and the salience seam.
3. **(fold-in) RFC 0045 — open-core policy + the `MIT ← BUSL ← Private` dependency-direction CI gate** ([RFC 0045](rfcs/0045-open-core-extraction-policy.md)). A license-boundary policy + its CI gate (`make imports-check` — a Python `import-linter` contract — plus the Go `internal/archpolicy` check), the [reserved-seams note](open-core-reserved-seams.md), and the DCO scaffold. **Moves no code, stands up no private track, ships no user-facing story** — pure infrastructure that rode v0.3.10 without competing for the headline. The per-extraction RFCs (0046/0047) stay v0.4.0+.

It covers: **execution** of the already-authored headline manual test ([`MT-REASON-001`](manual-tests/MT-REASON-001.md) — semantic silence with a stated reason on a directed-elsewhere / already-answered turn, a plan-threaded considered post on a turn the persona can add to, the walled private trace, and the reflexion opt-in; run against a **real provider**) plus the carried-forward v0.3.9 surface; a documentation refresh (the persona-agents guide's *Reasoning before posting* section + the memory-architecture diagram's walled-trace note, both authored during implementation → verified here) and a new release checklist; version bump `0.3.9` → `0.3.10`; dating the existing `[0.3.10]` `Unreleased` changelog into a tagged `[0.3.10]`; and final pre-tag verification.

**The release gate is the go-live flip, not a migration.** Unlike v0.3.9 (two channel-store migrations as the pre-tag gate), **v0.3.10 advances no store** — the channel store stays at **v10** and the persona-memory store is untouched. The pre-tag gate is instead the trio the master plan locks in [§Acceptance](v0.3.10-plan.md#acceptance-for-v0310): the **go-live flip has run live** (a newly governed channel defaults `mode: bid`; a 3-persona `mode: plan` brainstorm shows a *countable* pile-on-suppression delta vs. the `off` baseline; the `deliberation.*` telemetry emits), the **privacy wall holds** (the no-leak test is green for the plan *and* a discarded reflexion draft), and the **kill switch is one flip** (`reasoning.mode: off` restores byte-for-byte the prior RFC 0030 score gate at runtime, no restart).

**Out of scope**: new feature work. RFC 0051 (Phases 1–3 + 5) and both fold-ins are fully landed with no outstanding PRs (see [§RFC PR roll-up](#rfc-pr-roll-up)). Deferred — documented as Known Gaps in the release notes, not release gates:

- **RFC 0051 Phase 4 — native extended-thinking `reasoning.depth: deep`** → **deferred** ([RFC 0051 Phase 4](rfcs/0051-reasoning-before-posting.md#phase-4-optional--follow-on-native-extended-thinking-depth)). It needs a provider-protocol change *and* is telemetry-gated on [OQ 1](rfcs/0051-reasoning-before-posting.md#open-questions) — only evaluable *after* the Phase 3 `deliberation.*` telemetry this release ships has run. `validate` rejects `depth: deep` as an unbacked enum value until it is built (a release gate, [§Manual test state](#manual-test-state)).
- **The OQ 6(a) operator reasoning-reveal web panel** (RFC 0051 PR 7) → **cut from v0.3.10**. The silence-with-reason leg reads the verbatim `reason_note` from the operator-debug **agent log** per [RFC §E](rfcs/0051-reasoning-before-posting.md#e-privacy-boundary--the-trace-is-walled), which is what `MT-REASON-001` exercises — so PR 7 was the plan's explicitly-cuttable surface and was dropped without touching the headline. A future operator reveal is a separate egress, never a relaxation of the wall.
- **An end-user "watch them think" surface** ([OQ 6(b)](rfcs/0051-reasoning-before-posting.md#open-questions)) → **separate explicit egress, never this release.** Any future end-user reasoning reveal is its own egress, never a relaxation of the §E wall.
- **A durable reasoning store / persistent trace for offline eval** → **possible follow-on.** The trace is ephemeral + audit-only; a retention-bounded eval sink is a separate concern, not v0.3.10.
- **Group deliberation toward a decision** → [RFC 0028](rfcs/0028-agent-decision-policy-engine.md) (v0.4.x). RFC 0051 is per-persona, per-turn, private; reasoning *across* personas toward a justified recommendation is a different RFC.
- **The RFC 0034 `max_turns` / `max_tokens` data-driven retune** → **post-soak follow-up**, gated on collecting the Phase 3 `conversation_window.*` telemetry this release ships. The defaults are unchanged ([RFC 0034 Phase 3](rfcs/0034-phase3-pr-plan.md)).
- **RFC 0045 per-extraction RFCs (0046/0047) + any code movement** → **v0.4.0+.** v0.3.10 lands only the policy + the dependency-direction CI gate.
- **RFC 0039 accounts / auth ("safe remote console")** → **parallel track, v0.3.11 candidate** ([v0.3.x-sequencing §Amendment 2026-06-23](v0.3.x-sequencing.md#amendment-2026-06-23--add-v0310-reasoning-before-posting-as-the-next-realism-rung)). A different user story (deployment safety, not conversation quality); bundling it would obscure what the user gained.
- **RFC 0030 Layer 5 — moderator / bid-and-select** → **v0.4.0** (carried forward from v0.3.8/v0.3.9; not a v0.3.10 dependency).

**Documentation timing policy** (carry-forward from [v0.3.9 prep](v0.3.9-release-prep-plan.md)): public docs updated *before* tag; post-tag-only artifacts (tag link, release URLs, "Released" stamps) → [v0.3.10-plan Phase 4](v0.3.10-plan.md#phase-4--tag-and-post-release-follow-up).
