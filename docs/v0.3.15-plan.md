# v0.3.15 Plan — Who Said What (the derived, the relayed, and the replayed write)

**Status**: 📋 Phase 0 — this planning PR
**Target version**: v0.3.15 (the *attribution* release — one of two patches before the v0.4.0 Agent Organizations train)
**Created**: 2026-08-23
**Branch prefix**: `feature/v0315-`
**Target**: `main`
**Merge strategy**: Squash merge per [BRANCHING.md](BRANCHING.md)
**Codename**: *Who said what*

**Goal**: v0.3.14 made the caller's verified principal a per-request axis, and that boundary holds for **every turn's own write**. It does not hold for the three writes that are not turns:

* the **derived** write — the RFC 0020 interaction scope is the ROOM, so a group channel accumulates every speaker into one record, summarised and fact-extracted under whichever principal closed it ([ISSUE-0082](issues/ISSUE-0082-orchestrator-per-request-session-principal-emission.md) **R-1** / [ISSUE-0123](issues/ISSUE-0123-per-speaker-interaction-scope.md));
* the **relayed** write — a persona's reply re-enters as a fresh unauthenticated publish, so every fanout below it loses the tenant (**R-2** / [ISSUE-0124](issues/ISSUE-0124-orchestrator-hop-drops-tenant-on-agent-cascade.md));
* the **replayed** write — catch-up re-reads stored history, and `messages` has no principal column, so nothing derived at boot can be attributed ([ISSUE-0130](issues/ISSUE-0130-catchup-replay-rederives-memory-under-default-principal.md) shape **(b)**).

Underneath all three sits the axis none supplies. The principal is a *tenant* identifier and only authenticated humans have one, so a room of personas collapses into the shared `local` bucket: derived memory records what was said and where, never **who said it** ([ISSUE-0131](issues/ISSUE-0131-derived-memory-has-no-speaker-attribution.md)). The Phase 0 gate's decisive leak was exactly that — one persona storing another's assertion as the *subject's* own attribute.

This release closes all four, plus the operational failure that voids the live verification each is gated on ([ISSUE-0125](issues/ISSUE-0125-agents-never-reregister-after-orchestrator-restart.md)).

Scope was ratified by the [sequencing Amendment 2026-08-19](v0.3.x-sequencing.md#amendment-2026-08-19--v0315--v0316-attribution-and-audience-before-the-v040-train), whose next-steps item 3 this plan executes. Unlike v0.3.13 and v0.3.14, most of the per-PR breakdown **already exists** — [#822](https://github.com/mkhomutov/Persatrix/pull/822) landed the [residuals PR plan](issues/ISSUE-0082-residuals-pr-plan.md) and the [Phase 0 gate record](issues/ISSUE-0082-residuals-phase0-gate.md) for R-1 / R-2 / ISSUE-0131 — so this doc is a **thin orchestration overlay**. It owns what that plan does not: ISSUE-0130(b) (which has "no PR slot in it and is owned by the v0.3.15 milestone plan"), ISSUE-0125 (absent from it entirely), the sequencing between workstreams, and the single live arc.

## Scope decisions locked at plan opening (2026-08-23)

Three the amendment named; two the surface audit forced.

- **Record shape: `(principal, speaker, scope)` — resolved, and not re-opened here.** The [Phase 0 gate](issues/ISSUE-0082-residuals-phase0-gate.md) decided both axes on one live run: the principal dimension 2026-08-07 (Option A), the speaker dimension 2026-08-21 (key-side). This plan **records** that answer rather than re-deriving it; residuals PRs 3–4 are already written for it. Two consequences ride along: the close reserve becomes `1 + (personas × principals × speakers)`, sized in that plan's PR 4 with the half-cap clamp filed as its own calibration issue, and close-derived memory of a group discussion fragments per speaker per tenant — a release-note obligation, fixed now.
- **ISSUE-0130(b) runs in parallel with the residuals, not behind R-2 — two stores, two migrations.** `principal_id` on `messages` is `internal/channels/sqlite_schema.go` **v11 → v12** (Go); the speaker axis is persona-memory migration **17 → 18** (Python). The databases are disjoint — `agents/` issues no query against `messages` — and R-2's shape is deliberately in-memory, so it adds no column to share. The two meet at the wire (after R-2 re-stamps, a relayed publish reaches the stamp site with a causal principal, so the row persists it instead of `local`) — a **sequencing preference, not a schema dependency**, per the 2026-08-23 correction on ISSUE-0130.
- **ISSUE-0125 rides — in shape (4), and it lands *before* the live arc rather than beside it.** The amendment's cut clause stands (it cuts if the shape grows into registry persistence), but the ordering is not optional: every restart-bearing leg this release needs — the ISSUE-0130(b) replay verification most of all — is a leg that today leaves the fleet permanently mute. Shape: **agent-side re-registration driven by the existing orchestrator channel's gRPC connectivity state** (`AgentServer._orchestrator_channel`, the long-lived RFC 0023 connection carrying the log stream and wallet leases), so a `READY → TRANSIENT_FAILURE → READY` cycle is the trigger. Event-driven, no timer — which is why it and not a heartbeat: a fleet-wide periodic re-register is the polling shape [RFC 0024](rfcs/0024-event-driven-scheduling.md) removed, and the amendment's own bound ("re-registration on dispatch failure plus a heartbeat") has no orchestrator-side implementation — that side holds no address to dial. *A deliberate deviation from the amendment's wording, taken on ISSUE-0125's own more specific analysis (its shapes 1 and 4), recorded rather than amended; reversible at review.* Its shared precondition rides with it: `InMemoryRegistry.Register` becomes an **upsert**, since it returns `ErrAgentAlreadyRegistered` today and a re-register against a populated registry is a `409` no-op that never corrects a stale address.
- **Re-registration must NOT re-run catch-up replay.** *Forced by the plan-opening audit.* `_self_register()` and `replay_for_persona_agents()` sit adjacent in `AgentServer.start()` ([`agents/server.py`](../agents/server.py)), so the cheap implementation of the lock above — re-run the startup tail on reconnect — would re-ingest the catch-up window on every orchestrator blip. Catch-up has no watermark (RFC 0011 OQ #8), so that is unbounded re-derivation — the path ISSUE-0130 shape (a) just bounded, re-opened through a different door. The reconnect path re-registers **only**; a test pins that a connectivity cycle triggers no replay fetch.
- **One live arc, one MT.** [MT-MEMORY-GROUP-TENANT-001](manual-tests/MT-MEMORY-GROUP-TENANT-001.md) (eight legs, authored in #822) is the release gate, **extended with a restart leg** for ISSUE-0130(b) that reads the `local` partition after an orchestrator restart — the check no existing leg performs, and the one ISSUE-0130 names as missing. No second MT: the restart it needs is a precondition the same arc already sets up, and ISSUE-0125 is what makes it survivable. [MT-MEMORY-MULTIUSER-001](manual-tests/MT-MEMORY-MULTIUSER-001.md)'s Edge Case 2 wording widens back to the now-true claim at closeout, and its PR #823 registry warning is **deleted** rather than propagated to the other eight ([ISSUE-0126](issues/ISSUE-0126-mt-orchestrator-restart-registry-note-missing.md) option 1) — those eight restart steps confirmed safe as written.

**Out of scope** — deferred explicitly so they do not pressure the cut:

- **Registry persistence, and registration as a property of a live stream** — ISSUE-0125's shape (5), the destination. It needs an [RFC 0040](rfcs/0040-agent-orchestrator-transport-unification.md) §C amendment, since Phase 2 sketches a *unary* `RegisterAgent` that does not deliver it: v0.4.0 design work. ISSUE-0125 closes on shape (4) or it cuts; it does not grow.
- **The v0.3.16 bundle** — [ISSUE-0132](issues/ISSUE-0132-memory-egress-gate-blind-to-room-audience.md) (audience as a gate input, which needs this release's attribution to reason against), [ISSUE-0122](issues/ISSUE-0122-relationship-tier-emits-no-provenance.md) / [ISSUE-0108](issues/ISSUE-0108-reasoning-reason-note-no-operator-egress.md), [RFC 0044](rfcs/0044-eval-set-golden-traces.md) Phase 2.
- **Per-principal capacity sweeps and quota policy** (the v0.3.14 Known Gap stands) and **the v0.4.0 on-ramp** — RFC 0038 §C–§E, RFC 0049 Phases 2–4, RFC 0039 Phase 3, RFC 0041 Phase 1 (the 2026-08-02 ruling against pulling that forward stands).
- **Model-elected attribution.** The speaker axis is a projection of the record key; asking the model which speaker a fact came from is forbidden by the Phase 0 rule and stays so.

## Acceptance for v0.3.15

The release ships when **all** hold:

- **ISSUE-0123 (R-1) and ISSUE-0124 (R-2) close together** — a relayed turn carries the causal principal *and* lands in that principal's own per-speaker record. Neither closes alone: the release-note claim is unsafe with either half missing.
- **ISSUE-0131 is closed** — `episodes` and `facts` carry the speaker, frozen at interaction open from the triggering event's `sender_id`, so recall distinguishes testimony from hearsay without asking the model. The Phase 0b regression is the gate: one `local` principal, three agent speakers, one room scope → **three** records.
- **ISSUE-0130 shape (b) is delivered** — `messages` persists a server-stamped `principal_id` (v11 → v12), `_build_replay_event` seeds it, the shape-(a) skip narrows to genuinely unattributable spans, and RFC 0037's replayed-rotation stamping returns.
- **ISSUE-0125 is closed and ISSUE-0126 retired** — a restart self-heals without touching an agent process; `Register` is an upsert; a reconnect does not re-run catch-up; zero registered agents while channels have members is visible without reading dispatch WARNs; the one MT warning is deleted, not multiplied. Or it is **cut**, wholly, citing the amendment's clause.
- **No migration lands after its consumer** — v11 → v12 and 17 → 18 each ship in their own PR, ahead of the code reading them, and neither touches the other store.
- **`auth.mode: disabled` stays byte-identical on the principal axis** — and demonstrably **not** on the speaker axis: MT Leg 8's all-agent room is where the speaker split does its work.
- **The live proof exists** — the whole extended arc on a live provider, with Leg 2's per-dispatch `principal.id` table (storage cannot observe R-2) and Leg 4's `(principal_id, speaker_id, summary)` triples pasted verbatim.
- **The coherence trade is stated, not discovered** — release notes carry the per-speaker-per-tenant fragmentation of close-derived group memory, the `agent.interactions.closed.by_<reason>` metric-shape change, and the reserve re-size.
- **The full gate sweep is green live on host** — Go `-race`, `cargo test`, the Python suites (including the separate `mypy tests/` leg), Vitest, the linters, `make validate`, eval-replay, licenses. **Two** store migrations are expected; the checklist names both.

## Phase 1 — Implementation PRs

### Workstream A — the derived and relayed writes

Delegated whole to the [residuals PR plan](issues/ISSUE-0082-residuals-pr-plan.md) (PRs 1–5), not restated here. Two obligations it inherits from this milestone: its PR 4's reserve calibration files as its own issue **covering the half-cap clamp**, not only the multiplier; and its PR 5's live arc is the *extended* MT, so it does not run before PR B2 lands the restart leg.

### Workstream B — the replayed write

#### PR B1 — `feature/v0315-issue0130-messages-principal`

The column and its producer, landing with **no persona-side consumer** — the dormant-rail-then-producer split v0.3.14 PR 1 / PR 2 established. Channel store `v11 → v12` adds `principal_id` to `messages` ([`internal/channels/sqlite_schema.go`](../internal/channels/sqlite_schema.go)), stamped **server-side** at publish from the authenticated request context — never from the request body, since an agent-supplied principal is the cross-tenant read primitive ISSUE-0130 rules out — and surfaced on `channelMessageResponse`. Backfill is `'local'`, consistent with v11. Tests: migration round-trip; an authenticated publish persists the emitted principal, an unauthenticated one `'local'`; the history DTO carries the field.

#### PR B2 — `feature/v0315-issue0130-replay-seed`

The consumer. `_build_replay_event` ([`agents/channel_catchup.py`](../agents/channel_catchup.py)) seeds the principal from the history payload; the shape-(a) derivation skip narrows from *every* replayed span to genuinely unattributable ones, restoring single-tenant derivation and RFC 0037's replayed-rotation classification stamping (withdrawn in #834, whose tests flip back). `REASON_CATCHUP_COMPLETE` and the replay-opened-scope boundary are untouched — they were never about attribution. Authors the MT restart leg. Tests: an attributed replayed span derives under its own principal; an unattributed one still skips.

### Workstream C — the fleet

#### PR C1 — `feature/v0315-issue0125-reregister` *(cuttable)*

`InMemoryRegistry.Register` becomes an upsert ([`internal/registry/registry.go`](../internal/registry/registry.go)) — the precondition every shape shares, and on its own the fix for a stale advertised address. Agent-side, a watcher on `AgentServer._orchestrator_channel`'s gRPC connectivity state re-runs `_self_register()` on a `READY → TRANSIENT_FAILURE → READY` cycle, **and nothing else** — the no-replay lock, pinned by a test. Plus the observability the issue asks for on its own merit: zero registered agents while channels have members, logged once at ERROR or exposed as a metric. Finally ISSUE-0126 option 1 — delete the single registry warning #823 added to MT-MEMORY-MULTIUSER-001, the other eight restart steps confirmed safe as written. Tests: re-register against a populated registry updates the address rather than `409`-ing; a connectivity cycle re-registers and issues no history fetch; a restart in an integration harness leaves the fleet dispatchable.

## Risk and mitigations

| Risk | Mitigation |
|------|------------|
| The `1 + (personas × principals × speakers)` reserve is under-sized and the failure is **silent** — a denied lease commits `SUMMARY_UNAVAILABLE_TEXT` and the janitor never retries it. | The largest cost in the release, owned as a deliverable: residuals PR 4 sizes it with its own test, and the calibration files as an issue covering the half-cap clamp in [`internal/wallet/synthesis_reserve.go`](../internal/wallet/synthesis_reserve.go) — already a KNOWN GAP that a third dimension makes bite in the normal case. |
| ISSUE-0125 grows from re-registration into registry persistence or an RFC 0040 §C amendment. | Cuttable whole, and bounded by shape at the plan opening: upsert + connectivity-driven re-register + one observability signal. Shape (5) is the named destination and does not board. |
| The reconnect path re-runs catch-up, re-opening the unbounded re-derivation ISSUE-0130(a) just closed. | Locked as a scope decision, not left to implementation: the reconnect re-registers only, pinned by a test. Found at the plan-opening audit because the two calls are adjacent in `AgentServer.start()`. |
| The release ships half the boundary and the note over-claims. | Acceptance requires R-1 and R-2 together; the three writes are named individually in the notes, and any one that slips is stated as an open residual, not absorbed into a general claim. |
| Group-memory fragmentation reads as a regression: the persona's recollection of a discussion is now per speaker per tenant. | This *is* the promise applied inside a room — the trade v0.3.14 made per person. Room continuity is untouched; stated in the notes and observed by an MT leg, not discovered by a user. |
| The live arc cannot run because the fleet goes mute at the first restart — the failure that already voided one MT arc on a paid provider. | C1 lands first, ahead of the workstreams it serves. If it cuts, the arc keeps the manual-restart step and ISSUE-0126's warning stays. |
