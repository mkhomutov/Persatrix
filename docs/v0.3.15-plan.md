# v0.3.15 Plan — Who Said What (the derived, the relayed, and the replayed write)

**Status**: 🔄 Phase 1 — implementation (C1 + residuals PRs 1–4 merged; workstream B open at [B1](https://github.com/mkhomutov/Persatrix/pull/850))
**Target version**: v0.3.15 (the *attribution* release — one of two patches before the v0.4.0 Agent Organizations train)
**Created**: 2026-08-23
**Branch prefix**: `feature/v0315-`
**Target**: `main`
**Merge strategy**: Squash merge per [BRANCHING.md](BRANCHING.md)
**Codename**: *Who said what*

**Goal**: v0.3.14 made the caller's verified principal a per-request axis, and that boundary holds for **every turn's own write**. It does not hold for the three writes that are not turns:

* the **derived** write — the RFC 0020 interaction scope is the ROOM, so a group channel accumulates every speaker into one record, summarised and fact-extracted under whichever principal closed it ([ISSUE-0082](issues/ISSUE-0082-orchestrator-per-request-session-principal-emission.md) **R-1** / [ISSUE-0123](issues/ISSUE-0123-per-speaker-interaction-scope.md));
* the **relayed** write — a persona's reply re-enters as a fresh unauthenticated publish, so the cascade below it loses the tenant (**R-2** / [ISSUE-0124](issues/ISSUE-0124-orchestrator-hop-drops-tenant-on-agent-cascade.md));
* the **replayed** write — `messages` has no principal column, so nothing catch-up derives at boot can be attributed ([ISSUE-0130](issues/ISSUE-0130-catchup-replay-rederives-memory-under-default-principal.md) shape **(b)**).

Underneath all three sits the axis none supplies: the principal is a *tenant* identifier and only authenticated humans have one, so a room of personas collapses into the shared `local` bucket ([ISSUE-0131](issues/ISSUE-0131-derived-memory-has-no-speaker-attribution.md)). This release closes all four, plus the operational failure that voids the live verification ([ISSUE-0125](issues/ISSUE-0125-agents-never-reregister-after-orchestrator-restart.md)).

Scope was ratified by the [Amendment 2026-08-19](v0.3.x-sequencing.md#amendment-2026-08-19--v0315--v0316-attribution-and-audience-before-the-v040-train), whose next-steps item 3 this executes. The per-PR breakdown mostly **already exists** — [#822](https://github.com/mkhomutov/Persatrix/pull/822) landed the [residuals PR plan](issues/ISSUE-0082-residuals-pr-plan.md) and the [Phase 0 gate](issues/ISSUE-0082-residuals-phase0-gate.md) — so this is a **thin orchestration overlay**, owning what that plan does not: ISSUE-0130(b) ("no PR slot in it and is owned by the v0.3.15 milestone plan"), ISSUE-0125, the sequencing, and the live arc. Each lock states a decision and its binding consequence; evidence sits in the issue it belongs to.

## Scope decisions locked at plan opening (2026-08-23)

Three the amendment named; two the surface audit forced.

- **Record shape: `(principal, speaker, scope)` — resolved, not re-opened here.** The [Phase 0 gate](issues/ISSUE-0082-residuals-phase0-gate.md) decided both axes on one live run (principal 2026-08-07, speaker 2026-08-21). Residuals PRs 3–4 own both consequences — the reserve re-size, and per-speaker-per-tenant fragmentation of close-derived group memory, a release-note obligation fixed now. **The milestone adds two**, both in the [reserve-sizing record](issues/ISSUE-0082-residuals-reserve-sizing.md): ship the clamp **signal** with the re-size rather than deferring it alongside the constant, and move the *threshold* basis with the reserve basis — [`bounded_close.go`](../internal/channels/bounded_close.go)'s one-directional requirement inverts once a per-speaker reserve exceeds the member count it is compared against, and that half is Go, not residuals PR 4.
- **ISSUE-0130(b) is not gated on R-2 — two stores, two migrations.** `principal_id` on `messages` is `sqlite_schema.go` **v11 → v12** (Go); the speaker axis is persona-memory **17 → 18** (Python). The databases are disjoint (`agents/` issues no query against `messages`) and R-2's shape is in-memory, adding no column to share. They meet at the wire, not in a schema — per the 2026-08-23 correction on ISSUE-0130.
- **ISSUE-0125 rides — in shape (4), before the live restart legs.** The amendment's cut clause stands (it cuts if the shape grows into registry persistence). Shape: **agent-side re-registration driven by the orchestrator channel's gRPC connectivity state**, triggered by **any departure from `READY` and return** — *not* the literal `TRANSIENT_FAILURE` cycle, which an idle channel never reaches, so a watcher written to it tests green and never fires. Event-driven, not a heartbeat: periodic re-register is the polling shape [RFC 0024](rfcs/0024-event-driven-scheduling.md) removed. *A deliberate deviation from the amendment's wording, on ISSUE-0125's own analysis; reversible at review.* Precondition: `Register` becomes an **upsert** — which does not itself fix the restart case. Citations on [ISSUE-0125](issues/ISSUE-0125-agents-never-reregister-after-orchestrator-restart.md).
- **Replay must be idempotent — the reconnect path is only one door.** *Forced by the plan-opening audit.* Catch-up has no watermark (RFC 0011 OQ #8) **and no dedup**, so K restarts inside the window produce `K × N` turns. Shape (a) bounded that by skipping derivation for *every* replayed span — and narrowing that skip is precisely B2's job, handing the growth back under the *correct* principal. **So B2 carries a dedup or watermark check, not just the narrowed skip**; that is an acceptance condition. The reconnect corollary rides with it (C1 must not re-run the startup tail; a test pins it) — but it guards a door C1 creates, while the restart door is open today. Reasoning on [ISSUE-0130](issues/ISSUE-0130-catchup-replay-rederives-memory-under-default-principal.md).
- **One live arc, one MT.** [MT-MEMORY-GROUP-TENANT-001](manual-tests/MT-MEMORY-GROUP-TENANT-001.md) (**nine** legs, 0–8 — its own sign-off miscounts them as eight) is the release gate, **extended with a restart leg** that snapshots episode and fact counts in **both** partitions: after B2 duplicates land under the *attributed* principal, so the `local`-only read ISSUE-0130 originally framed would pass while the regression is worst. Two further MT edits need owners, not closeout notes — Leg 4 widens to `(principal_id, speaker_id, summary)` (it collects pairs today, so ISSUE-0131 would have no live evidence), and [MT-MEMORY-MULTIUSER-001](manual-tests/MT-MEMORY-MULTIUSER-001.md)'s Edge Case 2 **widens** back to the now-true claim, the group MT's contrary "narrow" note being stale since v0.3.14 prep. Per [ISSUE-0126](issues/ISSUE-0126-mt-orchestrator-restart-registry-note-missing.md) option 1 **as corrected 2026-08-23**, **both** warnings are deleted, the eight unguarded restart steps confirmed safe.

**Out of scope** — deferred explicitly so they do not pressure the cut:

- **Registry persistence / registration as a property of a live stream** — ISSUE-0125's shape (5). It needs an [RFC 0040](rfcs/0040-agent-orchestrator-transport-unification.md) §C amendment, since Phase 2 sketches a *unary* `RegisterAgent`: v0.4.0 work. ISSUE-0125 closes on shape (4) or cuts; it does not grow — **but not silently.** RFC 0040 routes that ask through ISSUE-0125 in both places it appears (§C and OQ 6, which says resolve it before the proto lands, the shape being non-additive), so closing this orphans both pointers. **Phase 4 re-files it as its own issue and re-points RFC 0040.**
- **The v0.3.16 bundle** — [ISSUE-0132](issues/ISSUE-0132-memory-egress-gate-blind-to-room-audience.md) (audience as a gate input, which needs this release's attribution), [ISSUE-0122](issues/ISSUE-0122-relationship-tier-emits-no-provenance.md) / [ISSUE-0108](issues/ISSUE-0108-reasoning-reason-note-no-operator-egress.md), [RFC 0044](rfcs/0044-eval-set-golden-traces.md) Phase 2.
- **Per-principal capacity sweeps and quota policy** (the v0.3.14 Known Gap stands) and **the v0.4.0 on-ramp** — RFC 0038 §C–§E, RFC 0049 Phases 2–4, RFC 0039 Phase 3, RFC 0041 Phase 1.
- **Model-elected attribution.** The speaker axis is a projection of the record key; asking the model which speaker a fact came from stays forbidden.

## Acceptance for v0.3.15

The release ships when **all** hold:

- **ISSUE-0123 (R-1) and ISSUE-0124 (R-2) close together** — a relayed turn carries the causal principal *and* lands in that principal's own per-speaker record. The release-note claim is unsafe with either half missing.
- **ISSUE-0131 is closed** — `episodes` and `facts` carry the speaker, frozen at interaction open from the triggering event's `sender_id`. The Phase 0b regression is the gate: one `local` principal, three agent speakers, one room scope → **three** records.
- **ISSUE-0130 shape (b) is delivered** — `messages` persists a server-stamped `principal_id` (v11 → v12), `_build_replay_event` seeds it, the shape-(a) skip narrows to genuinely unattributable spans, and RFC 0037's replayed-rotation stamping returns. **Replay is idempotent across restarts** — row counts in the *attributed* partition are flat across the restart leg, not just in `local`.
- **ISSUE-0125 is closed and ISSUE-0126 retired** — a restart self-heals without touching an agent process, demonstrated on a transition that is *not* `TRANSIENT_FAILURE`; `Register` is an upsert; a reconnect does not re-run catch-up; zero registered agents while channels have members is visible without reading dispatch WARNs; **both** MT warnings are deleted. Or it is **cut**, citing the amendment's clause.
- **No migration lands after its consumer** — v11 → v12 and 17 → 18 each ship in their own PR, ahead of the code reading them, neither touching the other store.
- **`auth.mode: disabled` stays byte-identical on the principal axis** — and demonstrably **not** on the speaker axis: MT Leg 8's all-agent room is where the speaker split does its work.
- **The live proof exists** — the extended arc on a live provider, with Leg 2's per-dispatch `principal.id` table (storage cannot observe R-2) and Leg 4's `(principal_id, speaker_id, summary)` triples verbatim. The MT collects pairs today; B2 widens it, before Phase 3 rather than after the paid arc.
- **The coherence trade is stated, not discovered** — release notes carry the per-speaker-per-tenant fragmentation of close-derived group memory, the `agent.interactions.closed.by_<reason>` metric-shape change, and the reserve re-size.
- **The full gate sweep is green live on host** — Go `-race`, `cargo test`, the Python suites (including the separate `mypy tests/` leg), Vitest, linters, `make validate`, eval-replay, licenses. **Two** store migrations are expected; the checklist names both.

## Phase 1 — Implementation PRs

### Workstream A — the derived and relayed writes

### Workstream B — the replayed write

#### PR B1 — `feature/v0315-issue0130-messages-principal`

The column and its producer, landing with **no persona-side consumer** — the dormant-rail split v0.3.14 PR 1 / PR 2 established. Channel store `v11 → v12` adds `principal_id` to `messages` ([`sqlite_schema.go`](../internal/channels/sqlite_schema.go)), stamped **server-side** at publish from the authenticated request context — never from the request body, an agent-supplied principal being the cross-tenant read primitive ISSUE-0130 rules out — and surfaced on `channelMessageResponse`. Backfill is `'local'`, matching the *persona-memory* store's v11; the channel store's own v11 backfilled `'internal'` onto `channels` and is not the precedent. Go has no `local` constant to lock-step against and an unauthenticated request yields `""`, so the stamp site coerces explicitly. Tests: migration round-trip; an authenticated publish persists the principal, an unauthenticated one `'local'`; the DTO carries the field.

#### PR B2 — `feature/v0315-issue0130-replay-seed`

The consumer. `_build_replay_event` ([`agents/channel_catchup.py`](../agents/channel_catchup.py)) seeds the principal from the history payload; the shape-(a) skip narrows from *every* replayed span to genuinely unattributable ones, restoring single-tenant derivation and RFC 0037's replayed-rotation stamping (withdrawn in #834, whose tests flip back). `REASON_CATCHUP_COMPLETE` and the replay-opened-scope boundary are untouched. **Narrowing is only safe with the idempotence half**, so this PR lands the dedup or watermark check lock 4 names. MT work: the restart leg reading both partitions, Leg 4 widened to `(principal_id, speaker_id, summary)`, the sign-off leg count corrected. Tests: an attributed span derives under its own principal; an unattributed one skips; **a span replayed twice derives once**.

### Workstream C — the fleet

#### PR C1 — `feature/v0315-issue0125-reregister` *(cuttable)*

`InMemoryRegistry.Register` becomes an upsert ([`internal/registry/registry.go`](../internal/registry/registry.go)) — the precondition every shape shares, and on its own the fix for a stale advertised address. Agent-side, a watcher on `AgentServer._orchestrator_channel`'s connectivity state re-runs `_self_register()` on **any departure from `READY` and return** (`IDLE` and `CONNECTING` included) **and nothing else** — the no-replay corollary. The watched channel and the registration endpoint (`orchestrator_url`, aiohttp) are different addresses. Plus the observability the issue asks for on its own merit: zero registered agents while channels have members, at ERROR or as a metric. Finally ISSUE-0126 option 1 as corrected — delete **both** warnings. Tests: re-register against a populated registry updates the address rather than `409`-ing; **an `IDLE` cycle re-registers** and issues no history fetch; a restart leaves the fleet dispatchable. Upsert and watcher are pinned separately — the upsert passes even when the watcher never fires.

## Risk and mitigations

| Risk | Mitigation |
|------|------------|
| The reserve is under-sized and the failure is **silent** — a denied lease commits `SUMMARY_UNAVAILABLE_TEXT` and the janitor never retries it. | Calibration is rightly deferred (a constant guessed off no telemetry is worse than none) — **but the signal is not**: the clamp site returns silently today, so a WARN or counter there and at the `SUMMARY_UNAVAILABLE_TEXT` commit ships with the re-size. [Reserve-sizing record](issues/ISSUE-0082-residuals-reserve-sizing.md). |
| B2 narrows the derivation skip without the idempotence half, and replay growth returns under the attributed principal. | Scope lock 4, and an acceptance condition — the restart leg reads both partitions, and a test pins that a twice-replayed span derives once. |
| C1's watcher is written to a transition that never occurs, and ships green. | Lock 3 names the trigger as *any* `READY` departure and return; the C1 test exercises an `IDLE` cycle, and the upsert test is pinned separately so it cannot stand in as evidence. |
| The release ships half the boundary and the note over-claims. | Acceptance requires R-1 and R-2 together; any write that slips is stated as an open residual. |
| Group-memory fragmentation reads as a regression. | This *is* the promise applied inside a room — the trade v0.3.14 made per person. Room continuity is untouched; stated in the notes, observed by an MT leg. |
| The live arc cannot run because the fleet goes mute at the first restart — the failure that already voided one arc on a paid provider. | C1 lands before any live restart leg. If it cuts, the arc keeps the manual-restart step and both warnings stay. |
