> v0.3.5 — "Session-Scoped Memory" — ships [RFC 0031](rfcs/0031-per-session-namespacing-channels.md) Phases 2–4 (session-scoped persona-memory recall + the `persatrix session …` operator CLI) plus the **epoch** run-isolation axis ([ISSUE-0085](issues/ISSUE-0085-epoch-axis-run-isolation.md)), with [RFC 0033](rfcs/0033-model-alias-layer.md) Phase 3 (the alias-layer closeout) as a conditional co-resident. The user-facing promise: *persona-memory recall is session-scoped — a run reads only its own session's rows (plus the always-visible `legacy` carve-out), so concurrent conversations don't bleed; isolate a run by giving it a fresh session, or wipe a same-named rerun clean with a fresh `epoch`, instead of nuking volumes with `make reset`.* This closes the **F-3** cross-run state bleed at the root (the recall half via session scoping, the structural half via epoch strict-equality isolation).

### 3.1 Required Upgrade Notes in Changelog

This is the canonical source for Upgrade Notes text (PR 3 copies it into `CHANGELOG.md`).

| Notable change | Detail |
|----------------|--------|
| **[Behaviour change — session-scoped default recall]** | Default persona-memory recall is now **session-scoped**: a run reads only the rows tagged with its active session, plus the always-visible `legacy` carve-out, across all four persona-memory tiers (episodes, relationships, facts, notes). Concurrent conversations no longer bleed into each other. Reaching across sessions (`sessions="*"`) is an explicit, library-only opt-in with no operator entry point (RFC 0031 §D). This is a behaviour change from the pre-v0.3.5 whole-store recall. |
| **[Feature]** `persatrix session …` operator CLI | A first-class session surface: `persatrix session new --label L [--activate] / use <id-or-label> / list [--include-archived] / current / archive <id-or-label>`, backed by the `/api/v1/sessions` REST registry. The active session resolves by precedence `--session` flag > `PERSATRIX_SESSION_ID` env > `~/.persatrix/active-session` pointer file > built-in `legacy` (RFC 0031 OQ #6). `legacy` is a reserved label; archive is one-way. See the [sessions operator guide](guides/sessions.md). |
| **[Feature]** Epoch run/test-isolation axis | A new `epoch` axis isolates a *same-named* rerun structurally: a fresh `PERSATRIX_EPOCH` (orchestrator boot env) or `--epoch <id>` (per-invocation override on `chat` / `channel send` / `channel reply`), default `live`, inherits **none** of a prior run's episodes / relationship trust / person-facts — strict-equality isolation with no `legacy` carve-out and no `*` wildcard. Production is unchanged (untagged deployments run under `live`). See the [epochs operator guide](guides/epochs.md). |
| **[Behaviour change — `make reset` reframed]** | `make reset` (`docker compose down -v`) is now positioned as the **whole-stack volume nuke** — all epochs across all sessions — not the everyday run-isolation tool. For an isolated rerun reach for a fresh `epoch` instead; `make reset` is for when you want the volumes themselves gone. The breadcrumb is reframed across the [channels](guides/channels.md), [persona-agents](guides/persona-agents.md), and [sessions](guides/sessions.md) guides. |
| **[Migration]** Auto-migration to `legacy` / `live` | A pre-v0.3.5 database auto-migrates on first open. Persona memory (`memory.db`) runs migrations v4→**v12**: the session axis added `session_id` (episodes/relationships v7, facts v8, notes v9, defaulting `'legacy'`); the epoch axis added `epoch_id` across all five tiers + the `relationships` primary key (v12, defaulting `'live'`). The channel store (`channels.db`) is at `channelStoreSchemaVersion = 6` (v5 session axis, v6 epoch axis). Every existing row lands under `session_id='legacy'` / `epoch_id='live'` and stays visible from the default resolution path — single-world deployments are byte-identical. |
| **[Behaviour change — RFC 0033 Phase 3]** Raw vendor IDs rejected | A `model:` in `config/agents.yaml` / `config/optimization.yaml` that is **not a declared alias** is now **rejected at resolve** with a loud `SystemExit` — the RFC 0033 §E raw-ID fall-through (a deprecation warning in v0.3.4) is removed, along with the `_infer_provider` heuristic, the `provider_inference` accessor/YAML block, and the `persatrix.llm.alias.raw_id_usage` gate counter. `config/optimization.yaml` `schema_version` bumps `"0.2"` → `"0.3"`. `models.aliases` is the single source of truth for model identity — provider is data, not inferred. |

## 6. Known Gaps to Document in Release Notes

These items remain intentionally incomplete and should be described as deferred scope, not regressions. Seeded from [v0.3.5-plan §Out of scope](v0.3.5-plan.md) and the [release-prep plan §Known follow-up issues](v0.3.5-release-prep-plan.md#known-follow-up-issues).

### v0.3.5-scope gaps

| Area | Description | Deferred to |
|------|-------------|-------------|
| Subject-scoped facts ([ISSUE-0084](issues/ISSUE-0084-fact-scope-by-subject-not-uniform-session.md)) | Facts are scoped uniformly by session like the other tiers; scoping a fact by its *subject* (so a fact about Alice follows Alice across sessions) is a continuity refinement, not a leak. | Beyond v0.3.5 — tracked separately |
| `--all-sessions` recall verb ([ISSUE-0086](issues/ISSUE-0086-operator-all-sessions-recall-verb.md)) | The `sessions="*"` cross-session debug mode exists at the recall layer but is reachable only programmatically; the `persatrix memory recall --all-sessions` operator verb is not built. The persona-runtime default context path is pinned never to reach `"*"` (the Phase 2 guarantee), so this is a missing convenience, not an isolation risk. | Tracked issue |
| `legacy` / `live` carve-out is permanent | Pre-v0.3.5 rows land under `session_id='legacy'` / `epoch_id='live'` and stay visible from the default path — the intended back-compat behaviour, by design. `persatrix memory legacy-prune` (a future cleanup verb) is scoped at [RFC 0031 Phase 4](rfcs/0031-per-session-namespacing-channels.md#phase-4-cleanup-and-documentation-pass), not built here. | RFC 0031 Phase 4 follow-up |
| Split-volume partial-reset footgun | The session registry (`channels.db`) and per-agent `memory.db` files live in different volumes that no single transaction spans; a partial `make reset` can strand `session_id`s in the registry vs. the per-agent store (the `legacy` carve-out keeps rows visible rather than orphaned). Reset both volumes together, or neither. A single-transaction society store (RFC 0029 Phase 3) closes this structurally. | RFC 0029 Phase 3 (v0.4.0) |
| DM-chat close-path write follows the persona's *boot* session/epoch (F-1) | A `--session` / `--epoch` on one `chat` call governs the recall query + channel-binding for that call but does not retag the asynchronous interaction-close write in a long-running persona (tagged with the session/epoch snapshotted at boot). Operator-documentation nuance, not an isolation defect — noted in the [sessions guide §4](guides/sessions.md). | Documented in the sessions guide |
