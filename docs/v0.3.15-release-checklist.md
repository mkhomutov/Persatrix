### 1.1 Live-run guidance (for any re-run of the arc)

The arc itself ran once, at PR 1. This section exists so a re-run does not
re-learn what that run cost to find — [ten defects in the procedure](manual-tests/v0.3.15-execution-report.md#mt-corrections--ten-defects-in-the-procedure-itself),
fixed in [MT-MEMORY-GROUP-TENANT-001](manual-tests/MT-MEMORY-GROUP-TENANT-001.md) v1.2.

**Reading live cost — the v0.3.14 instruction is wrong and must not be copied a third time.** That
checklist says `docker compose logs orchestrator | grep '"op":"settle"'` "yields
lease finalization carrying `actualUSD`". Both halves are false: `"op":"settle"`
matches `wallet: lease finalized` ([`internal/wallet/wallet.go`](../internal/wallet/wallet.go)),
which carries token counts and **no USD figure**; `actualUSD` rides a different
line with no `op` field — `provisional charge reconciled`
([`internal/cost/cost.go`](../internal/cost/cost.go)). Use
`scripts/manual_tests/mt_group_tenant_evidence.py::collect_cost`, which reads the
correct line and sums it, and read it **before `docker compose down -v`** — the
v0.3.14 arc lost its figure to teardown. Both lines are `Debug`: the compose stack
emits them because it runs `--env development`, but a `production` deployment logs
neither, so cost is not recoverable from logs there at all (`persatrix cost` is
still unimplemented).

**Preflight gates must parse, not grep.** The first Leg 2 of the PR 1 arc reported
"5 dispatches, 5 tenant-less" — the exact signature of R-2 being broken — because
`auth.mode` was `disabled` and the file gate had matched the word `mode: enabled`
inside a *comment*. A green arc proved nothing. The gate now parses YAML **and**
probes a `policyAuthenticated` route for `401`, because the file and the running
process disagree whenever the stack booted before the edit. Never accept an
artifact as a finding until storage agrees with it.

**Setup preconditions the MT now states**: bootstrap the account **in-container**
(the orchestrator reads `/var/lib/persatrix/accounts.db` on a named volume, not
`./data`); remove `-wal`/`-shm` sidecars with the database; declare membership in
config rather than `channel join` (a store/config divergence is a **FATAL** at
startup); pass `--as` on every send (its default is the OS username); rebuild the
**host** binaries too (`--build` refreshes only the container); and `make reset`
first — Leg 4's assertion is a count.

**Pacing**: governance windows are real time. Machine-pace the whole arc in one
script rather than idling between legs.

### 3.1 Required Upgrade Notes

1. **Four store migrations across two databases — the release is forward-only, not drop-in.**
   Channel store (Go) **v11 → v12** (`principal_id` on `messages`, stamped
   server-side at publish) and **v12 → v13**; persona-memory (Python) **17 → 18**
   (`speaker_id` on the derived tiers) and **19** (an index on the re-keyed close
   predicate). Two are not the ordinary "migration ahead of its consumer" shape:
   **v13 is a repair that ships *with* its consumer** — v12's backfill was inverted
   at the B2 review, `applyMigration` dispatches on `user_version`, so a store
   already at v12 would keep the inverted backfill forever and its first
   post-upgrade catch-up would derive an authenticated person's content into the
   shared `local` tenant permanently; v13 detects an affected store exactly and
   rewrites those rows. **19 has no reader to be ahead of** — it adds no column and
   changes no read *result*, only the plan. **Downgrade caution**: a store carried
   forward to channel v13 or persona-memory 19 and then run under a v0.3.14 binary
   meets a `user_version` from the future. Forward is supported; backward is not.
2. **The coherence trade.** Close-derived group memory now fragments **per speaker
   per tenant** — N partial views, not one narrative. This is the v0.3.14 promise
   applied *inside* a room rather than a regression: room continuity is untouched,
   because the transcript and RFC 0036 verbatim history are scoped by neither axis.
3. **The reserve re-size and its clamp consequence.** The [RFC 0052 §D](rfcs/0052-autonomous-agent-channels.md#d-termination-and-synthesis--always-produce-an-artifact)
   close reserve is now record-scaled `1 + R` (`personas × principals × speakers`)
   rather than roster-scaled `1 + N`. `R` grows with the **cube** of the room, so
   the half-cap clamp now bites in ordinary configs — **the bundled four-seat
   `blueprints/autonomous-multivendor` roster clamps at its own shipped 200 000
   cap** (clearing it needs 259 000). The effect is bounded (a clamped reserve is
   half the cap: the discussion gets half its budget, the close fires earlier and
   never later) and **no longer silent**:
   `channel.conversation.synthesis_reserve_clamped{channel_type, trigger}` fires
   per affected close, plus a warning once per channel per configuration.
   Calibration is deferred to [ISSUE-0138](issues/ISSUE-0138-close-reserve-multiplier-calibration.md).
4. **`agent.interactions.closed.by_<reason>` changes shape.** A room-wide close now
   fans across records rather than closing one, so the counter and its per-reason
   subtotals fire once **per record** — a room close increments by N. Dashboards
   keying off these need re-checking.
5. **The narrowed catch-up skip.** A replayed span now derives under **its own**
   tenant instead of being dropped wholesale, and derives **exactly once** across
   restarts. Only a genuinely unattributable span (a pre-v12 orchestrator, or a row
   written before the migration) still skips.
6. **`auth.mode: disabled` is byte-identical on the principal axis — and deliberately
   not on the speaker axis.** Every caller still resolves the single `local` tenant;
   within it, records now split by speaker. Leg 8 of the arc is exactly this
   assertion: same sender stamped `local`, `local` partition holding **2 speakers,
   not one**.
