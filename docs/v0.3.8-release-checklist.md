> v0.3.8 — "Conversations that converge" — ships the **brainstorm rung**: the convergence cluster that takes a multi-persona channel from *chatter* to a brainstorm that **converges, terminates, and produces a readable result**. **[RFC 0030 relevance Tier B](rfcs/0030-amendment-relevance-gated-response.md) — no pile-on** — an un-addressed open-floor message draws a small, relevant reply set via a cheap leased `fast`-model salience bid ([`agents/salience_bid.py`](../agents/salience_bid.py)) gated by each membership's `threshold`; the `chair` is a low-threshold facilitator (its Layer-5 moderator half inert). **[RFC 0030 governance Layers 1/2/4](rfcs/0030-multi-agent-conversation-governance.md) — converge + terminate** — a per-interaction cost ceiling (`interaction_budget_tokens`, fail-closed in the wallet), a per-participant reply budget (`max_replies_per_participant_per_interaction`, HTTP 429 pre-persistence), and an end-of-interaction vote (`END_INTERACTION_VOTE`; K distinct votes in W turns close), made live by the **`interaction_id` producer** + the **chair-stall escalation** and **end-vote close propagation** amendments. **[RFC 0020 interaction-summary surface](rfcs/0020-interaction-lifecycle.md) — a real result** — a closed interaction surfaces its one-per-interaction summary via the web console and `persatrix agent interactions`. Folded in: **[RFC 0050 operator-editable channel config](rfcs/0050-extensible-channel-configuration.md)** — the governance knobs are editable live from the CLI and web console, with the channel store as the single source of truth and a revision-gated YAML loader. The user-facing promise: *give a group of personas a problem and watch the brainstorm converge, terminate, and produce a readable synthesized outcome — no pile-on, bounded cost, a real result, and knobs you can turn without a restart.*

### 3.1 Required Upgrade Notes in Changelog

This is the canonical source for Upgrade Notes text (PR 3 reconciles it with the eight-row table already in `[0.3.8] - Unreleased`). **Seven of the eight existing rows stand as-is.** The two below are **not pure additions**: the existing channel-store **`v7→v8`** row is **replaced** — *not* joined — by the **`v6→v8`** row (the existing one is a Phase-1 snapshot still reading *"no behaviour change … not yet consulted at runtime"*, which contradicts the release reality that `config_edit_enabled` ships on and the apply path is live — leaving both rows would ship two conflicting channel-store migration notes); and the **persona-memory `v14→v15`** row is **promoted** from the inline mention already in the `🐛 Bug Fixes` ISSUE-0102 entry (`CHANGELOG.md` — *"schema migration v15 promotes the governance id to a queryable `episodes.governance_interaction_id` column"*) into a first-class migration note — do not author a second, divergent description. Plus the behaviour-active-by-default caveat and the version-skew caution.

| Notable change | Detail |
|----------------|--------|
| **[Migration — forward-only, upgrades on open]** Channel store v6→v8 | The channel store (`channels.db`, [`internal/channels/sqlite_schema.go`](../internal/channels/sqlite_schema.go)) advances from **v6** (the v0.3.5 epoch axis) to **v8**: **v7** adds the per-member salience-bid `threshold` column (RFC 0030 Tier B) — a pre-v7 row reads back as an un-gated legacy `always` member; **v8** adds three additive `channels` columns (RFC 0050) — `config_overrides_json` (a sparse per-channel governance override blob; `NULL` = inherit every knob), `config_revision` (store-owned monotonic revision, backfilled to `0`), and a reserved/dormant `config_change_lineage`. **Upgrades automatically on first open**, no operator action, no data loss; an already-v8 store is a no-op open. An existing `config/channels.yaml` seeds the router unchanged. With this release `config_edit_enabled` defaults **on**, so the CLI `channel config` verbs and the web settings panel are live. **There is no rollback path — forward-only.** See the [channels guide § channel config](guides/channels.md) and [RFC 0050](rfcs/0050-extensible-channel-configuration.md). |
| **[Migration — forward-only, upgrades on open]** Persona-memory v14→v15 (queryable governance interaction id) | The persona-memory schema (`agents/memory/migrations.py`) advances from **v14** to **v15**: migration 15 ([`_migration_governance_id.py`](../agents/memory/_migration_governance_id.py)) promotes the RFC 0030 governance interaction id to a queryable `episodes.governance_interaction_id` column (backfilled from the ISSUE-0102 context blob via `json_extract`), so `--interaction-id` matches **either** namespace (agent-side episode id *or* the orchestrator's governance id pasted from the logs). **Upgrades automatically on first open**, no operator action, no data loss; an already-v15 DB is a no-op open. **There is no rollback path — forward-only**, per the established migration contract. See [RFC 0020 §C/§D](rfcs/0020-interaction-lifecycle.md). |

**Behaviour-active-by-default caveat (must appear in the release body).** With the **interaction-id producer** landed in this same release, the governance layers run **live by default** — ids are stamped on every publish, an interaction closes on the end-vote defaults (K=2 / W=3), and idle rotation fires at 600s. An unedited `config/channels.yaml` therefore no longer behaves *exactly* as in v0.3.7. The **enforcement ceilings** (the Layer 1 cost ceiling, the Layer 2 reply budget) stay **off until opted in** — only the id stamping / end-vote close / idle rotation are active out of the box.

**Version-skew caution (RFC 0030 floor-capable directedness).** Upgrade agents first (or together) — a v0.3.8 orchestrator fanning out to pre-v0.3.8 agents degrades the directedness defect-fix scenario to a multi-minute publish stall ([floor-capable-directedness amendment §C item 1](rfcs/0030-amendment-floor-capable-directedness.md)). The reverse skew is safe (over-suppression, never under). Note it in the release notes.

### v0.3.8-scope gaps

| Area | Description | Deferred to |
|------|-------------|-------------|
| RFC 0030 **Layer 5 — moderator / bid-and-select** deferred | The v0.3.8 `chair` is a low-threshold facilitator with a minimal stall-escalation slice; it **cannot unilaterally close / wrap up / terminate** a conversation. The [`chair_moderation.py`](../agents/chair_moderation.py) seam is present but inert. Convergence is owned by Layers 1/2/4. The bid-and-select generalization of Tier B is also Layer 5. | v0.4.0 |

| Layer 1/2 **default-value calibration** deferred | The enforcement ceilings ship **uncapped/opt-in**; deriving sensible per-type defaults needs observed-workload data ([RFC 0030 §OQ-5](rfcs/0030-multi-agent-conversation-governance.md#open-questions)). No normative numbers ship in v0.3.8. | post-soak v0.3.x |
| RFC 0034 **Phase 3** deferred | Conversation-window instrumentation/tuning + the in-process fetch-cache **LRU bound** (currently unbounded-per-process). Tier B only *reads* the v0.3.7 in-round transcript; it does not re-open the window mechanics. RFC 0034 stays `⚠️ Partially Implemented` (Phases 1–2). | v0.3.x |
| Natural-language addressing is a **soft signal, not a hard filter** | "let's hear from X" *biases* the Tier-B bid; only structured `@`-mentions deterministically drop. A hard NL directed-elsewhere filter stays out until parsing is reliable ([amendment OQ #2](rfcs/0030-amendment-relevance-gated-response.md#open-questions)). | future |
| RFC 0050 **Phase 3** deferred | Schema-driven generic config / profiles. v0.3.8 ships the per-channel governance-override surface (Phase 1 + Phase 2); the generic schema-driven layer is a future RFC. RFC 0050 closes as `✅ Implemented` for its Phase 1+2 scope. | future RFC |
| DM `idle_gap` summary-trigger live re-exercise | `MT-INTERACTION-SUMMARY-001` Part A (the DM `close_reason=idle_gap` path) needs a ~10-minute idle window impractical in a live session; the summary surface is proven live ×3 (Part B) and the `idle_gap` boundary detection is pinned by the structural boundary-detector + episodic-lifecycle suites. Exercise the DM `idle_gap` close in a soak/long-idle run. | soak v0.3.x |
