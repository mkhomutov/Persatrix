# GitHub Workflows

> **Last updated**: 2026-11-14
> What runs on GitHub and when: every workflow under `.github/workflows/`
> and the Dependabot entries. Split out of the
> [automation catalogue](automation-catalogue.md), which lists everything
> else that runs without a human typing the steps.

| Workflow | Trigger | Does |
|----------|---------|------|
| `ci.yml` | push to `main`, every PR | Eleven jobs: `Go (build + test)` (incl. gofmt, the pinned golangci-lint via `make lint-go`, every Go package's tests via `make test-go`, sanitizer sync), `Web console (build + test)`, `Dockerignore context hygiene`, `Proto staleness check`, `Python (lint + test)` (incl. ruff/mypy on `scripts/` + `evaluators/`; its last four steps install the optional provider SDKs at their pins, type-check the Gemini and watsonx adapters against them, run both adapters against the real SDKs and check the licenses of what the SDKs brought in), `Cost regression gate (bored persona)` (path-filtered), `Rust (build + clippy)` (incl. rustfmt, `cargo test`; on the release `cli/rust-toolchain.toml` pins), `Validate configs` (incl. `prompt_refs` and the ROADMAP status rows), `Docs hygiene` (links, markup, markers, FILEMAP, merged-PR history, plan status, amendment evidence, conformance), `File size check`, `Third-party license check`. Every job carries a comment naming the incident it guards. |
| `commitlint.yml` | PR opened/edited/synchronised | Conventional Commit PR title (`Validate PR Title`) |
| `scheduled-audit.yml` | Mondays 06:00 UTC; manual | Four advisory audits in one job, each run even when another fails: `cargo deny check -D advisory-not-detected advisories bans sources licenses` for the CLI, which also fails on a `deny.toml` ignore that matches no crate; `govulncheck ./...` for the Go modules, on the newest patch release of the Go line `Dockerfile.orchestrator` builds with; `pip-audit --no-deps --disable-pip` over every `.github/python-constraints*.txt`; `npm audit --package-lock-only --audit-level=moderate` for `web/`. Any failure opens or comments on a `Scheduled Dependency Audit Failure` issue that names the audits that failed and the command each one ran |
| `perf-baseline-capture.yml` | manual (`workflow_dispatch`) | Captures the recall-latency baseline on a runner and opens a PR with it; merging arms the perf gate. Never run yet |
| `python-constraints-refresh.yml` | Mondays 05:00 UTC; a push to `main` that changes `agents/pyproject.toml`; manual | Re-resolves CI's Python pins, both constraints files, to the newest releases the ranges allow, installs them and runs the Python checks (`lint-python`, `proto-python-check`, the stable eval replay, the three test trees, `check-licenses-python`, `validate`, then with the provider SDKs added `lint-providers`, `test-providers` and `check-licenses-providers`). Reports in one `CI Python constraints: weekly refresh` issue: on green it pushes `chore/python-constraints-refresh` and links "Open the PR" (Actions may not open PRs here, and a person's PR starts CI); on red it names every failing check and leaves the pins alone; when nothing moved it closes the issue |
| `dependabot.yml` (config, not a workflow) | monthly | One grouped version-update PR per ecosystem — Go, pip (`agents/`), Cargo (`cli/`), the Rust toolchain (`cli/rust-toolchain.toml`, one release per PR), npm (`web/`), the base images of the two Dockerfiles, the images the compose files run, GitHub Actions — titled `chore(deps): …`; at most two open per ecosystem, and one for the Rust toolchain and for GitHub Actions. Two image tags are never offered a move: the agent image's Python (an open choice, ISSUE-0219) and the Node the orchestrator image builds the console with (held to the `engines` floor by a test). Committed 2026-09-06; before that only security updates ran. The pip block manages the ranges in `agents/pyproject.toml` only; CI's pins move through `python-constraints-refresh.yml` |
