**Scope**: the release-prep workstream for the v0.3.8 surface — the convergence cluster that takes a multi-persona channel from *chatter* to a **brainstorm that converges, terminates, and produces a readable result**. Four landed workstreams jointly own the headline:

1. **No pile-on — the Tier B salience bid + the `chair`** ([RFC 0030 relevance amendment](rfcs/0030-amendment-relevance-gated-response.md)). On an un-addressed open-floor message a `participant`/`chair` runs one cheap, leased `fast`-model bid ([`agents/salience_bid.py`](../agents/salience_bid.py)) and stays silent unless its score clears its `threshold` (the v0.3.7 reserved/no-op field, now live); the `chair` disposition is a low-threshold facilitator with its Layer-5 moderator half still inert ([`agents/chair_moderation.py`](../agents/chair_moderation.py)).
2. **Converge + terminate — governance Layers 1/2/4** ([RFC 0030 §E/§F/§H](rfcs/0030-multi-agent-conversation-governance.md)). Layer 1 per-interaction cost ceiling (`interaction_budget_tokens`, fail-closed in the wallet), Layer 2 per-participant reply budget (`max_replies_per_participant_per_interaction`, HTTP 429 pre-persistence), Layer 4 end-of-interaction vote (`END_INTERACTION_VOTE`; K distinct votes in W turns close). The **`interaction_id` producer** ([producer plan](rfcs/0030-interaction-id-producer-pr-plan.md)) makes the layers run live by default; the **chair-stall escalation** and **end-vote close propagation** amendments close the last two silent-death modes.
3. **A real result — the interaction-summary surface** ([RFC 0020 §C/§D](rfcs/0020-interaction-lifecycle.md)). A closed interaction (votes / cost / idle) surfaces its already-persisted one-per-interaction summary via the web console and `persatrix agent interactions`; the summariser is unchanged (a read surface, not a new synthesis step).
4. **Operator-editable channel config — RFC 0050 (fold-in)** ([RFC 0050](rfcs/0050-extensible-channel-configuration.md)). Per-channel governance config is editable from CLI and web console without restart, with the channel store as the single source of truth and a revision-gated YAML loader so config-as-code and live edits coexist. Not one of the three master-plan workstreams — it grew during the cycle as the surface that makes the convergence knobs *operable* — but it is part of the v0.3.8 release surface and a release gate.

It covers: **execution** of the already-authored convergence manual tests ([`MT-CHANNEL-RELEVANCE-002`](manual-tests/MT-CHANNEL-RELEVANCE-002.md), [`MT-CHANNEL-GOV-003`](manual-tests/MT-CHANNEL-GOV-003.md), [`MT-CHANNEL-GOV-004`](manual-tests/MT-CHANNEL-GOV-004.md), [`MT-INTERACTION-SUMMARY-001`](manual-tests/MT-INTERACTION-SUMMARY-001.md), [`MT-CHANNEL-CONFIG-001`](manual-tests/MT-CHANNEL-CONFIG-001.md)…[`004`](manual-tests/MT-CHANNEL-CONFIG-004.md)) plus a **combined convergence walkthrough** (no-pile-on → bounded cost → ends on votes → readable summary on one multi-persona channel — the role the master plan reserved for `MT-CONVERSATION-CONVERGENCE-001`) and the carried-forward v0.3.7 surface; a documentation + release-checklist refresh; version bump `0.3.7` → `0.3.8`; dating the existing `[0.3.8]` `Unreleased` changelog into a tagged `[0.3.8]`; and final pre-tag verification (the **two schema migrations** — channel store v6→v8 and persona-memory v14→v15 — are release gates).

**Out of scope**: new feature work. All four workstreams are fully landed with no outstanding PRs (see [§RFC PR roll-up](#rfc-pr-roll-up)). Deferred — documented as Known Gaps in the release notes, not release gates:

- **RFC 0030 Layer 5 — moderator / bid-and-select** → **v0.4.0**. The `chair`'s active half (transcript-level continue / wrap-up / terminate) and the bid-and-select generalization of Tier B both depend on the moderator agent, which composes with the RFC 0028 decision engine. v0.3.8 ships the `chair` *disposition value + low-threshold behaviour + the minimal stall-escalation slice* only; the [`chair_moderation.py`](../agents/chair_moderation.py) seam stays inert. A v0.3.8 `chair` **cannot unilaterally close a conversation** — convergence is owned by Layers 1/2/4.
- **RFC 0030 Layer 6 — declarative conversation types** (`design_review`, etc. with per-type budgets) → **v0.5.0+**. v0.3.8 exposes the raw per-channel knobs; the named-type presets that bundle them are later.
- **Layer 1/2 default-value calibration** ([RFC 0030 §OQ-5](rfcs/0030-multi-agent-conversation-governance.md#open-questions)) → **post-soak v0.3.x**. The enforcement ceilings ship **uncapped/opt-in**; deriving sensible per-type defaults needs observed-workload data. No normative numbers ship in v0.3.8.
- **RFC 0034 Phase 3** (conversation-window instrumentation/tuning + the fetch-cache LRU bound) → **v0.3.x**. Tier B only *reads* the v0.3.7 in-round transcript; it does not re-open the window mechanics. RFC 0034 stays `⚠️ Partially Implemented` (Phases 1–2).
- **RFC 0050 Phase 3** (schema-driven generic config / profiles) → a **future RFC**. v0.3.8 ships Phase 1 (persisted per-channel config + revision-gated YAML reconciliation) and Phase 2 (CLI + web-console editing, `config_edit_enabled` on); the generic schema-driven layer is later. RFC 0050 closes as `✅ Implemented` for its Phase 1+2 scope.
- **RFC 0035 / RFC 0036** (membership ledger + verbatim recall) → **v0.3.9**, the next release. Not a dependency of convergence.

**Documentation timing policy** (carry-forward from [v0.3.7 prep](v0.3.7-release-prep-plan.md)): public docs updated *before* tag; post-tag-only artifacts (tag link, release URLs, "Released" stamps) → [v0.3.8-plan Phase 4](v0.3.8-plan.md#phase-4--tag-and-post-release-follow-up).

### Known follow-up issues

All Known Gaps for the release notes, not release gates:

1. **RFC 0030 Layer 5 — moderator / bid-and-select deferred** → **v0.4.0**. The v0.3.8 `chair` is a low-threshold facilitator with a minimal stall-escalation slice; it **cannot unilaterally close / wrap up / terminate** a conversation. The [`chair_moderation.py`](../agents/chair_moderation.py) seam is present but inert. Convergence is owned by Layers 1/2/4.
2. **RFC 0030 Layer 6 — declarative conversation types deferred** → **v0.5.0+**. v0.3.8 exposes the raw per-channel knobs (`interaction_budget_tokens`, `max_replies_per_participant_per_interaction`, `threshold`, `end_vote_threshold`/`end_vote_window`, `escalation_chair_id`); the named-type presets that bundle them are later.
3. **Layer 1/2 default calibration deferred** → **post-soak v0.3.x**. The enforcement ceilings ship **uncapped/opt-in**; no normative numbers until observed-workload data exists ([RFC 0030 §OQ-5](rfcs/0030-multi-agent-conversation-governance.md#open-questions)).
4. **RFC 0034 Phase 3 deferred** (conversation-window instrumentation/tuning + the fetch-cache **LRU bound**) → v0.3.x. The cache is currently unbounded-per-process; Phase 3 bounds it. RFC 0034 stays `⚠️ Partially Implemented` (Phases 1–2).
5. **Natural-language addressing is a Tier-B salience signal, not a hard filter.** "let's hear from X" *biases* the bid; only structured `@`-mentions deterministically drop. A hard NL directed-elsewhere filter stays out until parsing is reliable ([amendment OQ #2](rfcs/0030-amendment-relevance-gated-response.md#open-questions)).
6. **RFC 0050 Phase 3 deferred** (schema-driven generic config / profiles) → a future RFC. v0.3.8 ships the per-channel governance-override surface; the generic schema-driven layer is later.
7. **Version-skew caution (RFC 0030 floor-capable directedness):** upgrade agents first (or together) — a v0.3.8 orchestrator fanning out to pre-v0.3.8 agents degrades the directedness defect-fix scenario to a multi-minute publish stall ([amendment §C item 1](rfcs/0030-amendment-floor-capable-directedness.md#c-mechanism--resolve-at-the-orchestrator-carry-on-the-wire)). The reverse skew is safe (over-suppression, never under). Note it in the release notes.

Any `Accepted-with-known-gap` MT outcome in PR 1 must cite a tracked issue or an RFC-closeout / sequencing follow-up bullet.
