**Scope**: the release-prep workstream for the v0.3.6 surface — the embedded web console (`--enable-ui`, off by default; chat + channel-timeline panels behind `config/ui.yaml`) and the channel floor-control fold-in ([RFC 0030 Layer 2.5](rfcs/0030-amendment-floor-control-speaker-serialization.md)). It covers: **execution** of the two already-authored manual tests ([`MT-CONSOLE-001`](manual-tests/MT-CONSOLE-001.md), [`MT-CHANNEL-GOV-002`](manual-tests/MT-CHANNEL-GOV-002.md)) plus the carried-forward v0.3.5 surface against the RC tip; a documentation + release-checklist refresh; version bump `0.3.5` → `0.3.6`; dating the existing `[Unreleased]` changelog into `[0.3.6]`; and final pre-tag verification.

**Out of scope**: new feature work. Both v0.3.6 workstreams are fully landed with no outstanding PRs — RFC 0048 Phase 1 / Slice 1 (6 PRs + Docker enablement + the channel-creation and chat-panel-retirement amendments) and the RFC 0030 floor-control amendment (4 PRs, telemetry included). Deferred — documented as Known Gaps in the release notes, not release gates:

- **RFC 0048 Slices 2–5** (memory inspector, isolation verifier, cost/observability, control plane) → v0.4.0+; Slice 5 is hard-gated on [RFC 0039](rfcs/0039-user-accounts-authentication.md) auth. Their `config/ui.yaml` toggles ship **off**.
- **Channel real-time push (OQ4)** and **chat token streaming (OQ5)** → named later enhancements; Slice 1 polls + synchronous request/response is the contract.
- **Floor-control follow-ups** — no responder-per-round cap (D4) and the `(channel_id, stimulus)` → `interaction_id` re-key (D5) are post-v0.3.6.

**Documentation timing policy** (carry-forward from [v0.3.5 prep](v0.3.5-release-prep-plan.md)): public docs updated *before* tag; post-tag-only artifacts (tag link, release URLs, "Released" stamps) → [v0.3.6-plan Phase 4](v0.3.6-plan.md#phase-4--tag-and-post-release-follow-up).

### Schema / migration state

v0.3.6 adds **no persona-memory or channel-store migration** — it is render-over-existing-API plus an orchestrator-side conversation-governance change. The relevant new/changed config + schema surfaces:

- **`config/ui.yaml` + [`schemas/ui.schema.json`](../schemas/ui.schema.json)** — the feature-toggle file (panels `enabled`; `available` is runtime-derived and authoring it is a validation error), wired into `make validate`.
- **`config/channels.yaml` / [`schemas/channel.schema.json`](../schemas/channel.schema.json)** — the optional `floor_control` (bool) and `floor_turn_timeout_seconds` (int ≥ 1, default 45) keys; group channels default `floor_control` **on**.
- **Channel store** (`channels.db`) — [`channelStoreSchemaVersion`](../internal/channels/sqlite_schema.go) stays at `6` (the v0.3.5 epoch axis); floor control is in-process state, not persisted.

PR 2 / PR 3 Upgrade Notes confirm a pre-v0.3.6 database opens unchanged (no migration) and that floor control activates on the default group-channel path with no operator action.

### Manual test state

The two v0.3.6 MTs are **already authored** (during implementation) — PR 1 **executes** them; it does not author new recipes:

- **[`MT-CONSOLE-001`](manual-tests/MT-CONSOLE-001.md)** — *Web Console fresh-stack Interactions slice* (**primary v0.3.6 gate**). From a clean build: `make ui` produces the real Svelte bundle; `--enable-ui` serves it at `/ui`; pick a persona and chat (synchronous reply); reload-and-confirm-recall; the session/epoch scope selector passes through; the channel timeline polls live; the optional human publish surfaces the agent fan-out.
- **[`MT-CHANNEL-GOV-002`](manual-tests/MT-CHANNEL-GOV-002.md)** — *Floor control: ordered, mutually-aware multi-persona replies* (**headline-claim test**). Three personas in a group channel, one user prompt; expected: ordered, mutually-aware replies (each reads its predecessors) with at least one `DO_NOTHING` when a point is already covered — contrasted against the pre-amendment simultaneous-shout baseline.

The v0.3.5 surface **carries forward**, regression-checked against the v0.3.6 RC tip. PR 1 confirms the final total once the two new rows are reflected in the [`manual-tests/README.md`](manual-tests/README.md) index.

The structural gates are the **automated release-blockers** counterpart to the new MTs: the web-console handler/scaffold tests (`internal/server/...`) and the floor-control suites ([`internal/channels/floor_control_test.go`](../internal/channels/floor_control_test.go), [`internal/channels/fanout_floor_test.go`](../internal/channels/fanout_floor_test.go)) — including the flag-off regression path that runs the existing concurrent-fanout suite unchanged. The carried-forward alias cost-attribution gate and the session/epoch isolation gates keep the v0.3.5 surface green.

### Known follow-up issues

All Known Gaps for the release notes, not release gates:

1. **RFC 0048 Slices 2–5 deferred** (memory inspector, isolation verifier, cost/observability, control plane) → v0.4.0+; Slice 5 hard-gated on [RFC 0039](rfcs/0039-user-accounts-authentication.md). Their `config/ui.yaml` toggles ship **off** so they land additively.
2. **Channel real-time push (OQ4) + chat token streaming (OQ5) deferred** — Slice 1 polls (with visibility-pause + error-backoff + head-poll de-dupe) and uses synchronous request/response. Named later enhancements.
3. **Floor control: no responder-per-round cap (D4), single-replica only (D5).** Floor state is in-process (the same single-replica constraint as the existing `replyWaiter`); the no-cap decision is bounded by Layers 0/2 and revisited via the shipped floor telemetry. The `(channel_id, stimulus)` → `interaction_id` re-key is a post-v0.3.6 follow-up.
4. **`/ui/` rate-limit exemption deferred** — static fetches ride the shared `apiH` rate limiter; exempt the `/ui/` prefix only if a page load trips it in practice (tracked as a fast-follow, not folded into Slice 1).

Any `Accepted-with-known-gap` MT outcome in PR 1 must cite a tracked issue or an RFC-closeout / sequencing follow-up bullet.
