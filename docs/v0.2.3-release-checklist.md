### 3.1 Required Upgrade Notes in Changelog

This is the canonical source for Upgrade Notes text; the `[Unreleased]`
section already contains the same content verbatim and must be preserved
when it is reshaped into `[0.2.3]`.

| Notable change | Detail |
|----------------|--------|
| Jaeger OTLP host ports unpublished | The `jaeger` service in `docker-compose.yaml` no longer publishes `4317`/`4318` on the host. The OTEL Collector now owns the host-facing OTLP ingress (also on `4317`/`4318`) and forwards traces to Jaeger over the internal compose network. Dev tooling that previously sent OTLP directly to `localhost:4317` against Jaeger must either be retargeted at the Collector (no other change required — the host ports are the same) or pin its Jaeger endpoint to the in-network `jaeger:4317`. See [`docs/observability.md` § 11.1](observability.md). |
| Python OTLP exporter transport changed (gRPC → HTTP) | `opentelemetry-exporter-otlp-proto-grpc` is replaced with `opentelemetry-exporter-otlp-proto-http`. Collector configs pointing the Python exporter at `:4317` must switch to `:4318`. The Go exporter was already HTTP; both runtimes now use the same endpoint. |
| Go package rename `internal/telemetry` → `internal/observability` | Internal only; forks importing it directly must update import paths. |
| Go zap reserved correlation-ID keys renamed | `runID` / `executionID` → `execution_id`; `agentID` → `agent_id`; `workflowID` → `workflow_id`; `stepID` → `step_id`. The encoder's `legacyRenames` map is a defence-in-depth backstop; downstream consumers (log shippers, `jq` queries, dashboards) filtering on the old keys must switch to the new ones. Site-local attributes (`inputTokens`, `wallTimeMs`, `estimatedCost`, …) remain camelCase on the wire pending a future PR. |
| Go log lines carry the RFC 0018 required-field group | `schema_version: "1"`, `service.kind: "orchestrator"`, `service.instance: <hostname>`, and a `source: {file, line, function}` object from `zap.AddCaller`. Forks constructing their own zap logger should switch to [`internal/observability/zapenc.NewEncoder`](../internal/observability/zapenc/encoder.go) for schema-conformant output. |
| `PERSATRIX_LOG_FORMAT=pretty` | Selects a human-readable console encoder for local debugging. Default (unset or `json`) emits the RFC 0018 wire format. Pretty mode is **not** consumed by the `persatrix logs` endpoint — leave unset in production. |
| `PERSATRIX_SERVICE_INSTANCE` | Overrides the orchestrator's `service.instance` log field (defaults to `os.Hostname()`). Useful in containerised deployments where the hostname is an ephemeral pod ID. |
| `PERSATRIX_TRACE_TOOL_PAYLOADS` | Controls `agent.tool.execute` span detail. Defaults to `none` (only `tool.name`). `metadata` adds `tool.arguments.<arg>.type`; `full` emits redacted argument values via the same `Redactor` Protocol used for log redaction. Use `full` only with a configured redactor — the default `NoopRedactor` echoes values verbatim and may capture secrets. |

## 6. Known Gaps to Document in Release Notes

These items remain intentionally incomplete and should be described as deferred scope, not regressions.

### v0.2.3-scope gaps

| Area | Description | Deferred to |
|------|-------------|-------------|
| `persatrix logs` restart durability | Disk-store warm-load is covered by `TestWarmLoadAfterReopen` in [`internal/observability/logbuffer/buffer_test.go`](../internal/observability/logbuffer/buffer_test.go) but production never calls `Buffer.Seal`, so a restart mid-run leaves no queryable history for runs that were in flight. MT-LOGS-001 Step 4 is footnoted accordingly. | RFC 0018 PR 7 follow-up |
| Cross-process trace stitching outside `ExecuteTask` | The executor's `otelgrpc` client handler stitches orchestrator and agent spans into a single trace on the workflow dispatch path; other gRPC paths whose caller is not routed through `otelgrpc.NewClientHandler()` may still land in a separate root trace. Exemplar- and workflow-tagged lookups remain correct in either topology. | Future RFC (per-path instrumentation audit) |
| No per-agent operator dashboard / alerting rules | The reference compose stack is for local debugging only. Production operators fork [`config/observability/otel-collector.yaml`](../config/observability/otel-collector.yaml) and build dashboards against their own Prometheus + Jaeger + Loki install. | Future operational guidance doc (not an RFC) |
| Site-local attribute namespacing | Go zap log fields like `inputTokens`, `outputTokens`, `retryCount`, `wallTimeMs`, `estimatedCost`, `serviceName` remain camelCase on the wire pending a future PR that nests them under the RFC 0018 schema's `attributes` slot. The reserved correlation IDs are already renamed. | Future v0.2.x follow-up |

### Carried forward from v0.2.2

| Area | Description | Deferred to |
|------|-------------|-------------|
| Operator-facing knobs for `_MEMORY_BUDGET_TOKENS` | Module-level constant; not a per-agent or per-event config field | Future RFC if demand exists |
| Hybrid char-cap layer manual coverage | Exercised by unit tests but no explicit manual runbook for adversarially-large items | Future MT iteration |

### Carried forward from v0.2.1

| Area | Description | Deferred to |
|------|-------------|-------------|
| Multi-user support | Single `UserParticipant` per session; no concurrent user isolation | v0.3.0 (RFC 0011) |
| Authentication | Sessions are local, caller-supplied `user_id`; no auth tokens | v0.3.0 (RFC 0009) |
| Streaming responses | Synchronous request-response only; no SSE or WebSocket streaming on the chat path | Future RFC |
| Agent-initiated messages | No notification infrastructure for outbound agent messages | Future RFC |
| Channel routing for user messages | Chat bypasses channel infrastructure; channels not yet user-ready | v0.3.0 (RFC 0011) |
| Rate limiting for chat | No per-user rate limit on the chat endpoint | v0.3.0 (RFC 0009) |
| Cost tracking for chat | `POST /api/v1/agents/{id}/chat` calls are not counted in `/api/v1/cost/summary` | v0.3.0 follow-up |
| Budget-exceed abort (`MT-COST-002`) | Live workflow abort on budget exhaustion | v0.2.x follow-up |
