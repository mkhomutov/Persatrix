## Overview

RFC 0004 defines ~1,130 LOC across 5 phases (excluding generated proto output). The project's PR size limit is <500 lines of meaningful change. This plan splits the work into **7 PRs**: Phase 1 is one PR, Phase 2 is one PR, Phase 3 is one PR, Phase 4 is pre-split into 4a (LLM client + base handle loop + `TaskInputConfig`) and 4b (three agent implementations), and Phase 5 is pre-split into 5a (gRPC server + agent loading) and 5b (self-registration + integration tests).

Each PR is independently mergeable and leaves the codebase in a passing-tests, lint-clean state.

> **Estimate calibration**: RFC 0001 PRs consistently exceeded estimates by 73–138%. Sizes in this plan are calibrated to ~1.7× of naive estimates.

**Prerequisite**: RFC 0001–0003 PRs merged (state, registry, planner, REST API, scheduler, executor). The Go orchestrator's `GRPCExecutor` (RFC 0003) dispatches `TaskRequest` messages to agent addresses — this RFC implements the Python server that receives them.

**Recommended merge order:** **PR 1 ‖ PR 2** (parallel) → **PR 3** → **PR 4a** → **PR 4b** → **PR 5a** → **PR 5b**. PR numbering implies execution order except where noted parallel.

### PR 2: `feature/v01-permission-sandbox` — Permission Gate + Path Validator

**Depends on**: Nothing (independent of proto stubs)
**Branch**: `feature/v01-permission-sandbox`
**Estimated size**: ~350–500 lines (implementation + tests)

#### Scope

| File | Change |
|------|--------|
| `agents/tools/permissions.py` | Replace stubs — `PermissionGate` class with `check()`, `is_command_allowed()`, `is_domain_allowed()` |
| `agents/tools/sandbox.py` | Replace stubs — `PathValidator` class with `validate()`. Preserve `ResourceLimiter` and `OutputSizeLimiter` TODO stubs (v0.2, PR-review m8) |
| `tests/unit/python/test_permissions.py` | New — permission gate tests |
| `tests/unit/python/test_sandbox.py` | New — path validator tests |

#### Key implementation details

- **`PermissionGate`**: deny-by-default. Initialized with agent's `permissions` config block from `agents.yaml`.
- `check(permission: str) -> bool`: split on `:` into category/action, check category config exists, check action matches.
- `is_command_allowed(args: list[str]) -> bool`: progressive prefix matching — `"git diff"` in allowlist matches `["git", "diff", "f.py"]` but not `["git", "push"]` (review-fix B1).
- `is_domain_allowed(domain: str) -> bool`: allow-overrides-deny semantics (PR-review B3) — `deny: ["*"]` + `allow: ["api.anthropic.com"]` works correctly.
- **`PathValidator`**: `Path.resolve()` canonicalizes (resolves `..`, symlinks), then matches against allow/deny glob patterns. Deny list takes unconditional precedence (different from network semantics — see RFC 0004 design section for rationale).
- Preserve existing `ResourceLimiter` and `OutputSizeLimiter` TODO stubs in `sandbox.py` — only `PathValidator` is implemented in this RFC.

#### Tests

**Permission Gate:**
- Granted permission → `True`.
- Denied permission (default, no config) → `False`.
- Missing permission category → `False` (deny by default, deep-review d7).
- Command allowlist: allowed → `True`; unlisted → `False`.
- Multi-word command: `"git diff"` matches `["git", "diff", "f.py"]`; `"git push"` does not match `["git diff"]`.
- Domain allowlist: allowed → `True`; wildcard deny + specific allow → `True`; deny all → `False`.
- Allow-overrides-deny (network): domain in both lists → allowed (PR-review B3).
- Deny-wins (paths): path in both lists → denied.

**Path Validator:**
- Valid read path within glob → resolved `Path` returned.
- Path traversal (`../../etc/passwd`) → `PermissionError`.
- Symlink resolution: symlink outside workspace → `PermissionError`.
- Deny list precedence: path in both allow and deny → `PermissionError`.
- Write to read-only path → `PermissionError`.

### PR 3: `feature/v01-builtin-tools` — Built-in Tool Implementations

**Depends on**: PR 2 merged (permission gate, path validator)
**Branch**: `feature/v01-builtin-tools`
**Estimated size**: ~400–550 lines (implementation + tests)

#### Scope

| File | Change |
|------|--------|
| `agents/tools/builtin.py` | Replace stubs — `file_read`, `file_write`, `shell_exec`, `http_request` with permission enforcement and sandboxing |
| `tests/unit/python/test_tools.py` | Extended — tool unit tests (existing file may have fixtures from tool registry tests) |

#### Key implementation details

- `MAX_OUTPUT_BYTES = 102_400` (100 KB) module-level constant. Caps `file_read`, `shell_exec` stdout/stderr, and `http_request` response to prevent gRPC 4 MB message size blowout and LLM context waste.
- **`file_read`**: `PathValidator.validate(path, mode="read")` → `Path.read_text(encoding="utf-8")` → truncate if > `MAX_OUTPUT_BYTES`.
- **`file_write`**: `PathValidator.validate(path, mode="write")` → `mkdir(parents=True, exist_ok=True)` → `Path.write_text(content, encoding="utf-8")`.
- **`shell_exec`**: `shlex.split(command)` → `PermissionGate.is_command_allowed(args)` → `asyncio.create_subprocess_exec(*args, cwd=workspace_root)` → `asyncio.wait_for(proc.communicate(), timeout)`. On timeout: `proc.terminate()` → 5s grace → `proc.kill()` → `proc.wait()` to reap zombie (PR-review M6). No `shell=True`.
- **`http_request`**: scheme validation (`http`/`https` only, review-fix S1) → hostname extraction → `PermissionGate.is_domain_allowed(hostname)` → `aiohttp` request via shared session → truncate response.
- `workspace_root` set from a module-level variable initialized by the server at startup (from `--workspace` CLI flag).
- Tool functions receive `PermissionGate` and `PathValidator` instances via module-level initialization (set by server startup), not as parameters — matching the existing `@tool` decorator pattern which auto-generates schemas from function signatures.

#### Tests

- **`file_read`**: read existing file → content; read denied path → `ToolResult(success=False)`; large file → truncated.
- **`file_write`**: write file → on disk; write denied path → error; parent dir creation.
- **`shell_exec`**: allowed command (`echo test`) → stdout; denied command → blocked; timeout → killed; non-zero exit → `success=False`.
- **`http_request`**: mock HTTP (aiohttp test server or `unittest.mock`) → response; denied domain → blocked; malformed URL → error; `file://` scheme → error (review-fix S1).
- **Output truncation**: verify `MAX_OUTPUT_BYTES` cap for each tool.
- All tests use `autouse` fixture with `clear_registry()` per project convention.

#### PR checklist

- [ ] `pytest tests/unit/python/test_tools.py -v` passes
- [ ] Coverage ≥ 80% for `agents/tools/builtin.py`
- [ ] `ruff check agents/tools/builtin.py` clean
- [ ] No `shell=True` in subprocess calls
- [ ] `shlex.split` used for command parsing
- [ ] `MAX_OUTPUT_BYTES` enforced on all output paths
- [ ] All tools use `PermissionGate.check()` before execution

### PR 4a: `feature/v01-llm-client-base` — LLM Client + TaskInputConfig + Base Handle Loop

**Depends on**: PR 3 merged (built-in tools for tool dispatch)
**Branch**: `feature/v01-llm-client-base`
**Estimated size**: ~300–450 lines (implementation + tests)

> **Note**: Phase 4 is pre-split into 4a/4b. Phase 4 naive estimate of ~700 LOC × 1.7 = ~1,190 LOC exceeds the 500-line limit. The natural split point is the LLM client + shared handle pattern (4a) vs. agent-specific system prompts (4b).

#### Scope

| File | Change |
|------|--------|
| `agents/llm_client.py` | New — `LLMClient` wrapper around Anthropic SDK |
| `agents/base.py` | Add `TaskInputConfig` dataclass, add `config` field to `TaskInput` (review-fix D1), add `_execute_tools()` helper method, add `_build_tool_definitions()`, add `_extract_text()` helper |
| `tests/unit/python/test_llm_client.py` | New — LLM client tests with mock |
| `tests/unit/python/test_base_handle.py` | New — base handle loop tests |

#### Key implementation details

- **`LLMClient`**: thin wrapper around `anthropic.AsyncAnthropic`. `create_message(**kwargs)` delegates to `self._client.messages.create()`. API key from `ANTHROPIC_API_KEY` env var (SDK default). Injected into agents for testability.
- **`TaskInputConfig`**: `max_llm_calls: int = 0`, `max_tokens: int = 0`, `allowed_tools: list[str] = field(default_factory=list)` (PR-review B2: carried from proto, enforcement deferred to v0.2).
- **`TaskInput.config`**: `config: TaskInputConfig = field(default_factory=TaskInputConfig)` — default so existing callers work.
- **`_execute_tools(content) -> list[dict]`**: sequential tool dispatch. Parses `ToolUseBlock` objects, dispatches through tool registry, catches `PermissionError` and generic `Exception` (PR-review M2), returns Anthropic-format tool results.
- **`handle()` loop on `BaseAgent`**: not directly on BaseAgent (it's ABC), but a shared `_run_llm_loop()` method that subclasses call. Implements the core loop: LLM call → check `stop_reason` (`end_turn` → COMPLETED, `max_tokens` → FAILED, `tool_use` → dispatch tools and continue) → max iterations → FAILED.
- Per-task config overrides take precedence over YAML config: `task.config.max_llm_calls or self.config.get("max_llm_calls", 10)`.

#### Tests

- **LLM client**: mock `AsyncAnthropic` → `create_message` delegates correctly; missing API key behavior.
- **Tool dispatch**: mock LLM returns tool call → tool executed → result formatted correctly; unknown tool → error result; permission denied → error result; generic exception → error result (PR-review M2).
- **Handle loop — end_turn**: mock returns text → `TaskOutput(status=COMPLETED)`.
- **Handle loop — tool_use**: mock returns tool call then text → tools dispatched, final result returned.
- **Handle loop — max_tokens**: mock returns `stop_reason="max_tokens"` → `TaskOutput(status=FAILED)` (review-fix B2).
- **Handle loop — max iterations**: mock always returns tool calls → `FAILED` after limit.
- **Per-task config override**: `TaskInputConfig(max_llm_calls=2)` → loop respects override (review-fix D1).
- **Token counting**: verify `metadata["tokens_used"]` accumulates from mock responses.

### PR 5a: `feature/v01-grpc-server` — AgentServiceServicer + Agent Loading

**Branch**: `feature/v01-grpc-server`
**Estimated size**: ~350–500 lines (implementation + tests)

> **Note**: Phase 5 naive estimate of ~600 LOC × 1.7 = ~1,020 LOC exceeds the 500-line limit. Split at the server/registration boundary: 5a implements the gRPC servicer and agent loading, 5b adds self-registration and integration tests.

#### Scope

| `tests/unit/python/test_server.py` | New — server unit tests with in-process gRPC client |

#### Key implementation details

- **`AgentServiceServicer`**: implements `ExecuteTask` (proto → `TaskInput` → `agent.handle()` → `TaskResponse`), `HealthCheck` (delegate to `agent.health_check()`, PR-review B4), `ExecuteTaskStream` (returns `UNIMPLEMENTED`).
- `ExecuteTask` catches all exceptions → `FAILED` `TaskResponse` (never gRPC application error). Agents only return `COMPLETED` or `FAILED` in response status (PR-review m1).
- `asyncio.wait_for(agent.handle(), timeout=request.config.timeout_seconds or None)` for per-task timeout.
- Metadata values: `json.dumps()` for non-str values (review-fix P2).
- **`load_agent()`**: YAML parsing with operator-friendly `SystemExit` errors (review-fix D3). Capability-based type resolution with `# TODO(v0.2): add explicit 'type' field` comment.
- **Graceful shutdown**: `server.stop(grace=30)` → `agent.shutdown()` → exit. 30s matches default `shell_exec` timeout. Configurable via `--shutdown-grace`.
- **CLI**: `argparse` with `--agent` (required), `--port` (default 50051), `--host` (default `127.0.0.1`), `--config` (default `config/agents.yaml`), `--workspace` (default `/workspace`), `--orchestrator-url` (default `http://127.0.0.1:8080`), `--log-level` (default `INFO`), `--shutdown-grace` (default 30).
- Signal handling: `SIGTERM` / `SIGINT` with `sys.platform != "win32"` guard per project convention.
- `grpc.aio.server()` with insecure port. `# TODO(security): enable TLS for production gRPC`.
- Single-agent-per-process: `main()` loads one agent into single-entry dict. Servicer accepts `dict[str, BaseAgent]` for v0.2 multi-agent hosting (deep-review D2).

#### Tests

- **`ExecuteTask` success**: in-process gRPC client → `COMPLETED` response with result and metadata.
- **`ExecuteTask` agent not found**: unknown agent ID → `NOT_FOUND` gRPC status.
- **`ExecuteTask` timeout**: blocking mock agent → `DEADLINE_EXCEEDED` response.
- **`ExecuteTask` agent exception**: agent raises → `FAILED` response (not gRPC error).
- **`HealthCheck`**: loaded agent → `SERVING`; agent `health_check()` returns `False` → `NOT_SERVING`; no specific agent → healthy if any loaded.

- **`load_agent` valid**: correct YAML → correct agent type instantiated.
- **`load_agent` missing ID**: unknown agent ID → `SystemExit`.
- **`load_agent` bad YAML**: malformed → `SystemExit`.
- **`load_agent` missing file**: → `SystemExit`.
- **`load_agent` type resolution**: planner (planning capability) → `PlannerAgent`; code-writer (code_generation) → `CoderAgent`; code-reviewer (code_review, no code_generation) → `ReviewerAgent`.
- **Graceful shutdown**: signal → server stops cleanly, `agent.shutdown()` called.
