**Branch**: `feature/v033-release-prep-version-bump`

Scope:

- Bump `agents/pyproject.toml`, `agents/observability/{metrics,tracing}.py` (`_DEFAULT_SERVICE_VERSION`), `cli/Cargo.toml` to `0.3.3` via `scripts/bump_version.py`; then `cd cli && cargo update --workspace` to regenerate `cli/Cargo.lock`. Run `make all` at the new version.

PR ranges per [§RFC PR roll-up](#rfc-pr-roll-up). Preserve `[0.3.2]` and prior verbatim; if `git-cliff` would overwrite curated content, generate to a temp file and merge manually (same pattern as v0.3.2 / v0.3.1).
- Reconcile the **`MemoryFacade` alias-removal** decision from [§Known follow-up issues §2](#known-follow-up-issues); record the chosen path in the PR description.
- **Upgrade Notes** must call out, at minimum:
  - **[Behaviour change — idle is truly idle]** The persona autonomy loop is now event-driven ([RFC 0024](rfcs/0024-event-driven-scheduling.md) Phases 1–4). A persona with `autonomy.timers: []` and no inbound traffic parks on `queue.get()` and pays nothing — no SQLite recall, no `_inject_memory_context`, no provider activity, no wallet lease. The polling-loop cost-leak class is closed structurally, guarded by `cost-regression-gate`.
  - **[Behaviour change — channel dispatch]** `ReceiveChannelMessage` now enqueues `InboundEventWake(event)` fire-and-forget via `event_loop.enqueue` (not `scheduler.wake()`) and returns `TaskAck` immediately. Chat, sub-agent, and workflow-task paths are unchanged — they keep their synchronous-return contract via `SyncDispatchHandle`.
  - **New `autonomy.timers` config block** (in `agents.yaml` / [`schemas/agent.schema.json`](../schemas/agent.schema.json)): per-agent timer list (`id`, `interval_seconds` ≥ `1.0`, `kind`, optional `jitter_max_seconds`). `tick_interval_seconds` **continues to work** — synthesised as one `ScheduledWake(timer_id="legacy_tick")`; if both set, `timers` wins (INFO log). Deprecation **warning** is Phase 5 (v0.4.0); removal Phase 6 (v0.5+). Absent block → `timers: []`.
  - **New per-agent SQLite `scheduled_wakes` cache** — derived from `agents.yaml` (source of truth), rebuilt on startup; restores `next_fire_at_ms` so a persona restarted mid-jitter-window resumes its schedule. Orphan rows deleted on next startup. No operator action.
  - **New `autonomy.salience_threshold` (default `0.95`) + `autonomy.salience_rate_max_per_sec` (default `10`)** — salience-triggered wakes from the memory-write path. **Ships disabled by default** (threshold strictly above stock scoring). Calibration is a data-gated follow-up ([RFC 0024 §OQ §2](rfcs/0024-event-driven-scheduling.md#open-questions)). The rate-limit is a DoS guard, not a calibration knob.
  - **New `agent.wake.{inbound,scheduled,salience,dropped}` metric counters** carrying `wake.kind` (plus `timer_id` on scheduled, `tier` + `suppressed_reason` on salience). `wake.kind` is an **OTEL/metric dimension only** — *not* a new `LeaseRequest` proto field; [proto/wallet.proto](../proto/wallet.proto)'s `Cause cause` is unchanged, so v0.3.2 cost-attribution dashboards keep working. This refines the [v0.3.3-plan acceptance row](v0.3.3-plan.md#acceptance-for-v033) that anticipated a lease-request attribute (`trace_id` already links the lease to the wake span). See [observability.md §10.5](observability.md).
  - **RFC 0017 §F empty-context TICK guard is now structurally unreachable but stays in place** — documented as vestigial via an [`action_loop.py`](../agents/persona_runtime/action_loop.py) cross-link naming Phase 5/6 as the deletion path. No behaviour change.

Acceptance:

- `make all` builds at `0.3.3`.
- `CHANGELOG.md` has a curated `[0.3.3]` section with the Upgrade Notes above.
- All prior version sections untouched (`git diff` below the new section shows zero diff).
- The `MemoryFacade` alias-removal decision is recorded in the PR description.
