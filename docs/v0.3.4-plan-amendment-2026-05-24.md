# v0.3.4 plan amendment — 2026-05-24 — Provider-parity hardening

> Status: amendment to [v0.3.4-plan.md](v0.3.4-plan.md). Driver: a 2026-05-24
> review of the *"Any Model, Any Provider"* release against its own codename.
> RFC: [0033 — Provider-Agnostic Model Alias Layer](rfcs/0033-model-alias-layer.md).

## Context

The plan as first opened delivers the *"Any Model, Any Provider"* promise at
the **config/code** layer: the alias resolver plus the Sonnet 4 → 4.6
migration. A review on 2026-05-24 found three further layers where the
codename does **not** yet hold — onboarding, OpenAI-as-peer, and a tested
swap — plus **one genuine safety regression the theme itself makes
reachable**. None of these change RFC 0033's mechanics; they widen the
release's acceptance and risk surface so the shipped product matches its
name. This amendment is the provenance record; the deltas fold into the
main plan's canonical sections (linked per item).

## Acceptance additions

Append to [§Acceptance for v0.3.4](v0.3.4-plan.md#acceptance-for-v034), under a **Provider parity** group:

- **Cost enforcement never silently disables.** A resolved model/alias with no pricing entry produces a loud startup warning and fails closed for non-local providers, rather than a $0 estimate — so the RFC 0023 lease gate stays real for every provider, not only priced Claude models. The silent-$0 path in [`internal/cost/config.go`](../internal/cost/config.go) is closed for the alias surface.
- **OpenAI ships as a first-class peer**: the `models.aliases` block carries at least one OpenAI alias and OpenAI pricing rows; the provider guide treats Anthropic / OpenAI / Ollama / offline as equals rather than Anthropic + alternatives.
- **The one-line swap is tested**: a manual test flips the `quality` alias's `provider` (Anthropic → OpenAI or → Ollama), runs the same agent unchanged, and confirms correct, non-zero (or documented-$0) cost attribution — validating the release's headline claim directly.
- **First-run is provider-neutral**: nothing in the documented quick-start, [`.env.example`](../.env.example), or the compose startup guard privileges one vendor as *the* required path; `make demo-openai` exists alongside `demo-offline` / `demo-ollama`.

## Phase 2 additions

Append to [§Phase 2 Acceptance](v0.3.4-plan.md#phase-2--implement-rfc-0033-phases-12):

- **Missing-price guard** (item 1): a resolved alias with no price warns loudly at startup and fails closed for non-local providers — never a silent $0 lease estimate. The guard is scoped to the alias surface, leaving the deliberately-preserved raw-ID fall-through (§Deferred) untouched. Unit coverage asserts the guard fires on an unpriced alias, and that a local ($0-by-design) alias is distinguishable from an unpriced one.
- **OpenAI alias + pricing land in the same migration** (item 2): `models.aliases` carries an OpenAI entry and the alias-derived `cost.pricing` ([§F](rfcs/0033-model-alias-layer.md#f-pricing-keyed-by-alias)) carries OpenAI rows, so the Phase 4 swap test has a priced target.
- **Example network allowlist neutralized** (item 5): the Anthropic-only `network.allow` in [`config/agents.yaml`](../config/agents.yaml) is generalized (or dropped) in the migration sweep so example configs no longer read as single-vendor.
- **Local-model pricing decision recorded** (item 6): offline / Ollama aliases either carry an explicit *simulation* price (so the wallet-cap demo still trips) or are documented as $0-real with the cap demo pinned to a priced alias.

## Phase 4 additions

In [§Phase 4](v0.3.4-plan.md#phase-4--v034-release-prep-execution), widen the release-prep PR scope and acceptance:

- PR 1 title → *MT execution report (alias routing + provider-swap + offline + Ollama)*.
- PR 2 title → *README + ROADMAP + model-alias/provider guide + provider-neutral onboarding (`.env` / compose / `demo-openai`) + release checklist*.
- **Provider-neutral onboarding verified** (item 4): [`.env.example`](../.env.example) presents providers as "pick one" (no Required/Optional split that privileges a vendor); the [`docker-compose.yaml`](../docker-compose.yaml) startup guard accepts any configured provider and names them all in its error; the README quick-start and [`v0.3.0-demo.md`](guides/v0.3.0-demo.md) opener use a vendor-neutral "an LLM provider" framing; `make demo-openai` runs end-to-end alongside `demo-offline` / `demo-ollama`.
- **Provider-swap MT `Pass`** (PR 1): the one-line alias-provider swap runs the same agent on a second provider with correct cost attribution.

## Risk additions

Append to [§Risk and mitigations](v0.3.4-plan.md#risk-and-mitigations):

| Risk | Mitigation |
|------|------------|
| **Missing-price → silent budget no-op.** "Any Model" invites unpriced models; `EstimateCost` returns $0 for them, disabling the RFC 0023 lease gate for that agent with no error. | A missing-price guard becomes a plan-level gate (warn loudly + fail closed for non-local providers); Phase 2 closes the silent-$0 path for the alias surface and unit-tests it. Independent of the alias mechanics, so it can land as a small standalone fix inside this release. |
| The *Any Provider* codename ships while first-run still funnels to Anthropic (env "Required", compose guard, README opener) — an internal contradiction reviewers will flag. | Phase 4 PR 2 folds in a provider-neutral onboarding pass (env "pick one", any-provider compose guard, neutral quick-start, `make demo-openai`); Acceptance gates it. |
| OpenAI stays invisible in an "Any Provider" release (acceptance only exercised Anthropic / offline / Ollama; alias-derived pricing means no OpenAI price ships either). | Phase 2 ships an OpenAI alias + pricing rows; Phase 4 PR 1 exercises a swap onto it; the provider guide treats it as a peer. |
| A genuinely-$0 local alias makes the simulated wallet never trip, contradicting the README's "agent pauses itself at the cap." | Phase 2 records the local-pricing decision (simulation price vs documented $0); the wallet-cap demo is pinned to a priced alias if local stays $0. |

## Deferred — named, not scoped into v0.3.4

- A CLI `--model` / `--provider` override is the natural surface expression of aliasing, but the surface users touch carries no provider affordance today. Re-home to v0.3.5 rather than inflate this release.
- Turning the `_infer_provider` unknown-model fall-through (logs a warning, defaults to OpenAI, then fails downstream on a missing key) into a clear up-front error. Small enough to ride a Phase 1 PR if convenient; not a gate.
- The raw-ID fall-through stays a deliberate back-compat half-step, closed by RFC 0033 Phase 3 on observed traffic — consistent with the pre-1.0 *prefer-evolvable* stance, since the alias layer is itself the clean refactor.
