# Persatrix — Issue Tracker

Internal follow-up findings captured as Markdown files. These complement GitHub
issues: internal, AI-accessible, co-located with RFCs and PR plans.

> **Lifecycle**: Open → (in_progress) → resolved (delete the file).
> Deleted files remain in git history: `git log -- docs/issues/ISSUE-NNN-*.md`.

---

## Conventions

| Rule | Detail |
|------|--------|
| Naming | `ISSUE-{NNN}-{slug}.md` — zero-padded three-digit number, kebab slug |
| Status values | `open`, `in_progress`, `resolved` |
| Severity values | `low`, `medium`, `high` |
| Area values | match `internal/` package or agent subsystem (e.g. `cost`, `persona`, `memory`, `grpc`) |
| Cross-references | Add `> See [ISSUE-NNN](../issues/ISSUE-NNN-slug.md)` inline anywhere the issue is relevant |
| Discovery | `grep -r "ISSUE-" .` or `make issues` |
| Closing | Delete the file; reference the closing commit/PR in the commit message |

Issues whose fix is trivially contained within an in-progress PR do **not** need
a file — record them directly in the PR plan's "Review findings" table.
