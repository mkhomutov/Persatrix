### 3.1 Required Upgrade Notes

| Notable change | Detail |
|----------------|--------|
| **[New opt-in capability]** autonomous channels | Arming requires `autonomous.enabled` + a **positive `interaction_budget_tokens` cap** + an `escalation_chair_id` distinct from the convener, **group-only**; a standing schedule additionally requires an aggregate bound (`max_convenings` and/or `standing_budget_tokens`). **Existing channels are unchanged** — every autonomous mechanism is `autonomous.enabled`-scoped. |
| **[Upgrade ordering — autonomous adopters]** upgrade both together | The convene/synthesis dispatches carry synthetic `orchestrator:*` sender ids that **pre-v0.3.11 agents reject** at inbound validation — arming a channel needs orchestrator **and** agents at v0.3.11. Ordinary channels tolerate skew in either direction (the four new wire fields are additive). |
| **[Wire — additive]** four `ChannelMessageEvent` fields | `convene = 27`, `close_notification_redelivery = 28`, `close_notification_close_trigger = 29`, `synthesis_turn = 30` — a pre-v0.3.11 party leaves/ignores them and keeps prior behaviour. |
| **[Scope limit]** aggregate bounds are per-process | The standing convening count and spend total reset on an orchestrator restart (no new store migration by design); a restart resumes a standing channel that had stopped at its bound. Documented §E-hardening residual. |
| **[Providers]** optional extras | `pip install 'persatrix-agents[providers]'` (or `[gemini]`/`[watsonx]`) pulls the two new SDKs; base installs carry no new runtime dependency. watsonx **fails closed at startup** without `project_id`/`space_id`. |
| **No store migrates this release** | Channel store stays **v10**; the persona-memory schema is untouched. |
