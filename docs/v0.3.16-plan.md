# v0.3.16 Plan — The persona knows who is listening (audience as a gate input, and an operator who can read why)

**Status**: 🔄 Phase 1 — implementation PRs (D1, D2, A1, A2, E1, B1, B2 and K1 merged; D3… cut 2026-09-12; C1 open; C2 next)

**Created**: 2026-09-08
**Branch prefix**: `feature/v0316-`
**Target**: `main`
**Merge strategy**: Squash merge per [BRANCHING.md](BRANCHING.md)
**Codename**: *The persona knows who is listening*

**Goal**: v0.3.15 made derived memory name the person it came from. The gate that decides whether that memory may be *spoken* still does not know who is in the room: the RFC 0037 §D egress gate ranks an entry's `protection_level` against the acting channel's classification alone, so a fact Alice taught the persona in a DM is admissible in any equally-classified room — including one Bob is in ([ISSUE-0132](issues/ISSUE-0132-memory-egress-gate-blind-to-room-audience.md)). Two operator blind spots sit beside it: the `relationship` tier charges the RFC 0017 budget without recording an admission, so the provenance switch is silent on the one tier that answers "does the persona know who I am?" ([ISSUE-0122](issues/ISSUE-0122-relationship-tier-emits-no-provenance.md)), and the RFC 0051 verbatim `reason_note` has no egress at all ([ISSUE-0108](issues/ISSUE-0108-reasoning-reason-note-no-operator-egress.md)). This release adds audience as an AND-condition on the §D decision — shadow-first, flipped only on a measured verdict — makes both decisions readable, and starts the org train with an automated regression bar ([RFC 0044](rfcs/0044-eval-set-golden-traces.md) Phase 2, paired with [ISSUE-0142](issues/ISSUE-0142-ci-never-runs-golangci-lint.md)). Ahead of all of it, the debt sweep the [release-cycle rule](methodology/release-cycle.md#the-debt-sweep) requires ([ISSUE-0143](issues/ISSUE-0143-debt-sweep-26-files-at-size-cap.md)): two of the twenty-six at-cap files are the ones this release must edit.

Scope was ratified by the [Amendment 2026-08-19](v0.3.x-sequencing.md#amendment-2026-08-19--v0315--v0316-attribution-and-audience-before-the-v040-train), whose next-steps item 4 this executes. No issue-owned PR plan exists for the audience gate — ISSUE-0132 is issue-shaped, not RFC-shaped — so this cycle writes its own: the [v0.3.16 PR plan](v0.3.16-pr-plan.md) carries the per-PR breakdown, the [scope locks](v0.3.16-scope-locks.md) carry every design decision, and this doc is the thin orchestration overlay between them — sequencing, acceptance, the live arc, hygiene.

## Acceptance for v0.3.16

The release ships when **all** hold:

- **The gate records audience, by cause** — for every channel-anchored turn the §D decision record carries an audience verdict per entry (*admit*, *withhold-disjoint*, *withhold-unknown-fetch-failed*, *withhold-unknown-no-provenance*), visible to the §G watch and the shadow log, with `public` entries and NULL-provenance rows never acquiring an audience. The regression that is the gate: one DM-taught `internal` fact; an acting room whose member set adds anyone not in the DM — Bob, or a peer persona — → *withhold-disjoint*; a room whose every member was in the DM → *admit*; a DM with Bob alone → *withhold-disjoint*.
- **The verdict is rendered and its outcome stated** — `shadow_measurement` reports the four lock-1 criteria over the new audience seed, the admit/withhold delta among them — the number the flip PR argues against a stated threshold. Green → the flip PR lands before release-prep PR 0 and **ISSUE-0132 closes**. Red or absent → the release ships in shadow, the release notes carry the measured delta as a Known Gap, and ISSUE-0132 stays open with a dated note. Either way the claim in the notes matches the shipped default.
- **ISSUE-0122 and ISSUE-0108 are closed** — `PERSATRIX_MEMORY_PROVENANCE=1` emits `tier_admitted` for `relationship` with the tokens actually charged; the verbatim `reason_note` reaches the agent DEBUG log on the suppression path and **nowhere else** — the no-leak test extends to say so. Both MT notes are flipped in the same PRs.
- **No store migration lands** — zero across both stores. The release is drop-in against v0.3.15; the checklist says so explicitly rather than inheriting v0.3.15's forward-only caution.
- **Byte-identical where it must be** — in shadow, every prompt is byte-identical to v0.3.15 across both auth modes; the five existing goldens replay unchanged before and after the flip. Under `auth.mode: disabled` the audience axis is *allowed* to differ — that is the whole point of Leg 5's second run.
- **The live proof exists** — MT-PERSONA-CONFIDENTIALITY-001, all five legs, once, on a live provider: Legs 1–4 as the regression baseline, Leg 5 self-contained (its own DM teach and close) under both auth modes with the gate's per-entry audience record quoted verbatim, the live fetch-failed count reported, and the vacuity rule honoured (Alice asks; nobody else's turn counts).
- **The debt sweep moved** — the two path files are under cap before A1 and E1 open; the Phase 4 follow-up re-reads the at-cap count and records it, and if a sweep ran and the number did not move, files the cap itself as the next question.
- **The CI pair is green or cut** — golangci-lint (pinned, configured) and `make eval-replay` run as jobs the live branch protection on `main` **requires** — the owner's action, requested in each PR body — with `docs/methodology/branch-protection.json` and the enforcement matrix updated to match; or Workstream C is ✂️ with the amendment's clause cited and the two issues re-noted.
- **The coherence trades are stated, not discovered** — release notes carry: audience narrows RFC 0049's "taught in a DM, known in the standup" headline to *the standup whose every member was in the DM* — which, in the default three-persona rooms, is no standup at all (only if flipped; otherwise the measured delta); the `reason_note` is now an egress surface at DEBUG, so operators who ship agent logs off-host inherit a confidentiality consideration RFC 0051 §E must state; and the `relationship` tier's admission line changes what a provenance transcript contains.
- **The full gate sweep is green live on host** — Go `-race`, `cargo test`, the Python suites (including the separate `mypy tests/` leg), Vitest, linters (now the pinned golangci-lint too), `make validate`, eval-replay, licences, `make notices` (no delta expected: golangci-lint is a binary, not a module).

## Risk and mitigations

| Risk | Mitigation |
|------|------------|
| The shadow verdict goes green on data that never exercised a disjoint audience, and the flip ships on a vacuous measurement. | The audience seed is *built* around the disjoint case, and Leg 5's live log reports the fetch-failed count — a roster that was never fetched shows up as a number, not as silence. |
| The verdict is green while the feature dies — in shadow nothing moves, so defect-only criteria cannot see that every default room withholds every DM-taught fact. | Lock 1's fourth criterion: the admit/withhold delta is reported per cause and room shape, and A3 must argue it against a stated threshold; the persona-peer consequence is written into the release-note trade now. |
| Per-turn source-room fetches reintroduce the N+1 the roster module was written to avoid. | Bounded by the tier recall limits and the per-turn cache; an A2 test pins fetch count equals distinct-room count. |
| The flip narrows RFC 0049's cross-room headline further than users expect. | Lock 1's default admits *unknown*; the release note states the narrowing in one sentence; `shadow` stays the documented rollback lever, as it did for `memory.facts.cross_room`. |
| Leg 5 passes for the wrong reason under `auth.mode: enabled`. | The vacuity rule in lock 6: Alice asks; the second run under `disabled` removes the tenant axis entirely. |
| A1 changes roster prompt text while "only moving" it. | A byte-identity test on the group-roster injection is A1's first failing test. |
| The `reason_note` egress becomes the leak path RFC 0051 §E walls off. | DEBUG only, agent log only; the no-leak test extends to the three surfaces that must never carry it. |
| golangci-lint's first red run turns a CI PR into a refactor. | Fix-or-exclude per linter with a reason is the PR's scope; anything larger is filed, not fixed, and C cuts as a pair before it grows. |
| Workstream D consumes the window and A never opens. | Only D1 and D2 gate anything; D3… is explicitly "as many as land" and stops the day A2 needs review bandwidth. |
| The plan is at the word cap by Phase 3. | The locks and the per-PR breakdown are already split out — the first draft measured 3 358 words; this doc opens at ~2 600 by the checker, and splits again rather than trims. |
