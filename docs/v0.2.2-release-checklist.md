### 3.1 Required Upgrade Notes in Changelog

| Notable change | Detail |
|----------------|--------|
| Per-event memory token budget | A new `_MEMORY_BUDGET_TOKENS` allocator (default 1500 tokens) bounds how much episodic + relationship + notes context a persona will inject into a single event. Operators who tuned working-memory limits expecting the old open-ended injection should expect smaller per-event prompts and lower per-tick cost. No config change required; defaults are conservative. |
| Empty-context TICK short-circuit | When an autonomous TICK fires with zero memory admitted, no active goal, and no pending conversation turn, the LLM call is skipped and the scheduler increments `idle_count`. This closes the cost-leak class that motivated v0.2.2 (see [README cost warning](../README.md#%EF%B8%8F-cost-warning--read-before-running)). Non-TICK events and TICKs with admitted context are unaffected. |
| `min_score` relevance threshold on recall | `EpisodicMemory.recall` / `recall_notes` now accept a `min_score` parameter and filter out matches below the threshold. The previous opaque "legacy gates" are removed. Callers that supplied no `min_score` are unaffected. |
| No proto / REST / CLI surface change | RFC 0017 is internal-only. No `AgentService` RPC was added; no new REST endpoint; no new CLI command. Existing clients require no updates. |

## 6. Known Gaps to Document in Release Notes

These items remain intentionally incomplete and should be described as deferred scope, not regressions.

### v0.2.2-scope gaps

| Area | Description | Deferred to |
|------|-------------|-------------|
| Hybrid char-cap layer manual coverage | `_REL_NOTES_INTERIM_CHARS`, `_MAX_EPISODE_SUMMARY_CHARS`, `_MAX_NOTE_CONTENT_CHARS` are exercised by unit tests but no explicit manual runbook covers an adversarially-large item that hits the pre-allocator char cap. Documented in `docs/pr-reviews/pr-154.md` recommendation #4 as a discoverability improvement. | Future MT iteration |
| Operator-facing knobs for `_MEMORY_BUDGET_TOKENS` | The per-event memory budget is a module-level constant (`_MEMORY_BUDGET_TOKENS = 1500`); not currently exposed as a per-agent or per-event config field. Sufficient for v0.2.2 — operators who need a different bound can patch the constant. | Future RFC if demand exists |

### Carried forward from v0.2.1

| Area | Description | Deferred to |
|------|-------------|-------------|
| Multi-user support | Single `UserParticipant` per session; no concurrent user isolation | v0.3.0 (RFC 0011) |
| Authentication | Sessions are local, caller-supplied `user_id`; no auth tokens | v0.3.0 (RFC 0009) |
| Streaming responses | Synchronous request-response only; no SSE or WebSocket streaming | Future RFC |
| Agent-initiated messages | No notification infrastructure for outbound agent messages | Future RFC |
| Channel routing for user messages | Chat bypasses channel infrastructure; channels not yet user-ready | v0.3.0 (RFC 0011) |
| Rate limiting for chat | No per-user rate limit on the chat endpoint | v0.3.0 (RFC 0009) |
| Cost tracking for chat | `POST /api/v1/agents/{id}/chat` calls are not counted in `/api/v1/cost/summary` | v0.3.0 follow-up |
| Budget-exceed abort (`MT-COST-002`) | Live workflow abort on budget exhaustion | v0.2.x follow-up |
