- **Persona-memory store** (`agents/memory/migrations.py`) — the `MIGRATIONS` table advances from **v12** (the v0.3.5 epoch axis) to **v14**:
  - **Migration 13** ([`_migration_identity.py`](../agents/memory/_migration_identity.py)) — adds the nullable `identity TEXT` (JSON) column to the `relationships` table so person identity (name / role / stable preferences) lives on the genuinely cross-room relationship tier (F-7 Option D, D1).
  - **Migration 14** ([`_migration_identity_backfill.py`](../agents/memory/_migration_identity_backfill.py)) — backfills pre-cutover `contact:<id>` notes by parsing their identity and merging it onto the relationship `identity` column, so identity learned before the cutover is not stranded (D4).
  - Both migrations follow the established non-atomic DDL-then-version-record pattern with crash-replay-safe handlers ([`_migration_handlers.py`](../agents/memory/_migration_handlers.py)). The amendment is [RFC 0031 person-identity-cross-room-tier](rfcs/0031-amendment-person-identity-cross-room-tier.md).
- **Channel store** (`channels.db`) — [`channelStoreSchemaVersion`](../internal/channels/sqlite_schema.go) stays at **6** (no channel migration this release; the relevance gate and working-memory changes are render-/admission-time, not persisted).
- **Config / schema surfaces** — [`config/channels.yaml`](../config/channels.yaml) / [`schemas/channel.schema.json`](../schemas/channel.schema.json) gain the **disposition vocabulary** for a member's `respond` field (`participant`/`addressed`/`observer`) with back-compat normalization of the legacy `always`/`when_mentioned`/`never` at the Go config-load boundary, plus the **reserved/no-op per-disposition `threshold`** field (additive v0.3.8 seam). No new wire field for directedness — Tier A keys on the existing RFC 0011 `mentions` payload.

PR 4 confirms a **pre-v0.3.7 persona-memory DB opens and forward-migrates cleanly to v14** (no data loss; identity backfilled), that an already-v14 DB is a no-op open, and that an existing `config/channels.yaml` using legacy `respond_policy` values loads unchanged.
