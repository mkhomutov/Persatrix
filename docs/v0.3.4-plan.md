# v0.3.4 Plan — Any Model, Any Provider

**Status**: 🚧 Planning
**Target version**: v0.3.4 (RFC 0033 Phases 1–2 + release of the already-merged offline / Ollama provider work)
**Created**: 2026-05-23
**Branch prefix**: `feature/v034-`
**Target**: `main`
**Merge strategy**: Squash merge per [BRANCHING.md](BRANCHING.md)
**Codename**: *Any Model, Any Provider* (proposed — maintainer owns the final codename)
**Amended**: 2026-05-24 — provider-parity hardening; see [v0.3.4-plan-amendment-2026-05-24.md](v0.3.4-plan-amendment-2026-05-24.md)

**Goal**: orchestrate v0.3.4 end-to-end. One user-facing story: **Persatrix is no longer pinned to a vendor's model IDs.** Agents reference models by logical alias (`quality` / `fast` / `summarizer`); a vendor retirement or provider swap becomes a one-line edit. The release also ships the two provider modes already merged to `main` and parked in [`CHANGELOG.md` §Unreleased](../CHANGELOG.md) — offline (`MockProvider`, [#422](https://github.com/mkhomutov/Persatrix/pull/422)) and Ollama local-model ([#423](https://github.com/mkhomutov/Persatrix/pull/423)) — the same axis: pick any provider, including free local ones.

The umbrella RFC is [RFC 0033](rfcs/0033-model-alias-layer.md) (Provider-Agnostic Model Alias Layer). Phase 1 **absorbs the unavoidable Anthropic Sonnet 4 → 4.6 migration** as its first exercise.

**Out of scope** — not absorbed mid-flight:

- [RFC 0033](rfcs/0033-model-alias-layer.md) **Phase 3** (raw-ID fall-through removal, `_infer_provider` retirement). Per the RFC's [§Phased Implementation Plan](rfcs/0033-model-alias-layer.md#phased-implementation-plan), Phase 3 is gated on observed dogfood traffic showing zero raw-ID startup warnings — an observed-state gate, not a date. Re-homes to v0.3.5+ when that condition is met.
- [RFC 0031](rfcs/0031-per-session-namespacing-channels.md) **Phases 2–4** (recall filtering, `persatrix session …` CLI — the F-3 fix, [ISSUE-0051](issues/ISSUE-0051-per-session-memory-namespacing-channels.md)). The v0.3.3 plan forward-referenced this as v0.3.4; this plan **re-sequences it to v0.3.5** so the deadline-bearing alias work ships first ([§Decision](#decision--re-sequence-rfc-0033-ahead-of-rfc-0031-phases-24)). The drafted [`0031-phase2-pr-plan.md`](rfcs/0031-phase2-pr-plan.md) is preserved as the v0.3.5 input; only its version label and `feature/v034-` branch prefix re-point.
- [RFC 0030](rfcs/0030-multi-agent-conversation-governance.md) Phase 1, [RFC 0034](rfcs/0034-persona-conversational-working-memory.md) Phases 2–3, [RFC 0039](rfcs/0039-user-accounts-authentication.md) — `v0.3.x` candidates not on this contract.

## Why this plan exists

Three reasons v0.3.4 deserves an umbrella rather than a bare RFC 0033 PR plan:

1. **It is the only backlog item with a dated external deadline, and current config breaks on it.** `claude-sonnet-4-20250514` (**retires 2026-06-15**) is wired into production config in nine places: [`config/agents.yaml`](../config/agents.yaml) (×6), [`config/optimization.yaml`](../config/optimization.yaml) defaults + pricing key, and the [`agents/persona_types.py`](../agents/persona_types.py) default. On the retirement date the default `quality` agents stop working until each line is migrated. RFC 0033 Phase 1 **is** the migration — one alias edit, not a nine-site sweep — and leaves the abstraction in place so the next retirement is also one line. A throwaway sweep now plus the abstraction later pays the cost twice.
2. **The release vehicle already has cargo.** Offline (`MockProvider`, [#422](https://github.com/mkhomutov/Persatrix/pull/422)) and Ollama ([#423](https://github.com/mkhomutov/Persatrix/pull/423)) are merged and need a tagged release. They are the same story — RFC 0033 [§H](rfcs/0033-model-alias-layer.md#h-multi-provider-extensibility) names local Ollama as an alias-extensibility case — so folding them in adds the "free / local providers" half with no new implementation.
3. **The alias layer touches a cost-attribution surface v0.3.2 ratified.** Pricing is keyed by exact model ID today; RFC 0033 [§F](rfcs/0033-model-alias-layer.md#f-pricing-keyed-by-alias) re-keys it by alias and [§G](rfcs/0033-model-alias-layer.md#g-telemetry) adds a `persatrix.llm.model_alias` span attribute. The umbrella promotes "cost reporting stays correct across the migration" to a plan-level gate so the v0.3.2 wallet/cost dashboards do not silently mis-attribute.

Single RFC, so no inter-RFC sequencing tension — only Phase-internal ordering, which RFC 0033's [§Phased Implementation Plan](rfcs/0033-model-alias-layer.md#phased-implementation-plan) owns.

## Decision — re-sequence RFC 0033 ahead of RFC 0031 Phases 2–4

The [v0.3.3 plan](v0.3.3-plan.md#phase-5--tag-and-post-release-follow-up) and the prior ROADMAP prose forward-referenced v0.3.4 as *"RFC 0031 Phases 2–4."* That predates RFC 0033 being filed (2026-05-15) and the Sonnet 4 retirement becoming the nearest dated constraint. This plan supersedes it:

- **v0.3.4 carries RFC 0033 Phases 1–2** (+ the offline / Ollama release) — the only item with a hard external deadline, and Phase 1 delivers the deadline's migration as a side effect of the abstraction.
- **RFC 0031 Phases 2–4 re-home to v0.3.5.** The F-3 fix ([ISSUE-0051](issues/ISSUE-0051-per-session-memory-namespacing-channels.md)) stays committed but carries no deadline and is mitigated by `make reset`; shipping it after the alias work costs nothing it was not already paying. Its drafted [`0031-phase2-pr-plan.md`](rfcs/0031-phase2-pr-plan.md) becomes the v0.3.5 input; per its [§Prerequisites](rfcs/0031-phase2-pr-plan.md#prerequisites) the `feature/v034-rfc0031p2-` prefix sweeps to `feature/v035-`.

Not bundled into one release because the [ROADMAP Version Map](../ROADMAP.md#version-map) holds each release to one story — "alias your models" and "every run is auto-isolated" are two. Recorded canonically in [v0.3.x-sequencing.md §Amendment 2026-05-23](v0.3.x-sequencing.md#amendment-2026-05-23--v034-carries-rfc-0033-ahead-of-rfc-0031-phases-24); the completed [v0.3.3 plan](v0.3.3-plan.md) is left as a historical record.

## Acceptance for v0.3.4

The promise — *"reference models by alias; a retirement or provider swap is a one-line edit, and you can run the society on a free local or mock provider"* — is met when:

- `agents/model_aliases.py` exists: `resolve()` maps an alias (`quality` / `fast` / `summarizer`) to a `(provider, model_id, pricing)` record, with unit coverage for alias hit, raw-ID fall-through, and the deprecation warning ([RFC 0033 Phase 1](rfcs/0033-model-alias-layer.md#phase-1--resolver--alias-config-block--first-migration)).
- The `models.aliases` block lands in [`config/optimization.yaml`](../config/optimization.yaml) with `schema_version` bumped; all six `agents.yaml` `model:` entries and `context_management.summarization.model` reference aliases.
- **The Sonnet 4 → 4.6 migration is done by editing only the `quality` alias** — no per-agent sweep. After Phase 1 no runtime path carries a literal vendor model ID (the `persona_types.py` default becomes `None`, resolved at construction per [§J](rfcs/0033-model-alias-layer.md#j-persona-and-sub-agent-model-selection)).
- A startup deprecation warning fires on any remaining raw vendor model ID (the Phase 3 gate's signal).
- **Cost attribution survives the migration**: pricing derived from the alias map ([§F](rfcs/0033-model-alias-layer.md#f-pricing-keyed-by-alias)); `persatrix.llm.model_alias` span attribute emitted ([§G](rfcs/0033-model-alias-layer.md#g-telemetry)); `GET /api/v1/cost/summary` reports correctly-keyed, non-zero cost for an alias-routed agent.
- **Offline**: `PERSATRIX_OFFLINE=1` runs a full round-trip with zero provider calls, zero spend, populated `gen_ai.*` spans + wallet settle at $0 (carried from [#422](https://github.com/mkhomutov/Persatrix/pull/422)).
- **Ollama**: `PERSATRIX_OLLAMA=1` routes to a local model with real token counts and $0 cloud spend (carried from [#423](https://github.com/mkhomutov/Persatrix/pull/423)).
- A new manual test exercises an alias-routed agent (live), plus the offline and Ollama paths; the carried-forward MT surface passes unchanged.

Out of acceptance: RFC 0033 Phase 3 (observed-traffic gated); RFC 0031 Phases 2–4 (v0.3.5); RFC 0030 Phase 1; RFC 0034 Phases 2–3.

## Risk and mitigations

| Risk | Mitigation |
|------|------------|
| The migration re-keys pricing from raw model ID to alias; a missed entry silently mis-attributes cost. | [§Acceptance](#acceptance-for-v034) makes alias-keyed cost reporting a plan-level gate; Phase 2 derives pricing from the alias map ([§F](rfcs/0033-model-alias-layer.md#f-pricing-keyed-by-alias)) and the MT report captures `GET /api/v1/cost/summary` for an alias-routed agent. |
| Phase 1 keeps a raw-ID fall-through for back-compat; teams could ignore the warning and the abstraction never fully lands. | Phase 3 (raw-ID rejection) closes it, gated on observed zero-warning traffic, not a date — it lands when dogfood proves the migration complete. The startup warning is that gate's signal. |
| If v0.3.4 slips past 2026-06-15, default agents break on the Sonnet retirement. | The migration is a single alias edit — the smallest critical-path item. As a standalone fallback, a direct `claude-sonnet-4-20250514 → claude-sonnet-4-6` config swap clears the deadline independently of Phases 2+. |
| A resolver change could regress the already-merged offline / Ollama modes before anyone re-runs them. | Phase 1 PR plan adds a `provider: mock` / `provider: ollama` resolver regression check; Phase 4 re-runs both end-to-end on the RC tip. |
| Re-sequencing away from RFC 0031 Phases 2–4 leaves the F-3 fix unshipped another cycle. | F-3 stays mitigated by `make reset` ([ISSUE-0051](issues/ISSUE-0051-per-session-memory-namespacing-channels.md)); the fix is re-homed to v0.3.5, not dropped. The drafted [`0031-phase2-pr-plan.md`](rfcs/0031-phase2-pr-plan.md) is preserved as the v0.3.5 input. |
| Master plan rots as Phase 2 progresses. | Status updates are part of every step PR's checklist ([ROADMAP hygiene](#roadmap-hygiene)); reviewers reject step PRs that flip RFC status without touching the per-RFC plan's progress table. |
