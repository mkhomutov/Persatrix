## Follow-ups

- **F-1 — Chat REST surface lacks `BudgetExceededError` → `reply_status="error"` translation on the publish-and-await path** ([ISSUE-0065](../issues/ISSUE-0065-chat-rest-budget-denied-no-channel-reply.md); MT-COST-003 ❌ Fail; severity: **high — release blocker for the literal MT-COST-003 acceptance**). RFC 0023 PR 4 wired the gRPC `SendChatMessage` servicer to catch `BudgetExceededError` and return the [`chat_reply.chat_error_response`](../../agents/chat_reply.py) envelope — but the production REST chat path uses `ChannelRouter.PublishAndAwait` (see [`internal/server/chat_handler.go:302`](../../internal/server/chat_handler.go)) which routes via the agent's `ReceiveChannelMessage` ([`agents/server_servicers.py:322`](../../agents/server_servicers.py)). The fire-and-forget `_dispatch_channel_event` ([`agents/server_servicers.py:454-471`](../../agents/server_servicers.py)) catches `BudgetExceededError` via the generic `except Exception` arm with **a log line only — no error-reply is published on the channel**, so the orchestrator's reply waiter times out (HTTP 504 `DEADLINE_EXCEEDED`) instead of returning HTTP 200 + `reply_status="error"` + `LeaseDenied.message`. Additionally, `ChannelMessageEvent` proto has no metadata map for `chat_session_id` propagation ([`proto/task.proto:129-200`](../../proto/task.proto)), so the agent-side `cause_for_event` derives `CAUSE_CHANNEL_MESSAGE` rather than `CAUSE_CHAT` — the wallet still gates (verified), but the chat-specific surface contract is unmet. **Proposed fix shape** (out of scope for PR 1): in `_dispatch_channel_event`, catch `BudgetExceededError` and publish a structured error reply on the originating DM channel so `PublishAndAwait`'s waiter resolves with a chat-error envelope; alternatively, propagate `chat_session_id` through `ChannelMessageEvent` and route chat-origin events back through the `SendChatMessage` envelope path. Either fix needs a new MT-COST-003 re-run on a build that carries it. **Net effect on the v0.3.2 release decision**: the wallet enforcement *itself* — the core RFC 0023 deliverable — is fully working (denial is closed, no provider spend leaks, every lifecycle stage logs cleanly). Only the *user-facing error-envelope shape* for the chat REST surface fails the spec. The operator-visible surface under budget pressure is HTTP 504 instead of a clean structured error.
- **F-2 — Live `idle_reason=budget_denied` not observed during MT-COST-004 (Edge Case 2 dominated)** (MT-COST-004 ⚠️ Accepted-with-known-gap; severity: low). The Python integration test `tests/integration/test_tick_budget_denied_idle.py::test_budget_exhausted_tick_loop_stays_idle` passes — the action loop's `BudgetExceededError` catch → `DO_NOTHING` → `persona_tick_idle` counter with `idle_reason=budget_denied` works as specified. Live, however, every observed ember-owl autonomous tick was classified `idle_reason=empty_context_tick` (7+ ticks across ~5 min observation window), matching MT-COST-004 Edge Case 2 verbatim: the RFC 0017 §F empty-context short-circuit runs *before* the LLM call attempt, so the wallet never sees the lease for a tick whose context the persona judges empty. To genuinely live-observe `idle_reason=budget_denied`, a future MT iteration needs a richer fixture — e.g. a persona with an active goal, a populated working-memory item, or a recently-arrived event that *forces* the tick into the LLM-call branch under budget pressure. Wallet enforcement under the `CAUSE_AUTONOMOUS_TICK` arm is otherwise structurally identical to the proven `CAUSE_CHANNEL_MESSAGE` arm in MT-COST-003.
- **F-3 — Wallet acquire+settle p99 = 11.243 ms (above 5 ms target, informational)**. Loopback measurement across the Docker bridge network; per-RPC overhead includes ~1–2 ms host↔container loopback. Steady-state in-process number would be lower. RFC 0023 §Goal #6 marks this as informational, not a blocker. Captured as the v0.3.2 baseline.
- **F-4 — operator note for the release checklist** (carry-forward from v0.3.1 F-4). An empty `ANTHROPIC_API_KEY` exported in the shell overrides a populated `.env` under Docker Compose precedence. Every `docker compose` invocation in this run was prefixed with `unset ANTHROPIC_API_KEY` so Compose reads the `.env` file value. Worth keeping a one-line note in the release checklist's environment-setup section.
- **F-5 — gRPC rate limiter (60/60s anonymous-bucket) blocks naive load harnesses**. The wallet p99 harness initially failed with `RESOURCE_EXHAUSTED "rate limit exceeded"` because all `WalletService` RPCs without an `x-agent-id` gRPC metadata header share the anonymous rate-limit bucket. Fix shape: harness attaches `x-agent-id` metadata and rotates agent IDs every 20 cycles. Worth documenting at the operator-facing `wallet` section of the v0.3.2 docs so external load harnesses don't trip the same.
