## Release-prep regressions fixed

Four release-blocking issues surfaced during the pre-manual gate and are bundled in
this PR alongside the execution report, following the v0.2.2 precedent
(integration-test assertion fix shipped in the MT-execution PR so the gate reads green on
merge).

| # | Area | Fix | Why it blocked the gate |
|---|------|-----|-------------------------|
| 1 | Tests | [`tests/integration/test_span_links.py`](../../tests/integration/test_span_links.py) — two `deque([])` ↔ `[] `equality checks changed to `len(...) == 0` | PR #176 switched `_pending_tick_links` from `list` to `deque(maxlen=32)`. `deque([]) != []` under Python equality, so both `TestEventTriggersTickLink` tests failed on every run. Product behavior is unchanged. |
| 2 | Lint | [`internal/observability/logbuffer/subscribe.go`](../../internal/observability/logbuffer/subscribe.go) — dropped the `if _, ok := b.subs[s]; ok` guard around `delete(b.subs, s)` | `golangci-lint` (gosimple S1033) failed — `delete` on a missing key is already a no-op so the guard was redundant. Behavior unchanged; `go test ./internal/observability/logbuffer/...` still `ok`. |
| 3 | Deployment | [`Dockerfile.orchestrator`](../../Dockerfile.orchestrator) — create `/var/lib/persatrix` and `chown` it to `appuser`; [`docker-compose.yaml`](../../docker-compose.yaml) — add `orchestrator-data` named volume + `PERSATRIX_LOGBUFFER_DIR=/var/lib/persatrix/logs` env + `--grpc-bind 0.0.0.0` CLI flag on the orchestrator service | Without these, the reference compose deployment fails `logbuffer.New` at startup (`mkdir data: permission denied`, non-root `appuser` with no writable CWD). `gRPC LogService` then never binds, and the entire `persatrix logs` + cross-process trace-correlation surface — the headline v0.2.3 feature — is silently disabled. MT-LOGS-001 Scenario B could not pass against an unmodified v0.2.3 compose topology. |
| 4 | Deployment | Same `docker-compose.yaml` change: `--grpc-bind 0.0.0.0` added to the orchestrator `command:` | PR #173 review Must-Fix #2 defaulted `--grpc-bind` to `127.0.0.1` so a bare binary run did not expose the unauthenticated `LogService` on every interface. Inside the compose bridge network the agents resolve `orchestrator:9090` and dial it from another container's IP, which loopback-only rejects with `Connection refused`. |

All four changes live under this branch (`feature/v023-release-prep-mt-exec`). Every
result in this report was collected against a stack built from those fixes; see
[Stack build](#stack-build) below for the explicit `docker compose build` invocation.
