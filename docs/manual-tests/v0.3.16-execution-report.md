### The three evidence obligations

**A green leg that never exercised the contested surface is not proof.** Leg 5 can pass for the wrong reason in three distinct ways, so each has its own verbatim artifact:

| # | Wrong reason | Why green is not enough | Artifact required |
|---|---|---|---|
| 1 | **The tenant withheld it, not the gate.** | Under `enabled` the v0.3.15 partition already withholds Alice's DM content from any turn she did not cause; a quiet reply on her own turn is also consistent with the fact never having been a §D-admitted candidate. | The per-entry **`audience egress` record**: her entry at *withhold-disjoint*, `withheld` 1, read *after* the admitted set — from both runs, since the `disabled` run removes the tenant axis entirely. |
| 2 | **Rosters never resolved.** | *withhold-unknown-fetch-failed* cannot occur offline and `live` **admits** it, so a run whose rosters never resolved reads as every entry admitted-as-unknown. | The **fetch-failed count from both runs**, stated even when zero. |
| 3 | **The fact never consolidated with DM provenance.** | The check reads `source_channel_id`; NULL measures *no-provenance* (admitted), and a fact that never consolidated is a failed leg, not a vacuous pass (Edge Case 2). | The `facts` row `(subject, protection_level, source_channel_id)` with the id starting `dm:`, quoted **before** 5c is sent. |

## Findings & follow-ups

| # | Severity | Finding | Disposition |
|---|----------|---------|-------------|
| F-1 | **high** | **The containerised orchestrator could not be built at the RC tip.** Dependabot's x/crypto bump ([#877](https://github.com/mkhomutov/Persatrix/pull/877)) raised `go.mod` to `go 1.26.0` while `Dockerfile.orchestrator` still built on `golang:1.25-alpine` (`GOTOOLCHAIN=local`), so `go mod download` refused — `go.mod requires go >= 1.26.0` — and **every `make demo-*` stack was unbootable**. CI never sees it: the workflows read `go-version-file: go.mod` and no job builds the image (the same blind spot the offline-smoke gate exists to cover; v0.3.12's F-2 was the same shape one flag over). | **Fixed in this PR** — base image → `golang:1.26-alpine`; TDD: `tests/unit/python/test_dockerfile_go_toolchain.py` pins the builder tag against the directive (red before the fix). The arc ran on the rebuilt image. |
| P-1 | low | `make build-cli` copies the binary into `bin/` with `cp … \|\| true` and never creates the directory, so on a fresh worktree it prints `✓ CLI built → bin/persatrix` with no `bin/persatrix` on disk. | noted here; a one-line `mkdir -p` fix rides PR 2 or later |
| P-2 | low | MT Leg 5a/5b are written as `persatrix chat send "…" --as alice`; no such verb exists — `chat` is a REPL (`persatrix chat <agent> --user <id>`) that reads stdin line by line, so one piped line is one turn, and under `enabled` the verified claim replaces the body's `user_id` (RFC 0039 §F), which is why the account is bootstrapped with participant `alice`. | driver carries the correction; the MT text is corrected at PR 2's header bump (the MT is at its word cap — the fix is net-neutral) |
