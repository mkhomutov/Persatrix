## ISSUE-0109 calibration capture

Per-run data (all `group:planning`, Anthropic; cap 200,000):

| Arc | Topic shape | Duration | Close | Notes |
|-----|------------|----------|-------|-------|
| 1 | Monorepo, personas NAMED | 99 s | cascade cap (depth 5) → structural, chair synthesis | 7 msgs; 47,474 tok / $0.167 incl. close path |
| 2 (web re-convene) | Same topic, unchanged | ~4 min | cascade cap → structural, chair synthesis | Roster pushed back "we already worked through this"; produced a **redundant second synthesis** |
| 3 (retro) | Broad/bland, unnamed | 41 s | **end-vote quorum** (`end_votes`, threshold 2) | No stall — roster engaged a bland opener on a warmed store; no chair synthesis (end-vote close arms none, by design; agent-side reason falls back to `structural` — the documented unmarked-close mapping) |

Calibration findings (feeding [ISSUE-0109](../issues/ISSUE-0109-rfc0052-autonomous-defaults-calibration.md)):

1. **The global `max_cascade_depth` (5) binds before `max_rounds` on every productive arc** (arcs 1–2; reconfirms the 2026-07-20 finding) — ≈4–5 productive hops per discussion regardless of `max_rounds=8/12`. The cascade cap is currently the *de facto* discussion length knob; `max_rounds` never fired live.
2. **Collapse-proneness is inversely correlated with accumulated channel memory.** On a fresh store (2026-07-20) bias-to-silence muted bare openers; on this warmed store (relationships + history) even a bland retro drew immediate engagement, and the anti-collapse cadence had nothing to do. Openers naming personas remain the reliable fresh-store lever.
3. **Re-convening an unchanged topic produces a redundant synthesis** — the roster recognises the settled record and re-synthesises anyway (arc 2). A standing channel needs topic/agenda freshness per convening, or a "confirm-or-object" framing.
4. **`end_vote_threshold=2` closes a 3-persona autonomous channel fast** once two members converge (arc 3, 41 s). Operators wanting longer exploration should co-tune the threshold with `max_rounds`.
5. **Reserve headroom**: arc 1's close path (chair synthesis + 3 metered summaries) fit comfortably inside the `1 + N` reserve; no close-path denial in any arc (post-F-1).

## Findings & follow-ups

- **F-1 — [ISSUE-0111](../issues/ISSUE-0111-anonymous-wallet-rpcs-share-rate-limit-bucket.md): agent wallet RPCs were anonymous to the RFC 0009 rate limiter → the bounded-close summary fan starved a persona into the placeholder summary (§D violation). FIXED in this PR** (TDD: `agents/tests/test_wallet_client_identity.py`; `WalletClient` stamps `x-agent-id` on all three wallet RPCs; the misleading "active-lease cap" warn now logs the server detail). Surfaced by the first offline-smoke run: `iron-fox`'s summary lease was denied `RESOURCE_EXHAUSTED: rate limit exceeded` (3 retries in ~200 ms vs a 60 s shared anonymous window), and `ember-owl`'s successful summary lost its `SettleLease` to the same window (TTL-reaped at the granted estimate). Residuals tracked in the issue: `retry-after-seconds` not honoured on the close path; the REST publish surface still rides the anonymous bucket.
- **F-2 — the no-target `make eval-replay` sweep was unrunnable since PR 4c: recipe discovery globbed `*.yaml` and tried to load the `offline_responses.eval.yaml` mock-responses fixture as a recipe (schema rejection). FIXED in this PR** (discovery filters to `EVAL-*.yaml`, the schema's closed id domain; regression test added). Latent because every CI/integration invocation passes `--target`; only the release-prep suite sweep runs discovery bare. Also noted: `make eval-replay` uses `python3`, so a host without the repo `.venv` active fails on imports — run it from the venv (CI's ambient python carries the deps).
