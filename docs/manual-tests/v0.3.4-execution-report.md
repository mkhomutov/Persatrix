## Follow-ups

- **F-5 — `docker-compose.yaml` plumbs only `ANTHROPIC_API_KEY` into agents** — ✅ **RESOLVED on HEAD
  `6ce23cd`** ([#440](https://github.com/mkhomutov/Persatrix/pull/440)). The base compose now plumbs
  **both** `ANTHROPIC_API_KEY` and `OPENAI_API_KEY` into every agent (each with a `:-` empty default);
  the config-driven re-run's `make demo-openai` leg authenticated end-to-end with **no** throwaway
  override and logged no `OPENAI_API_KEY not set` warning. *Original `7e74873` finding (severity:
  medium; not a release-blocker):* a config-only swap to a cloud-OpenAI alias did not authenticate in
  stock Docker because no `OPENAI_API_KEY` was threaded into the agent containers — the MT-ALIAS-002
  OpenAI leg needed a throwaway compose override.
  This is precisely the provider-neutral onboarding gap [release-prep PR 2](../v0.3.4-release-prep-plan.md#pr-2--readme--roadmap--model-aliasprovider-guide--provider-neutral-onboarding--release-checklist)
  is scoped to close (`.env.example` "pick one", an any-provider compose guard that names every
  configured provider, `make demo-openai`). Worth wiring `OPENAI_API_KEY` (and any future provider key)
  into the agent service env there.
- **F-6 — the chat *default* 30 s timeout is too short for CPU-only local-model inference**
  ([ISSUE-0073](../issues/ISSUE-0073-cpu-local-model-chat-exceeds-default-timeout.md); new this run;
  severity: low — default-UX on the advertised demo, **not correctness**). On CPU, `llama3.2` generating
  a full-length response (plus the ~8 s one-time model load) runs past the chat default of 30 s →
  `DEADLINE_EXCEEDED`. The endpoint **already** supports a per-request `timeout_seconds` override clamped
  to ≤ 300 s (`internal/server/chat_handler.go`); with `timeout_seconds:120` the same turn returns
  `reply_status="ok"` (~93 s) — so **MT-OLLAMA-001 passes** and the MT recipe now sets it. The residual
  gap is purely the *advertised* `make demo-ollama` first-run UX (a user following the README at the
  default would get the error). Disposition options in ISSUE-0073: document `timeout_seconds` in the
  demo-ollama / README path (smallest, a natural fold-in to PR 2's onboarding sweep), or raise the
  default when a local provider mode is active, or lower the demo `max_tokens`.
- **F-7 — Live `model_alias` / `gen_ai.*` span not observable for a single healthy turn under 1% tail
  sampling** (new this run; severity: low — observability of the manual run, not a product gap). The
  collector keeps error / ≥5 s / workflow traces always but samples the remaining healthy traces at
  **1%**, so a single fast successful chat turn almost never lands in Jaeger. The `model_alias` span
  attribute is instead evidenced by `tests/unit/python/test_llm_client_model_alias_span.py` (green) plus
  the Prometheus per-model call series. A future telemetry MT wanting live span inspection should drive a
  workflow-tagged or deliberately-slow trace (always-sampled), or temporarily raise
  `healthy-tick-sample`.
- **F-1 — Stale "consume LLM tokens continuously" cost-warning fires for `timers: []` personas**
  (carry-forward from v0.3.3 F-1; severity: low — cosmetic). Observed again this run in ember-owl's
  Ollama-overlay startup logs. Fix: gate the warning on a non-empty timer set.
- **F-2 — Live `idle_reason=budget_denied` not observable on a stock persona** (carry-forward from
  v0.3.3/v0.3.2; MT-COST-004 ⚠️; severity: low). `test_tick_budget_denied_idle.py` confirms it; live the
  §F empty-context short-circuit masks it. Unchanged in v0.3.4.
- **F-3 — Operator note: empty shell `ANTHROPIC_API_KEY` shadows `.env` under Compose** (carry-forward
  from v0.3.3 F-3 / v0.3.2 F-4; severity: low). Every `docker compose` invocation this run was prefixed
  with `unset ANTHROPIC_API_KEY` so Compose read `.env`. Worth a one-line note in the release-checklist
  environment-setup section (release-prep PR 2).
