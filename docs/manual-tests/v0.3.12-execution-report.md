**Leg 4 diagnosis** (the MQ-11 provenance discipline, worth recording in full — this leg's first live run found two real things):

1. *The MT's scripted probe was structurally invalid*: Leg 2's own reply had put "Friday" into `group:planning`'s transcript, and the RFC 0034 conversation window is recent-N channel history, deliberately epoch-agnostic (the transcript is room-visible content, not memory) — an in-channel probe can never observe absence. The MT now probes on a fresh channel (F-3).
2. *On clean channels the epoch wall holds at the injection path*: with `PERSATRIX_MEMORY_PROVENANCE=1`, a fresh-epoch turn admitted **zero** items on every tier while the live-epoch control admitted 7 facts (+ `fact.recalled` reinforcement audit); direct gRPC probes at the agent with a `persatrix-epoch` header held on both the group and DM shapes; Jaeger shows the orchestrator emitting the override on the dispatch span (`epoch.id = mt-crossroom-fresh3`) — every wire hop correct.
3. *The residual leak is the tool side door*: on the leaked turns the model — finding its injected context empty, correctly — elected a **recall tool round** (two API calls, one trace), and tool execution runs in the action executor's task where the `on_event`-bound ContextVar scopes cannot reach (`resolve_active_epoch` falls back to the boot `live` snapshot). Pre-existing since tools and the epoch axis have coexisted (nothing in RFC 0037/0049/0039 touched it); the RFC 0037 classification axis does **not** share the hole (it rides `event.metadata` + `DispatchContext` for exactly this reason — the #788 tripwire lesson, and this run verified the tool-written notes stamped `restricted`). Filed as [ISSUE-0118](../issues/ISSUE-0118-tool-recall-bypasses-epoch-session-scopes.md) with the fix direction.

## Findings & follow-ups

- **F-1 — the §F cross-user 403 emitted no `authz.denied` audit record. FIXED in this PR** (TDD: `TestChatHistoryCrossUserMismatchEmitsAuthzDenied`, red → green; re-verified live on the rebuilt binary). MT-AUTH-001 Leg 3 pins the record on the cross-user history refusal, but the shipped emission lived only on the §E role-gate 403 (`enforcePolicy`) — which is **unreachable live** in Phases 1–2, where the bootstrap operator is the only account (role-gate 403s need a `user`-role principal; account creation is Phase 3). Net: a live deployment had **no** reachable `authz.denied` at all. The fix mirrors the middleware's emission in the §F claim-mismatch branch of `chat_history_handler.go` (`required: claim-match`); the claim-matching read stays record-free.
- **F-2 — the containerized orchestrator FATALed at boot on the RC tip: `auth: init failed — mkdir data: permission denied`. FIXED in this PR** (docker-compose.yaml). The RFC 0039 accounts store opens under **both** auth modes (PR 3 #790 — bootstrap needs it; login inert while disabled), and its binary default `data/accounts.db` is cwd-relative — not on any writable mount in the container (the exact ISSUE-0047 shape `--channels-db` already works around, one flag over). Every `make demo-*` stack was unbootable at the RC tip; CI never sees it (no docker in CI — the same blind spot the release-prep plan's offline-smoke gate exists to cover). Fix: `--accounts-db /var/lib/persatrix/accounts.db` in the compose command (base file only — no overlay overrides the orchestrator command). Verified by the passing offline smoke below and `accounts.db` present on the `orchestrator-data` volume.

- **F-3 — MT procedural gaps, all FIXED in this PR** (doc corrections to both memory MTs, found by executing them): (a) neither MT's preconditions required the *operator identity's* channel membership — the publish path 403s a non-member sender, and the naive runtime-join recovery carries the strict-reconcile restart brick, now spelled out; (b) the verification commands invoked a `sqlite3` CLI the agent image doesn't ship — replaced with the runtime's `python3` equivalents; (c) CROSSROOM Leg 4's in-channel probe could never observe absence (Leg 2's reply sits in the same channel's epoch-agnostic conversation window) — re-scripted onto a fresh probe channel; (d) the tripwire seed pointed at fact `object` text the live extractor stores too short for an 8-word span — re-pointed at the `restricted` episode summary.
- **F-4 — [ISSUE-0118](../issues/ISSUE-0118-tool-recall-bypasses-epoch-session-scopes.md) (medium, OPEN): agent-initiated memory-tool recalls bypass the per-request epoch/session scopes** — the executor-task ContextVar gap; full evidence chain in the [Leg 4 diagnosis](#mt-memory-crossroom-001--memory-that-travels-live-anthropic) above. Not a v0.3.12 regression (pre-existing; the shipped widening honors the wall at the injection path, and the classification axis is correctly threaded) — **whether it gates the v0.3.12 tag is a maintainer call**, flagged in this PR. The fix direction (thread epoch/session through `event.metadata` + `DispatchContext` like the classification axis) is in the issue.
