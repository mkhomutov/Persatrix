## Findings & Follow-ups

- **F-1 — the demo `config/channels.yaml` pinned the v0.3.10 headline `off`** (**found live, fixed in this PR**, non-blocking). The `planning` channel explicitly declared `reasoning.mode: "off"` with a stale comment claiming the block *"ships DARK … flips to `bid` in a later step"* — but that step (RFC 0051 PR 6 / [#697](https://github.com/mkhomutov/Persatrix/pull/697)) had already shipped. Because the governed-default `off → bid` flip only fills an **absent** mode (`config.go:445` `normalizedForGovernance`), the explicit `off` defeated it: `make demo-anthropic` ran the headline **off** on its main channel, and `MT-REASON-001` Step 1 (which reads `group:planning` and expects `bid`) failed as written. **The flip itself is correct** — a runtime-created governed channel resolves to `bid` (Step 1b). **Fixed in this PR**: `config/channels.yaml` planning now declares `mode: "bid"` (the governed default — still reported as governed-default provenance) with a refreshed comment documenting the live go-live + the `off` kill switch. `make validate` clean; no golden test pins the value.
- **F-2 — the verbatim `reason_note` has no operator egress** ([ISSUE-0108](../issues/ISSUE-0108-reasoning-reason-note-no-operator-egress.md), low, **documented + deferred**). The RFC 0051 deliberation parses a free-text `reason_note` and carries it on the decision, but **no log statement writes it** — the code/tests call its egress *"the operator-debug path, wired in a later PR"*, and that PR was the cut PR 7. Compounding it, the count-only `agent.deliberated` audit attaches `reason_code` via stdlib `extra=`, but the structlog `foreign_pre_chain` has no `ExtraAdder`, so the audit log line is presence-only. **Net:** the deliberation reason is observable **only** as the `deliberation.suppressed{reason_code, mode}` metric **label**; the verbatim `reason_note` is observable nowhere. **Not a privacy defect — the §E wall is stronger than documented** (zero egress). It is an observability + doc gap: §E and MT-REASON-001 Step 2 should not claim the agent log carries the reason until the egress lands. Per the [release-prep plan](../v0.3.10-release-prep-plan.md), wiring a new egress for a deliberately-walled field is feature work for its own reviewed PR, so it is deferred; Step 2 below reads the reason at **reason_code** granularity from the suppression metric (a real "stated reason"). PR 2 should correct the §E / persona-agents-guide wording.
- **Operational note (not a v0.3.10 finding) — runtime `channel join` on a YAML-declared channel trips the boot reconcile.** Adding the human driver `alex` to the YAML-declared `group:planning` at runtime, then restarting the orchestrator, hit the **intended, pre-existing** strict reconcile guard: `FATAL channels: config-vs-store membership divergence: channel=group:planning divergent_participants=[+alex]` (`internal/channels/router_reconcile.go` → `cmd/orchestrator/main.go:356`), already tracked as [ISSUE-0010](../issues/ISSUE-0010-reconcile-membership-divergence-doc-behaviour-mismatch.md). It is **orthogonal to reasoning** and **not a v0.3.10 regression** — the YAML is the membership source of truth for a declared channel. The Step 5d off-survives-boot leg was therefore run on a fresh stack (no runtime member divergence); a real deployment declares its human drivers in YAML or drives a non-declared channel.
