The new v0.3.5 MTs are **authored *and* executed in PR 1**. Proposed IDs (PR 1 finalizes naming):

- **`MT-SESSION-003`** — *F-3 recall isolation + within-session continuity* (**headline-claim test**). A second run under a fresh `PERSATRIX_SESSION_ID` surfaces none of the prior session's recall across all four persona-memory tiers, **and** a within-session arc still continues (the OQ #1 tension — single-session default recall *is* the dementia-test path). Mirrors [`test_session_continuity.py`](../tests/integration/test_session_continuity.py) / [`test_session_recall_isolation.py`](../tests/integration/test_session_recall_isolation.py) at the operator surface.
- **`MT-EPOCH-001`** — *epoch structural run-isolation* ([ISSUE-0085](issues/ISSUE-0085-epoch-axis-run-isolation.md)). A rerun under a fresh `PERSATRIX_EPOCH` (or `--epoch`), **same room + same `--user`**, inherits no episodes / relationship trust / person-facts — the structural residue a fresh channel name alone cannot reach. Mirrors [`test_epoch_run_isolation.py`](../tests/integration/test_epoch_run_isolation.py) live; confirms the `channel.dispatch` span carries the resolved epoch.
- **`MT-MEMORY-005` re-run** — the [dementia-test continuity gate](manual-tests/MT-MEMORY-005-dementia-test.md). **Must be re-run** on the alias/session-routed config: the recall path changed (default recall is now session-scoped), so this is the executable proof that single-session continuity is not regressed — unlike v0.3.4, where it carried forward unexecuted.
- **`MT-SESSION-001` Edge Case 2** — the Phase 1 write-contract MT, updated by Phase 2 (re-confirm the recall side now matches the write contract).

The v0.3.4 surface (37 rows — 33 carried + the 4 alias/provider MTs) **carries forward**, regression-checked against the session/epoch-routed config. PR 1 confirms the final total once the new rows are authored and added to the [`manual-tests/README.md`](manual-tests/README.md) index.

### Known follow-up issues

All Known Gaps for the release notes, not release gates:

1. **Subject-scoped facts deferred ([ISSUE-0084](issues/ISSUE-0084-fact-scope-by-subject-not-uniform-session.md)).** Facts are scoped uniformly by session like the other tiers; scoping a fact by its *subject* (so a fact about Alice follows Alice across sessions) is a continuity refinement, not a leak — beyond v0.3.5.
2. **`--all-sessions` recall verb deferred ([ISSUE-0086](issues/ISSUE-0086-operator-all-sessions-recall-verb.md)).** The `sessions="*"` cross-session debug mode exists at the recall layer but is reachable only programmatically; the `persatrix memory recall --all-sessions` operator verb is not built. The persona-runtime default context path is pinned never to reach `"*"` (the Phase 2 guarantee), so this is a missing convenience, not an isolation risk.
3. **`legacy`/`live` carve-out is permanent, by design.** Pre-v0.3.5 rows land under `session_id='legacy'` / `epoch_id='live'` and stay visible from the default path — the intended back-compat behaviour, not a gap. `persatrix memory legacy-prune` (a future cleanup verb) is scoped at [RFC 0031 Phase 4](rfcs/0031-per-session-namespacing-channels.md#phase-4-cleanup-and-documentation-pass), not built here.

Any `Accepted-with-known-gap` MT outcome in PR 1 must cite a tracked issue or an RFC-closeout / sequencing follow-up bullet.
