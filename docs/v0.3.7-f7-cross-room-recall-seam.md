# F-7 — Cross-Room Recall Seam (explicit recall is narrower than ambient injection)

**Finding ID**: F-7 (candidate ISSUE-0095)
**Severity**: Medium — memory is *correct in the data* but *inconsistent at the surface*: a persona recalls a person on a casual turn yet can claim amnesia when asked point-blank.
**Status**: 📋 Documented — fix not yet started (this doc precedes the fix PR).
**Origin**: End-to-end verification of the v0.3.7 conversation test-findings campaign (PRs #540–#548) on the rebuilt stack (gpt-4o). All six headline findings verified fixed; this seam surfaced while confirming F-3b (cross-room person memory).
**Parent**: [v0.3.7 conversation test-findings PR plan](v0.3.7-test-findings-pr-plan.md) (F-7 row); relates to [memory-scope-axes.md](memory-scope-axes.md), [RFC 0031 §D amendment](rfcs/0031-amendment-person-keyed-note-recall.md) (F-3b), [memory-quality-roadmap.md](memory-quality-roadmap.md) (ISSUE-0093, facts-tier re-home).

---

## The finding

On a **brand-new** channel, the same persona answers the *same underlying question* — "what do you know about me?" — two different ways depending on how it's asked:

| Turn (fresh channel) | LLM calls | Result |
|---|---|---|
| "Morning! Anything on your mind?" (casual) | **1** (no tool) | *"Morning, **Max**…"* — recalls the person cross-room ✅ |
| "Do you remember my name / favorite language?" | **2** (`recall_notes` tool) | *"I don't have any stored notes about you."* ❌ |

Ground truth: the `contact:local` notes (name + language) exist in the DB with `principal=local, epoch=live`; the exact cross-room query returns them. So the memory **is** there and **is** reachable — only one of the two read paths reaches it.

**Diagnosis (per-turn LLM-call counts):** the 1-call turn used the **auto-injected** cross-room contact note (correct). The 2-call turns are the LLM following the `memory-tool-usage` instruction — *"when a user asks if you remember something, call `recall_notes` first"* — hitting the **session-scoped** `recall_notes` tool, getting empty on a fresh room, and then **trusting that empty result over the injected context**.

## Root cause (architectural)

Memory **scope is decided at the call site, not by the data.** Two read paths disagree:

- **Auto-injection** (`recall_contact_notes` → `merge_sender_contact_notes`): `contact:*` notes are **cross-room** — correct, per `memory-scope-axes.md` (person identity is the cross-room axis).
- **`recall_notes` tool** (`agents/tools/builtin.py`): **session/room-scoped** for everything (the deliberate F-3b decision — only auto-injection went cross-room).

The prompt then steers the model into the **narrower** path. An *explicit* recall that is narrower than *ambient* injection is the inversion at the heart of the seam: asking directly returns **less** than not asking.

A secondary contributor is LLM-level: a model that just called a tool and got `[]` tends to trust that over background context — so the seam isn't merely latent, it surfaces as confident amnesia.

## Options considered

| Option | What | Verdict |
|---|---|---|
| **B — prompt only** ("prefer injected context; don't over-trust empty recall") | Tell the model to reconcile tool-empty vs context-present | ❌ **Not the fix.** Band-aid on a symptom; relies on the model resolving a direct contradiction it already handles inconsistently. Keep only as defense-in-depth. |
| **A — single source of truth for scope** | Centralize the `contact:*` → cross-room / room-note → room-scoped rule in one resolver that **both** auto-injection and the `recall_notes` tool obey | ✅ **Robust, do now.** Deterministic; closes the seam for every caller, not just the LLM; no model-behaviour dependency. |
| **C — drop the proactive-recall instruction** | Stop telling the model to call the narrower tool for identity (injection already provides it) | ➕ Cheap hardening to bundle with A; not sufficient alone (the tool stays scope-inconsistent for callers that do use it). |
| **D — scope is a property of the tier** | Re-home person identity onto the **inherently cross-room** relationship / declarative-facts tier (RFC 0026), per `memory-scope-axes.md` | ✅✅ **Architectural end-state.** Removes the `contact:*`-prefix special-case entirely; `recall_notes` goes back to honestly room-scoped; the two-path seam **cannot exist by construction**. Larger; also closes the "facts table empty" gap. = ISSUE-0093. |

## Recommendation — A now, D as the target (they compose)

1. **A (robustness, this campaign):** extract the topic→scope decision into one helper and make the `recall_notes` tool honor it — the tool returns room-scoped query hits **∪** the active participant's cross-room `contact:*` notes (the same set injection surfaces). Deterministic seam closure.
2. **C (hardening, bundle with A):** loosen the `memory-tool-usage` instruction so identity questions lean on injected context rather than mandating a narrower tool call.
3. **D (architecture, follow-up):** move person identity onto the cross-room relationship/facts tier so scope is intrinsic to the tier; at that point the `contact:*` cross-room special-case (and most of A) becomes unnecessary and `recall_notes` is purely room-scoped again. Carries an RFC amendment (touches RFC 0031/0026 + `memory-scope-axes.md`) and depends on fact extraction capturing identity — tracked as ISSUE-0093 on the [memory-quality roadmap](memory-quality-roadmap.md).

> **Why not just B:** the bug is that the data's scope rule is enforced in one path and not the other. Fixing it in the prompt leaves the divergence in the code and bets on model behaviour. A makes the rule a single source of truth; D makes the rule unnecessary.

## Fix PR plan

### PR A: `fix/v037-recall-scope-single-source` — unify recall scope (Option A + C)

- **Scope:** a single scope resolver for notes recall — `contact:<participant>` → cross-room (principal/epoch-scoped); other topics → room-scoped (`session IN (active, legacy)`). Both `_inject_memory_context`'s notes tier and the `recall_notes` tool route through it; the tool additionally folds in the active participant's cross-room contact notes. Loosen the `memory-tool-usage` proactive-recall instruction for identity (C).
- **Tests (TDD):** the `recall_notes` tool returns a cross-room `contact:*` note from a fresh session while a room note stays room-scoped; prompt-snippet content + byte-identity golden for the loosened instruction; an injection/tool parity test pinning that both paths surface the same person identity.
- **Live re-verify:** the F-7 reproduction — fresh channel, "do you remember my name?" now recalls cross-room (matching the casual-turn behaviour).

### Follow-up (separate, RFC-amendment): Option D — identity on the cross-room tier (ISSUE-0093)

Not in this PR. Re-home person-identity capture/recall onto the relationship/declarative-facts tier; retire the `contact:*` notes cross-room special-case; `recall_notes` reverts to purely room-scoped. Sequenced with the memory-quality roadmap.
