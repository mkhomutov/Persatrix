> **Status**: 🚧 Release prep — created by [release-prep plan PR 2](v0.3.6-release-prep-plan.md#pr-2--readme--roadmap--web-consolechannels-guide-verification--release-checklist). §1 (Pre-release Verification) and §2 (Version Alignment) are executed by [PR 3](v0.3.6-release-prep-plan.md#pr-3--version-bump--changelog-curation) (version bump + changelog) and re-certified by [PR 4](v0.3.6-release-prep-plan.md#pr-4--final-pre-tag-verification--release-notes) on the post-version-bump RC tip; the [Phase 4](v0.3.6-plan.md#phase-4--tag-and-post-release-follow-up) post-release follow-up cuts the `v0.3.6` tag and publishes the GitHub Release. The §4 manual-test sign-off references the [MT execution report](manual-tests/v0.3.6-execution-report.md) landed by [PR 1](https://github.com/mkhomutov/Persatrix/pull/523) — **both v0.3.6 headline gates passed live** (`MT-CONSOLE-001` + `MT-CHANNEL-GOV-002` on Anthropic, RC tip `83d478b`).

> v0.3.6 — "Web Console" — ships [RFC 0048](rfcs/0048-operator-tester-web-console.md) Phase 1 / Slice 1 (Interactions): an embedded, same-origin Svelte web console served from the Go orchestrator (`--enable-ui`, **off by default**) that renders over the existing chat / channels / agents REST API — open a URL, pick a persona, chat with it, and watch a channel, with zero CLI knowledge. Folded in with it is the [RFC 0030 Layer 2.5 floor-control amendment](rfcs/0030-amendment-floor-control-speaker-serialization.md): group-channel personas now reply in a deterministic, mutually-aware speaker round (on by default) instead of the pre-amendment concurrent, mutually-blind shout — the console makes multi-persona channels a *visible* surface, where that incoherence would have been the first thing a newcomer saw. The user-facing promise: *open `http://localhost:8080/ui`, talk to a persona, and watch a coherent multi-persona conversation — no CLI, no hand-edited config.*

### 3.1 Required Upgrade Notes in Changelog

This is the canonical source for Upgrade Notes text (PR 3 reconciles it with the four-row table already in `[Unreleased]`).

| Notable change | Detail |
|----------------|--------|
| **[Feature]** Embedded web console (`--enable-ui`, **off by default**) | `--enable-ui` serves the RFC 0048 Slice 1 console at `/ui` — a same-origin Svelte SPA embedded in the Go binary (`embed.FS`, no separate web server, no Node in the deployed binary), rendering over the existing chat / channels / agents REST API. Off by default; with it off `/ui/` is a clean `404` and no default behaviour changes. New surfaces: the read-only `/api/v1/ui/config` (toggles + runtime-derived `available` + `build.version`) and `/api/v1/ui/context` (`principal=local`) endpoints, `config/ui.yaml` (+ [`schemas/ui.schema.json`](../schemas/ui.schema.json), in `make validate`; an authored `available:` is a validation error), the `web/` JS toolchain, and `make ui` / `make run-ui`. It is **one consolidated conversation panel** (group channels + DMs; the standalone Chat panel was retired) and can **create group channels** over the existing `POST /api/v1/channels`. See the [web console guide](guides/web-console.md). |
| **[Security — load-bearing]** Localhost-only until auth | The console makes the **unauthenticated** REST surface browser-discoverable. The orchestrator binds `127.0.0.1` and the console is off by default, but **do not expose the console (or `:8080`) beyond localhost without an authenticating reverse proxy** until [RFC 0039](rfcs/0039-user-accounts-authentication.md) ships. Slice 1 is interact-only (chat + optional channel publish + group-channel creation — a signed-off structural-write-before-auth carve-out adding *zero new reachability*); the destructive/admin control plane is Slice 5, hard-gated on RFC 0039. See [web console guide §Security](guides/web-console.md#security--do-not-expose-beyond-localhost). |
| **[Scope]** Slice 1 only — later panels deferred | v0.3.6 ships the Interactions slice (the consolidated conversation panel). The memory inspector, isolation verifier, cost/observability, and control-plane panels are deferred to v0.4.0+ / post-RFC 0039; their `config/ui.yaml` toggles ship **off** so they land additively. Channel real-time push and chat token streaming are named later enhancements (Slice 1 polls + synchronous chat). |
| **[Behaviour — default change]** Floor control on for group channels | Group channels with **≥2 responders** now reply **serially** — one at a time, ordered mentioned-first then member order, each dispatched only after the prior speaker's reply lands, so each persona reads its predecessors. This **adds latency** (~N reply-compositions end-to-end instead of one) for a coherent, mutually-aware conversation. **On by default** for every group channel (declared in `config/channels.yaml` or created at runtime; persisted runtime channels re-resolve ON on restart), a **no-op below two responders** (DMs unaffected). To restore the old concurrent fanout, set `floor_control: false` on a config channel (opt-out is config-only). Per-turn wait `floor_turn_timeout_seconds` (default **45 s**). **Single-replica only** (in-process state). Telemetry: `channel.conversation.floor_turn{channel_type, outcome}` + `floor_round_duration{channel_type}`. See [channels guide §7](guides/channels.md) + [observability §11.3](observability.md). |
