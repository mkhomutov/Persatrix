# v0.3.8 Plan — Conversations That Converge (brainstorm: convergence + bounded cost + a readable outcome)

**Status**: 🚧 Planning
**Target version**: v0.3.8 (brainstorm-level usefulness — the second rung of the [usefulness ladder](v0.3.x-sequencing.md#the-usefulness-ladder))
**Created**: 2026-06-07
**Branch prefix**: `feature/v038-`
**Target**: `main`
**Merge strategy**: Squash merge per [BRANCHING.md](BRANCHING.md)
**Codename**: *Conversations that converge* (locked 2026-06-07; "brainstorm" is the descriptive subtitle, not the headline — preserves the *Conversations …* trilogy with v0.3.7 *worth watching* and v0.3.9 *you can mine*)

**Goal**: orchestrate v0.3.8 end-to-end. One user-facing story: **give a group of personas a problem and the brainstorm converges, terminates, and produces a readable synthesized outcome** — no pile-on, bounded cost, a real result. This is the *usefulness* rung that sits on top of the v0.3.7 *realism* rung (personas already read like colleagues) and below v0.4.0 *deliberation* (reasoning toward a decision), per the [2026-06-04 sequencing amendment](v0.3.x-sequencing.md#amendment-2026-06-04--re-sequence-the-v03x-tail-for-conversation-realism--usefulness-ahead-of-v040) and its [usefulness ladder](v0.3.x-sequencing.md#the-usefulness-ladder).

Three workstreams, one release contract:

- **RFC 0030 relevance Tier B — the cheap salience bid (no pile-on)** plus the `chair` disposition and natural-language addressing. When several `participant` personas could speak on ambiguous open-floor traffic, a cheap, leased `fast`-model bid decides who actually has something to add — biased to silence. This is the layer that turns "reply when you need to" into a real dynamic decision. It activates the per-disposition `threshold` field shipped reserved/no-op in v0.3.7, lights up the `chair` disposition (low threshold), and consumes free-text addressing ("question only to Iron Fox") as a salience signal. Owned by a Tier B PR plan (Phase 1 deliverable). Per the [relevance amendment](rfcs/0030-amendment-relevance-gated-response.md#scope--v037--v038--v040).
- **RFC 0030 deterministic governance layers — convergence + bounded cost.** The three deterministic layers that make a conversation *end*: **Layer 1** per-interaction cost ceiling (lease budget — RFC 0023 extension), **Layer 2** per-participant reply budget (fair turn-taking, no one dominates), **Layer 4** end-of-interaction signal (K consecutive votes → close the interaction). All ship **opt-in / uncapped by default** so they are additive, per [RFC 0030 §OQ-5/§OQ-8](rfcs/0030-multi-agent-conversation-governance.md#open-questions). Owned by a governance-layers PR plan (Phase 1 deliverable). Per [RFC 0030 §E/§F/§H](rfcs/0030-multi-agent-conversation-governance.md#e-layer-1--per-conversation-cost-ceiling).
- **Interaction summary surface — the readable synthesized outcome.** A closed brainstorm must hand back a *result*, not just stop. Surface the [RFC 0020](rfcs/0020-interaction-lifecycle.md) one-per-interaction summary at end-of-interaction (CLI + web console), so "converge and terminate" produces something a human can read. This is the "produce a real result" half of the headline; the deterministic layers are the "converge and terminate" half. Owned by a summary-surface PR plan (Phase 1 deliverable).

Each structural workstream gets a standalone PR plan opened as Phase 1 of this master plan; **this master plan wraps them** with the release contract + release-prep + tag phases. Same thin-orchestration shape as [v0.3.7-plan.md](v0.3.7-plan.md): the RFC PR plans own the internals; this doc owns which phases, in what order, by what release gate.

**Scope decisions locked at plan-authoring time (2026-06-07):**

- **`chair` disposition is IN v0.3.8 — as a low-threshold facilitator only.** Its full moderator behaviour (reading the transcript and deciding wrap-up/terminate) lives in **Layer 5, which remains v0.4.0**. In v0.3.8 the `chair` is a `participant` with a low (configurable) salience threshold — it clears Tier B easily and keeps the discussion moving — and its "Layer 5 hooks" are wired but **inert** until the moderator lands (the same reserved-field pattern v0.3.7 used for `threshold`). A v0.3.8 `chair` therefore **cannot unilaterally close a conversation**; convergence still comes from Layers 1/2/4. See [§Open-question status](#open-question-status).
- **Natural-language addressing is IN v0.3.8 — as a Tier-B salience signal, not a hard filter.** Free-text "only to Iron Fox" biases the salience bid; it does **not** become a deterministic directed-elsewhere drop (that stays keyed on structured `@`-mentions, per [amendment OQ #2](rfcs/0030-amendment-relevance-gated-response.md#open-questions) — caution against a hard NL filter until parsing is reliable).

**Out of scope** — explicitly deferred so they don't pressure the convergence cut:

- **RFC 0030 Layer 5 — moderator / bid-and-select** — v0.4.0. The `chair`'s active half (transcript-level continue/wrap-up/terminate) and the bid-and-select generalization of Tier B both depend on the moderator agent, which composes with the RFC 0028 decision engine. v0.3.8 ships the `chair` *disposition value + low-threshold behaviour* only; the hooks stay inert. Per [RFC 0030 §I](rfcs/0030-multi-agent-conversation-governance.md#i-layer-5--moderator-role).
- **RFC 0030 Layer 6 — declarative conversation types** (`design_review`, etc. with per-type budgets) — v0.5.0+. v0.3.8 exposes the raw per-channel knobs (`interaction_budget_tokens`, `max_replies_per_participant_per_interaction`); the named-type presets that bundle them are later.
- **Layer 1/2 default-value calibration** ([RFC 0030 §OQ-5](rfcs/0030-multi-agent-conversation-governance.md#open-questions)) — the layers ship **uncapped/opt-in**; deriving sensible per-type defaults needs observed-workload data, which only exists after v0.3.x usage. No normative numbers ship in v0.3.8.
- **RFC 0034 Phase 3** (instrumentation/tuning of `max_turns`/`max_tokens`, `_WINDOW_CACHE` LRU bound) — a later v0.3.x patch per [0034 PR plan §Future Phases](rfcs/0034-pr-plan.md#future-phases). Tier B *reads* the v0.3.7 in-round transcript; it does not re-open the window mechanics.
- **RFC 0035 / RFC 0036** (membership ledger + verbatim recall) — v0.3.9, the next release. Not a dependency of convergence.

## Why this plan exists

The three PR plans (Tier B salience, the deterministic governance layers, the summary surface) could ship as independent RFC workstreams. Three reasons they get an umbrella:

1. **A patch release needs a release contract, not just PR sequences.** Per [ROADMAP §Version Map](../ROADMAP.md#version-map), a version is defined by what a user *can do*; v0.3.8's promise — "watch a brainstorm converge, terminate, and hand back a readable result" — is a release-level gate no single PR owns. It is jointly delivered by no-pile-on (Tier B), bounded-and-finite (Layers 1/2/4), and a-real-outcome (the summary surface); the acceptance bar is the *combined* manual-test outcome — a real brainstorm that ends with a usable synthesis — not any one layer's unit suite.

2. **The convergence cluster is cross-cutting and must compose.** Tier B decides *who* speaks; Layers 1/2 bound *how much*; Layer 4 decides *when it's done*; the summary surface turns "done" into "here's the result". A regression in any one breaks the headline: pile-on returns (Tier B), or the conversation runs forever / costs unboundedly (Layers 1/2/4), or it stops with nothing to show (summary). One plan owns the join and the composition rule ([RFC 0030 §D](rfcs/0030-multi-agent-conversation-governance.md) — a publish proceeds only if every layer admits it; lower-layer drops short-circuit higher layers).

3. **Tier B finally has its substrate.** The [relevance amendment](rfcs/0030-amendment-relevance-gated-response.md) gated Tier B's *quality* on the in-round transcript (RFC 0034 Phase 2) — "judging relevance in a vacuum is hopeless." That substrate landed in v0.3.7. v0.3.8 is the release where Tier B is actually buildable, and where the per-disposition `threshold` field shipped reserved in v0.3.7 stops being a no-op. This plan owns the activation and the v0.3.7→v0.3.8 reconciliation of any source-doc prose that still reads "reserved/no-op".

Same thin-orchestration shape as [v0.3.7-plan.md](v0.3.7-plan.md): the RFC PR plans own the internals; this doc owns which phases, in what order, by what release gate.

## Acceptance for v0.3.8

The promise — *give a group of personas a problem and the brainstorm converges, terminates, and produces a readable synthesized outcome — no pile-on, bounded cost, a real result* — is met when:

- **No pile-on on open-floor traffic (Tier B salience).** On a multi-`participant` channel, an ambiguous open-floor message no longer draws a reply from every eligible persona: a cheap, leased `fast`-model salience bid runs per `participant`, and only those whose bid clears their `threshold` reach the quality turn. The bid is **bias-to-silence** (an unset/zero threshold biases to *no reply*), reads the v0.3.7 in-round transcript (so "someone already made my point" → silence), and fires **only** on the ambiguous remainder Tier A leaves (`@`-directed and `observer`/sender-self traffic never reach it). Manual test: a 4-persona channel given an open question produces a *small, relevant* set of replies, not 4 — and a follow-up that one persona already covered draws no duplicate.
- **The idle-cost invariant survives Tier B.** Tier B fires only for `participant` members on genuinely ambiguous traffic, on the `fast` model, under a lease (RFC 0023/0024). An uninvolved or `observer` persona still costs **zero** tokens; the existing cost-regression gate is extended to assert Tier B does not bill idle personas and that every bid is leased + attributable.
- **The `chair` disposition speaks like a facilitator (degraded, Layer-5-inert).** A persona configured `chair` clears Tier B at a low threshold and participates readily; its config loads and validates; the reserved "Layer 5 hooks" are present but inert. Acceptance explicitly records that a `chair` **cannot close an interaction** in v0.3.8 — convergence is owned by Layers 1/2/4.
- **Natural-language addressing biases the bid.** A free-text "let's hear from Iron Fox on this" raises Iron Fox's salience and lowers others'; it does **not** hard-drop the others (that remains structured-`@`-mention only). Unit test: NL addressing shifts bid outcomes without re-introducing a deterministic NL directed-elsewhere filter.
- **Cost is bounded (Layer 1).** A channel with `interaction_budget_tokens=N` denies further leases in the same interaction once the running total crosses N (`INTERACTION_BUDGET_EXHAUSTED`), fail-closed per RFC 0023 §F; default `0` (uncapped) keeps existing channels unchanged. Test: declare a small budget, assert later leases in the interaction are denied and a `governance_drop{layer=cost}` counter increments.
- **Turn-taking is fair and finite (Layer 2).** With `max_replies_per_participant_per_interaction=K`, a participant's (K+1)th publish in one interaction is rejected pre-persistence (HTTP 429 + `ErrParticipantBudgetExhausted`); default `0` (uncapped) preserves v0.3.0 behaviour; the orchestrator emits a startup Warn when a channel has all-eager membership and an uncapped budget. Human principals are exempt ([§OQ-7](rfcs/0030-multi-agent-conversation-governance.md#open-questions), `governance.exempt_principals: [human]`).
- **The conversation ends on its own (Layer 4).** When K participants emit the end-of-interaction signal, the interaction closes (`interaction_closed{trigger=end_votes}`); the signal is an **explicit action** (resolving [§OQ-4](rfcs/0030-multi-agent-conversation-governance.md#open-questions) in favour of auditability), votes are per-(`participant_id`,`interaction_id`) so double-voting counts once, and vote-spam is logged. The depth cap (Layer 0) and cost ceiling (Layer 1) remain the safety nets if no votes arrive.
- **A closed brainstorm produces a readable outcome (summary surface).** When an interaction closes (by votes, cost, or idle), its [RFC 0020](rfcs/0020-interaction-lifecycle.md) summary is surfaced to the human — visible in the web console interaction view and via CLI — so the brainstorm yields a synthesis, not just a stop. (If the summary is not already *generated* at interaction close, that generation step is part of this workstream — resolved when the summary-surface PR plan is authored; see [§Open-question status](#open-question-status).)
- **The composition + failure-down rules hold.** A publish proceeds only if every active layer admits it; a lower-layer drop short-circuits higher layers and increments `governance_drop{layer}`; higher layers fail safely down to lower ones; with every layer at its default (uncapped/opt-in), behaviour is identical to v0.3.7 (the whole feature is opt-in).
- **The combined story is documented and demonstrable.** A new `MT-CONVERSATION-CONVERGENCE-001` (open-floor brainstorm on a multi-persona demo channel: no pile-on → bounded cost → ends on votes → readable summary) is authored and passes live; CHANGELOG `[0.3.8]` describes the convergence win and the new opt-in channel knobs; `docs/guides/` channel docs name `interaction_budget_tokens`, `max_replies_per_participant_per_interaction`, the `threshold`/`chair` semantics, and the end-of-interaction signal.

Out of acceptance: Layer 5 moderator / bid-and-select; Layer 6 declarative conversation types; calibrated non-zero defaults; RFC 0034 Phase 3; RFC 0035/0036 (all deferred per the **Out of scope** list above).

## Phase 1 — Implement the three convergence workstreams

**Goal**: execute the three workstreams that jointly deliver the convergence story. The first step of this phase is **authoring the three PR plans**; they own per-PR scope, tests, and checklists. Rows 1a/1b/1c of the [Master Progress Overview](#master-progress-overview) stand for those sequences.

**Workstream 1a — RFC 0030 relevance Tier B** (`feature/v038-rfc0030-tierb-`):
- Leased `fast`-model salience bid in [`agents/response_gate.py`](../agents/response_gate.py) for `participant` members on the ambiguous open-floor remainder Tier A leaves; bias-to-silence; reads the v0.3.7 in-round transcript to suppress "already covered" replies.
- Activate the per-disposition `threshold` field (reserved/no-op since v0.3.7) in `schemas/channel.schema.json` + `config/channels.yaml`; clear the "reserved" caveat in schema/CHANGELOG.

**Workstream 1b — RFC 0030 governance Layers 1/2/4** (`feature/v038-rfc0030-layers-`):

- Wire the composition + failure-down rules; emit `governance_drop{layer}`, `interaction_closed{trigger}`, and the conversation cost/decision metrics ([RFC 0030 §Observability](rfcs/0030-multi-agent-conversation-governance.md)); proto fields reserved where RFC 0028 `DecisionRecord` will later consolidate (no behaviour change when it lands).

## Candidate fold-ins (maintainer decision)

Surfaced during pre-planning triage. None is required for the convergence cut; the maintainer owns whether to commit them — default is the three workstreams alone, so the CHANGELOG story stays singular.

| Item | Recommendation |
|------|----------------|
| **Pull Layer 5 (moderator / bid-and-select) forward into v0.3.8** so `chair` becomes fully active | **Defer (default) to v0.4.0.** The moderator is a transcript-level LLM role that composes with RFC 0028 and should land *after* RFC 0024-style event wake; folding it in would blur the deterministic-convergence story with the moderator workstream and roughly double the cut. v0.3.8's convergence is deliberately deterministic (Layers 1/2/4) so it needs no moderator. The `chair` ships as a low-threshold facilitator with inert hooks. |
| **Ship calibrated non-zero default budgets** (Layer 1/2) | **Defer (default).** [§OQ-5](rfcs/0030-multi-agent-conversation-governance.md#open-questions) commits to uncapped/opt-in until observed-workload data exists; shipping guessed numbers risks silently throttling channels. Calibrate post-soak. |
| **Declarative conversation types (Layer 6)** bundling the knobs into `design_review`/etc. presets | **Defer to v0.5.0+.** v0.3.8 exposes the raw per-channel knobs; the named presets are a later ergonomics layer per [RFC 0030 §J](rfcs/0030-multi-agent-conversation-governance.md). |
| **RFC 0034 Phase 3 cache LRU bound** | **Defer.** Harmless at demo scale; Tier B only *reads* the existing window. Phase 3 telemetry sizes the bound later. |

## Risk and mitigations

The per-PR implementation risks live in the three Phase-1 PR plans (authored in Phase 1). The release-level risks:

| Risk | Mitigation |
|------|------------|
| Tier B re-introduces idle cost — a leased LLM bid per persona could bill uninvolved members and break the RFC 0023/0024 zero-idle-cost invariant. | Tier B fires **only** on the ambiguous remainder after Tier A sheds `@`-directed/`observer`/sender-self traffic, only for `participant`s, on the `fast` model, under a lease. The cost-regression gate is extended to assert idle/`observer` personas cost zero and every bid is leased + attributable; a channel-size cap falls back to `addressed`-only on large channels ([amendment OQ #4](rfcs/0030-amendment-relevance-gated-response.md#open-questions)). |
| The `chair` ships looking like a moderator but cannot close conversations (Layer 5 is v0.4.0), confusing operators. | Acceptance + CHANGELOG state plainly that v0.3.8 `chair` is a *low-threshold facilitator* and convergence is owned by Layers 1/2/4; the Layer 5 hooks are documented as inert/reserved, same pattern as v0.3.7's reserved `threshold`. |
| The convergence layers ship but defaults silently change existing channels' behaviour. | All three layers default to **uncapped/opt-in**; a back-compat test proves end-to-end behaviour with defaults is identical to v0.3.7; the startup Warn only fires on all-eager + uncapped (advisory, not a behaviour change). |
| The summary surface stops conversations but shows nothing (summary not generated at close). | [§Open-question status](#open-question-status) forces the summary-surface PR plan to resolve generation-vs-surfacing **before** implementation; acceptance requires every close `trigger` (votes/cost/idle) to carry a readable summary. |
| Four mechanisms in one patch read as scope creep vs. a smaller cut. | All four serve a single user-facing story (a brainstorm that converges and produces a result) per the [Version Map contract](../ROADMAP.md#version-map); Tier B without termination, or termination without a summary, would each *fail* the headline. [§Candidate fold-ins](#candidate-fold-ins-maintainer-decision) makes every further addition an explicit opt-in; the default is the convergence three. |
| Layer 1 depends on the RFC 0023 lease path; a wallet/lease regression silently disables the cost ceiling. | Layer 1 fail-closed per RFC 0023 §F (lease fail → no LLM call); a dedicated test asserts a small budget denies later leases and increments `governance_drop{layer=cost}`; the depth cap (Layer 0) remains the always-on net. |
