# v0.3.12 Plan — Memory That Travels (cross-channel persona experience + safe remote console)

**Status**: 📋 Planned (this PR)
**Target version**: v0.3.12 (the *cross-channel persona experience* release — a persona's knowledge and experience follow it across every room it belongs to, made safe by classification instead of walls; plus the long-parallel *safe remote console* foundation)
**Created**: 2026-07-25
**Branch prefix**: `feature/v0312-`
**Target**: `main`
**Merge strategy**: Squash merge per [BRANCHING.md](BRANCHING.md)
**Codename**: *Memory that travels*

**Goal**: orchestrate v0.3.12 end-to-end. The headline user-facing story: **tell a persona something in one room and it knows it in every other room it belongs to — without ever leaking what it learned in a confidential room.** A project fact taught in a DM is known in the standup; raw experience from other rooms is available (room-first-ranked); what was learned in a `restricted` channel informs a `public` turn without being disclosed — withheld, or restated through a declassification projection. This is the maintainer's 2026-07-15 lock — *"everything crosses channels, gated by classification"* — turned into a release.

The bundled second workstream: **verified accounts** ([RFC 0039](rfcs/0039-user-accounts-authentication.md) Phases 1–2) — password login, revocable sessions, and an operator/user role gate on the REST surface, closing the "web console must stay on localhost" limitation carried since v0.3.6.

Two workstreams, one release contract:

- **The cross-channel persona-experience cluster (the headline).** [RFC 0037](rfcs/0037-memory-confidentiality-channel-classification.md) (the keystone, all three phases; the RFC 0038 §B single-channel-turn guard carved in per its Decision #3) + [RFC 0049](rfcs/0049-memory-consolidation-gradient.md) Phases 0–1, delivered through the three authored amendments: [0049-L1](rfcs/0049-amendment-l1-cross-room-availability.md) (cross-room episodic availability, room-first-ranked), [0031 fact-scope](rfcs/0031-amendment-fact-scope-by-consolidation-level.md) (L2 facts cross rooms; re-roots [ISSUE-0084](issues/ISSUE-0084-fact-scope-by-subject-not-uniform-session.md)), [0026 topic predicates](rfcs/0026-amendment-topic-subject-predicates.md) (the capture path). Owned by the [0037](rfcs/0037-pr-plan.md) and [0049](rfcs/0049-pr-plan.md) PR plans.
- **RFC 0039 Phases 1–2 (bundled, independently shippable).** The account/session foundation ships inert behind `auth.mode: disabled` (Phase 1), then enforcement + the verified `participant_id` claim (Phase 2); Phase 3 stays v0.4.0. Owned by the [0039 PR plan](rfcs/0039-pr-plan.md).

Same thin-orchestration shape as [v0.3.11-plan.md](v0.3.11-plan.md): the RFC PR plans own the internals; **this doc owns which phases, in what order, by what release gate**, and locks the version-scope decisions.

## Scope decisions locked at plan-authoring time (2026-07-25)

Resolved with the maintainer at plan opening (the 2026-07-15 lock fixed the theme; these fix the release):

- **v0.3.12 bundles both workstreams — a deliberate two-story release.** The cross-channel cluster is the headline; RFC 0039 P1–2 rides as the bundled second workstream. This deviates from the one-story-per-release contract that kept RFC 0039 out of v0.3.10 and v0.3.11 — accepted here explicitly because RFC 0039 has slipped twice, is entirely independent of the memory work (zero shared files), and is **cuttable to v0.3.13 without touching the headline** if the train stretches. The release notes lead with the memory story; accounts/auth is the second section, never the title.
- **RFC 0037 ships all three phases.** Phase 1 (lattice + channel classification + protection levels + the §D hard gate + the §F recall filter + the §B single-channel-turn guard) is the non-negotiable keystone. Phase 2 (declassification projections) is what makes the gate non-blunt — without it, cross-channel availability just silently *withholds* gated memories in lower rooms; the "informed by but doesn't disclose" half of the story needs projections. Phase 3 (leak tripwire) is small, deterministic, and independent. **Phases 2–3 are cuttable** if the train stretches; Phase 1 is not.
- **ISSUE-0106 rides, direction (b).** Deployment model confirmed at plan opening: **separate runs/epochs never share a channel-store DB**, so the recall `epoch_id` body override is a footgun with no enforcement value — drop it, amend RFC 0036 §OQ-6, retire the decoupling tripwire test. Lands in [0037 PR plan](rfcs/0037-pr-plan.md) PR 5, which already reworks the endpoint's parameters, so the surface changes once. The `epoch`/`principal` axes stay hard walls everywhere else.
- **ISSUE-0114 rides as a cuttable fold-in.** Per-channel `max_cascade_depth` — the de facto discussion-length knob on a productive autonomous roster (ISSUE-0109 finding 1): config + schema + a synchronized per-channel map (the `endVoteThresholds` precedent) + the RFC 0050 PATCH decision. Go/Python alignment default: option (c) — the Python dispatcher cap stays a global backstop, per-channel caps ≤ it — revisitable in the fold-in PR. Droppable without touching either workstream.
- **The hard sequencing rule is a merge gate, not guidance.** No RFC 0049 widening (L1 or L2) merges before RFC 0037 Phase 1's §D gate + §F filter are on `main` ([RFC 0049 §E](rfcs/0049-memory-consolidation-gradient.md#e-confidentiality-is-the-keystone-not-an-add-on), extended to L1 by the [L1 amendment](rfcs/0049-amendment-l1-cross-room-availability.md)). Widening before the gate is a confidentiality regression by definition.
- **The widenings ship shadow-first.** Cross-room recall (both the L1 episodic mode and the L2 fact widening) lands in *shadow* — evaluated against the [RFC 0044](rfcs/0044-eval-set-golden-traces.md) golden traces — and promotes to the live prompt only when it does not degrade prompt quality under the RFC 0017 injection budget and does not regress the dementia-test continuity bar (room-first ranking is the mechanism that protects it).

**Out of scope** — explicitly deferred so they don't pressure the cut:

- **RFC 0049 Phases 2–4** (cross-scope consolidation pump, decisions-as-memory, 0038/0042 reconciliation) — v0.4.0; they need the unimplemented RFC 0027/0028 engines.
- **RFC 0038 §C–§E** (concurrent contexts / awareness / relay) — v0.4.0; only its §B guard rides, inside RFC 0037 Phase 1.
- **RFC 0039 Phase 3** (account administration REST API, self-service password change, failed-login lockout) — v0.4.0.
- **The per-persona `compartmentalised` posture** (RFC 0049 OQ-1's named exception) — v0.4.0 implementation detail; v0.3.12 ships the cross-room default only.
- **MFA / SSO / API-key principals** — RFC 0039 §I extension points, v0.5.0+.
- **A subject classifier for facts** — superseded by the §D re-rooting (scope is consolidation level, not subject); ISSUE-0084 closes by re-rooting, not by building the classifier it originally asked for.

## Why this plan exists

v0.3.12 is the widest-coupled release since v0.3.2: it changes what every memory tier may surface, everywhere. The umbrella earns its place:

1. **The sequencing rule needs a release-level owner.** "Nothing widens before the gate" spans two RFCs and three amendments; no single PR plan can enforce ordering *between* plans.
2. **Two workstreams, one tag.** This doc owns which pieces are cuttable (RFC 0039 whole; 0037 P2–3; the ISSUE-0114 fold-in) and what "cut" means: slip to v0.3.13, headline untouched.
3. **The shadow→live promotion is a release-level decision.** The golden-trace measurement gate decides whether v0.3.12 ships cross-room recall *live* or *shadow-with-a-flip-note* — a release-prep call, not any feature PR's.

## Acceptance for v0.3.12

The release ships when **all** hold:

- **`MT-PERSONA-CONFIDENTIALITY-001` passes live** — a persona learns a fact in a `restricted` channel; acting in a `public` channel it does not disclose it (withheld, or — with Phase 2 — restated only through its lower-classified projection); acting back in the `restricted` channel it recalls it verbatim. The §G tripwire (Phase 3) audits a deliberately-seeded verbatim leak.
- **`MT-MEMORY-CROSSROOM-001` passes live (the headline scenario)** — a project fact taught in a DM ("Atlas ships Friday") is recalled in a group channel the persona belongs to, via the L2 widening + `topic.*` capture; the DM re-ask after a group-channel mention also recalls it. RFC 0049 worked-example scenario 2, end-to-end.
- **The dementia-test continuity bar does not regress** — `EVAL-MEMORY-001` replays green, and the room-first-ranking change shows no continuity degradation on the golden traces (the L1 amendment's promise that the bar is a *ranking* property).
- **The shadow measurement gate ran** — cross-room recall (L1 + L2) was evaluated in shadow against RFC 0044 goldens before live promotion; if the gate failed, v0.3.12 ships the widenings shadow-only with a documented flip criterion — a valid release, recorded in the notes.
- **Classification is fail-closed everywhere** — all three §A rules hold, each with its own resolver: stamp → `internal`, acting level → `public` floor (autonomous ticks included), unparseable *entry* level → withheld; an unclassified pre-migration channel backfills `internal`; `validate` rejects unknown levels.
- **Auth Phase 1 is inert and Phase 2 enforces** — the full suite passes unchanged under the default `auth.mode: disabled`; under `enabled`, the §E 401/403 matrix holds on every human-facing route, `persatrix login/logout/whoami` round-trips, the chat path carries the verified `participant_id` claim, first-operator bootstrap works on an empty `accounts.db`, and the [enabled-mode exposure amendment](rfcs/0039-amendment-enabled-mode-exposure.md) holds — `HttpOnly` cookie sessions (no token in JS), same-origin-asserted cookie writes, throttled login (`MT-AUTH-001`).
- **ISSUE-0106 is closed in direction (b)** — override gone, RFC 0036 §OQ-6 amended, decoupling tripwire retired.
- **ISSUE-0114 is closed (or explicitly cut)** — per-channel `max_cascade_depth` resolves like `ResolveInteractionBudgetTokens` (zero/absent → fleet value) through a synchronized per-channel map (the `endVoteThresholds` precedent); `closeOnCascadeBound` and the arming validation read the per-channel value; the Go/Python alignment posture is documented.
- **Docs + diagrams are edited, not just verified** — persona-agents / channels / sessions / web-console guides + the memory-architecture diagram carry classification, protection levels, the two-axis model, and the auth surface; the README localhost-only-console line names `auth.mode`.
- **The full gate sweep is green live on host** — Go `-race -cover`, the Python persona/channel/wallet suites, Vitest, Rust, ruff/mypy/clippy/go-vet; `make validate`; the live-provider Docker smoke; the `MIT ← BUSL ← Private` gate.

## Phase 1 — Implement RFC 0037, RFC 0049 P0–1, RFC 0039 P1–2

Owned end-to-end by the three RFC PR plans. The release gates this plan enforces over them:

- **The merge gate is absolute.** No L1/L2 widening PR merges before the RFC 0037 §D gate + §F filter are on `main`. The 0049 PR plan's first implementation slice hard-references the 0037 PRs it needs.
- **Dark-until-complete inside RFC 0037 Phase 1.** Per the RFC's PR-ordering rule (item 8): all Phase-1 steps land within one release and no channel is operator-classified above `internal` before the full set ships; note-stamping lands with-or-after the §D gate + `recall_notes` gating.
- **The capture amendment carries its security gate.** The `topic.*` allowlist expansion re-runs the blast-radius review (subject canonicalization, object length bounds, delimiter escape) *in the PR that widens the extractor prompt* — a named review gate, not a footnote.
- **Shadow-first for both widenings.** L2 fact widening and L1 episodic availability each land behind a shadow evaluation; the live flip is a separate, small PR gated on the golden-trace measurement.
- **RFC 0039 Phase 1 is provably inert.** The Phase-1 closeout requirement is the *unchanged* full test suite under `auth.mode: disabled` — the same "byte-for-byte untouched" posture v0.3.11 applied to human channels.
- **Everything but the keystone is cuttable.** 0037 P2–3, all of RFC 0039, and the ISSUE-0114 fold-in can each slip to v0.3.13 without touching the headline scenario (which needs 0037 P1 + the 0049 slices only). Cutting 0037 P2 downgrades the confidentiality story from "informed by, doesn't disclose" to "withheld" — acceptable, documented in release notes if taken.

## Risk and mitigations

| Risk | Mitigation |
|------|------------|
| A widening merges before the gate and opens a leak window. | The merge gate is stated in three places (this plan, the 0049 PR plan, the L1 amendment); `post-gate` branch names; reviewers reject any widening PR based before the §D/§F PRs. Inside 0037 Phase 1 the item-8 rule keeps everything dark until the set completes. |
| Cross-room recall floods the injection budget and degrades prompts. | Room-first ranking demotes other-room candidates; both widenings ship **shadow-first**, promoting only on a green golden-trace measurement; a red gate ships shadow-only — the release does not block. |
| The dementia-test continuity bar regresses when the wall becomes a boost. | Asserted twice: `EVAL-MEMORY-001` replay and the new ranking goldens; the L1 slice cannot promote on a red replay. |
| The `topic.*` extractor widening re-opens the prompt-injection surface. | The blast-radius review is a named in-PR gate; the namespace stays a **closed** allowlist — new verbs still require an amendment. |
| Two-story release obscures what the user gained. | Release notes and the Version-Map line lead with memory; accounts/auth is a separate section; cutting RFC 0039 whole reverts v0.3.12 to one story. |
| The channel-store v11 or memory-side migrations bite on real data. | Both follow the shipped versioned in-transaction discipline with conservative `internal` backfill; migration tests run on populated pre-migration stores. |
| Auth enforcement breaks existing deployments. | Opt-in (`auth.mode: enabled`); `disabled` is the shipped default; Phase 1 is provably inert (full-suite no-delta gate); bearer plumbing lands with enforcement in the same PR. |
