### 3.1 Required Upgrade Notes in Changelog

This is the canonical source for Upgrade Notes text; the `[Unreleased]` section already contains the same content verbatim and must be preserved when reshaped into `[0.3.0]`.

| Notable change | Detail |
|----------------|--------|
| Channel-event enum hard-rename | `EventType.MESSAGE_RECEIVED` → `CHANNEL_MESSAGE` and `ActionType.SEND_MESSAGE` → `SEND_CHANNEL_MESSAGE` across all Python producers (chat ingest, persona-runtime response gate, dispatch executor, action validators, prompt assembly, state persistence, memory routing). v0.2 enum aliases dropped. `ActionExecutor` result dict now carries `"action_type": "send_channel_message"`. Out-of-tree consumers must update event-type filters and result-dict consumers. |
| Chat REST endpoint migrated to channels | `POST /api/v1/agents/{id}/chat` now goes through the channels publish-and-await façade ([RFC 0011 amendment](rfcs/0011-amendment-chat-as-dm.md)). JSON contract on `chatRequest` / `chatResponse` is preserved — Rust CLI and existing REST clients are unaffected — but the legacy `SendChatMessage` gRPC path is dead code (cleanup tracked in ISSUE-0035). |
| New `SECURITY_RATE_LIMIT_*` env vars | RFC 0009 PR 2 ships a per-agent sliding-window rate limiter with circuit breaker. `SECURITY_RATE_LIMIT_RPS`, `SECURITY_RATE_LIMIT_BURST`, `SECURITY_RATE_LIMIT_DISABLED` configure the limiter at startup. Opting out emits a one-shot `rate_limit.disabled` audit event so the choice is visible in the audit log. Operators see HTTP 429 + `Retry-After` on REST and `ResourceExhausted` / `PermissionDenied` on gRPC after threshold violations; `POST /api/v1/agents/{id}/unquarantine` clears a quarantined agent. |
| `<external_data>` envelope wrapping | RFC 0009 PR 3 wraps `http_request` / `file_read` tool results in an `<external_data>…</external_data>` envelope at the LLM-content boundary, with close/open-tag escaping (`_EXTERNAL_DATA_TAG_RE`) so untrusted content cannot break out. Out-of-tree LLM evaluators or post-processors that grepped on raw tool-output strings must move to the wrapped form. The unconditional `external-data-handling` prompt fragment teaches the model the contract. |
| Channels REST surface is unauthenticated | A startup `WARN` notice fires whenever the channels subsystem is enabled. `sender_id` is body-trusted in v0.3.0 — firewall the port or front with an authenticating reverse proxy until [RFC 0009 Phase 4](rfcs/0009-security-sandboxing.md) lands in v0.4.0. The notice is intentionally not suppressible from config. |
| Persona prompt-section directory is public surface | Every persona prompt fragment now lives under [`prompts/runtime/persona/sections/`](../prompts/runtime/persona/sections/) ([RFC 0022](rfcs/0022-persona-prompt-section-templating.md)). Forks and out-of-tree tooling that override prompt assembly should pin against this directory shape. |
| Now-anchor in persona prompts | Persona prompts emit a `now-anchor` line and render episode + relationship timestamps as relative time ("yesterday", "3 days ago") instead of raw epoch seconds (RFC 0021 Phase 1). Out-of-tree prompt evaluators that key on absolute timestamps must move to the rendered form, or read the underlying epoch from the episodic store directly. |
| Episodic write cadence changed | RFC 0020 collapses multi-turn dialogues to **one** episodic entry per interaction (open → multi-turn → close → summarize) instead of one entry per inbound event. Out-of-tree memory-inspection tools that counted episodes-per-message will see the count drop sharply on chatty channels — this is by design. The `interaction_id` + scope tag on each episode is the new lookup key. |

### v0.3.0-scope gaps

| Area | Description | Deferred to |
|------|-------------|-------------|
| Channels REST surface is unauthenticated | `sender_id` is body-trusted; orchestrator emits a one-shot startup `WARN`. Run behind your own ingress/auth proxy on shared networks. | RFC 0009 Phase 4 (v0.4.0) |
| External bridges (Slack / Discord / email) | Channels are internal-only in v0.3.0. The bridge surface is RFC 0011's deferred external scope. | v0.5.0 (RFC 0011 external scope) |
| Persona named-entity recall after idle-gap closure | MT-MEMORY-005 Leg 1 fails on the V1 dementia-test variant — the canonical signature motivating the declarative facts tier. Legs 2/4/5 hold up at the same 11-min boundary. | v0.3.1 ([RFC 0026](rfcs/0026-declarative-facts-tier.md)) |
| Sandbox isolation + token auth (RFC 0009 Phases 3–4) | v0.3.0 ships audit + redactor + rate-limit + sanitization (Phases 1–2). Process/container isolation and authenticated REST surface are deferred. | v0.4.0 ([RFC 0009 Implementation Notes (v0.3.0)](rfcs/0009-security-sandboxing.md#implementation-notes-v030)) |
| Persona temporal awareness — Phases 2–4 | now-anchor + relative-time rendering ship in v0.3.0 (Phase 1). Structured commitment tracking, scheduled callbacks, and conversation-thread temporal grounding are deferred — surfaces in MT-MEMORY-005 Leg 3 (commitment recall miss is a known v0.3.0 gap, not a regression). | v0.4.0 ([RFC 0021](rfcs/0021-persona-temporal-awareness.md) Phases 2–4) |
| Eviction-parameter calibration (RFC 0008) | RFC 0008 ships per-eviction instrumentation. Calibration of the eviction parameters is a forward-looking placeholder that fires when production-like workload telemetry exists. | v0.3.x follow-up gated on observed-workload data ([RFC 0008 §OQ #12 walkback](v0.3.0-release-prep-plan.md#rfc-0008-oq-12-walkback)) |
