# v0.2.0 Release Checklist

> v0.2.0 is the first public Persatrix release: Persona Core, three-tier memory, and execution-cost controls.

---

## 1. Pre-release Verification

- [ ] `make test` is green on a clean checkout
- [ ] `make lint` is clean
- [ ] `make validate` passes for all config files
- [ ] Proto staleness check passes: `make proto` then `git diff --exit-code`
- [ ] `make check-licenses` is clean for Go, Python, and Rust
- [ ] `make notices` regenerated and diffed: any newly added dependency has an acceptable license (nothing GPL, AGPL, LGPL, SSPL, or unknown); commit the updated [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) as part of the release-prep PR
- [ ] Verify the checked-in manual test suite is complete: 13 test documents plus [docs/manual-tests/README.md](../docs/manual-tests/README.md)
- [ ] Optional but recommended: `make docker-build && make docker-up` smoke test before tagging

Record the command outputs or links to CI runs used as release evidence.

## 2. Version Alignment

Before tagging, all shipped components must declare `0.2.0` consistently.

| Component | File | Required state for release |
|-----------|------|----------------------------|
| Python agents | `agents/pyproject.toml` | `version = "0.2.0"` |
| Rust CLI | `cli/Cargo.toml` | `version = "0.2.0"` |
| Rust lockfile | `cli/Cargo.lock` | Regenerated after the CLI version bump |
| Go orchestrator | git tag | Release identified by `v0.2.0` tag |

Checklist:

- [ ] `agents/pyproject.toml` updated to `0.2.0`
- [ ] `cli/Cargo.toml` updated to `0.2.0`
- [ ] `cli/Cargo.lock` regenerated and committed
- [ ] No docs or examples still describe v0.2.0 as unreleased work-in-progress

## 3. Changelog

The release changelog must preserve the curated v0.2 material already prepared in [CHANGELOG.md](../CHANGELOG.md).

Checklist:

- [ ] `CHANGELOG.md` contains a `[0.2.0]` section
- [ ] The current curated `[Unreleased]` items were moved under `[0.2.0]` rather than overwritten
- [ ] The v0.2.0 section has a readable summary of persona agents, memory, and cost controls
- [ ] An explicit **Upgrade notes** subsection calls out the `max_llm_calls` default change from `10` to `5`
- [ ] The changelog notes that v0.1.0 was an internal baseline, not a public release

Suggested generation command:

```bash
git-cliff --tag v0.2.0 --unreleased --prepend CHANGELOG.md
```

If `git-cliff` would overwrite curated content, generate into a temporary file and merge manually.

## 5. Tag And GitHub Release Procedure

Use a clean `main` checkout after the final release-prep PR merges.

```bash
git checkout main
git pull --ff-only origin main
git tag -a v0.2.0 -m "v0.2.0 - Persona Core"
git push origin v0.2.0
```

GitHub Release checklist:

- [ ] Create the GitHub Release from tag `v0.2.0`
- [ ] Use the curated v0.2.0 changelog section as the release notes baseline
- [ ] Call out first-public-release positioning for Persatrix
- [ ] Include upgrade notes and known gaps in the release body
- [ ] Attach binaries or container references if they are produced for this release

## 6. Known Gaps To Document In Release Notes

These items remain intentionally incomplete and should be described as deferred scope, not regressions.

| Area | Path | Release-note callout |
|------|------|----------------------|
| Resilience | `internal/resilience/` | Stub package; advanced circuit-breaker and dead-letter behavior remain deferred |
| Agent-to-agent protocol | `internal/a2a/` | Distributed or cross-node agent protocol work is not part of v0.2.0 |
| Mesh runtime | `internal/mesh/` | Multi-node deployment is deferred to a later version |
| Internal bridges | `internal/bridges/` | Bridge infrastructure is not user-ready in v0.2.0 |
| Internal channels | `internal/channels/` | Shared-channel conversations do not ship in v0.2.0 |
| Security hardening | `internal/security/` | RFC 0009 follow-on work remains for v0.3.0+ |
| Telemetry | `internal/telemetry/` | OTEL package is still a stub; no dedicated release RFC yet |

Notes:

- Channels and bridges align with the future channels-plus-bridges track in the roadmap.
- Security hardening is explicitly deny-by-default today, but broader audit and sandbox work is still pending.
- v0.2.0 is the first public release; describe these as deferred roadmap items, not missing back-compat promises.
