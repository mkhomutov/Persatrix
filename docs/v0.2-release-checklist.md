# v0.2.0 Release Checklist

> v0.2.0 is the first public Persatrix release. This checklist is the pre-tag gate for release-prep PRs 10-12.

---

## 1. Pre-release Verification

- [ ] `make test` completes cleanly on a clean checkout
- [ ] `make lint` completes cleanly on a clean checkout
- [ ] `make validate` completes cleanly on a clean checkout
- [ ] Proto staleness check: run `make proto` and confirm `git diff --exit-code`
- [ ] Docker smoke verification completed with `make docker-build` and `make docker-up`
- [ ] Cost summary endpoint check completed against a configured orchestrator: `GET /api/v1/cost/summary`

### Verification notes

- Run these commands from a clean checkout of `main` after PRs 1-10 are merged.
- If the cost summary endpoint returns `503` with `cost tracking is not configured`, restart the orchestrator with the config directory (`--config config/`) rather than a single file path.
- If agent startup fails on a fixed port during manual verification on Windows, retry with port `0` so the runtime selects a free port.

## 5. Tag And GitHub Release Procedure

Run these steps only after PR 12 merges and `main` is green.

```bash
git checkout main
git pull --ff-only origin main
git tag -a v0.2.0 -m "v0.2.0 - Persona Core"
git push origin v0.2.0
```

Then create the GitHub Release from `v0.2.0`.

- [ ] Annotated tag `v0.2.0` created from the final release commit on `main`
- [ ] Tag pushed to `origin`
- [ ] GitHub Release draft uses the curated v0.2.0 changelog section
- [ ] Release notes include upgrade notes and known limitations
- [ ] Optional artifacts attached or linked if produced (`bin/persatrix-server`, CLI binary, container references)

## 6. Known Gaps To Call Out In Release Notes

These are intentional gaps or TODO-heavy areas that should not be presented as released v0.2.0 functionality.

| Area | Path | Release-note guidance |
|------|------|-----------------------|
| Resilience | `internal/resilience/` | Still a TODO stub; circuit breaker, retry policy, fallback chain, and DLQ are deferred beyond v0.2.0 |
| A2A | `internal/a2a/` | Agent-to-agent networking is not shipped in v0.2.0 |
| Mesh | `internal/mesh/` | Multi-node routing and migration remain future work for later versions |
| Bridges | `internal/bridges/` | External Slack/Discord/Telegram/email bridges are not shipped |
| Channels | `internal/channels/` | Full internal channel manager and routing layer are not shipped as a public feature yet |
| Security | `internal/security/` | Advanced permission gates, rate limiting, audit logging, and sanitization remain future work |
| Telemetry | `internal/telemetry/` | OTEL instrumentation is still a TODO stub; no dedicated telemetry RFC is implemented yet |

Additional release-note callouts:

- `internal/state/` still uses in-memory runtime state; durable orchestrator-side persistence is not complete.
- `internal/server/` exposes the cost summary endpoint, but callers must start the orchestrator with the config directory so cost tracking is loaded.
- Persona runtime activity may emit non-fatal FTS5 fallback warnings on punctuation-heavy memory queries; these should be described as non-blocking if still present at release time.

- [ ] Release notes include each relevant gap above
- [ ] No TODO-heavy subsystem is described as production-complete if its package is still a stub
