# v0.3.4 plan amendment — 2026-05-27 — Knob-free, config-driven provider selection

> Status: amendment to [v0.3.4-plan.md](v0.3.4-plan.md) and the
> [2026-05-24 provider-parity amendment](v0.3.4-plan-amendment-2026-05-24.md).
> Driver: a review during release-prep PR 2 (the provider-neutral onboarding
> pass) found that the *mechanism* for selecting a provider was not itself
> provider-neutral. RFC: [0033 — Provider-Agnostic Model Alias Layer](rfcs/0033-model-alias-layer.md).

## Context

The offline ([#422](https://github.com/mkhomutov/Persatrix/pull/422)) and Ollama
([#423](https://github.com/mkhomutov/Persatrix/pull/423)) providers shipped with
**global env force-knobs** — `PERSATRIX_OFFLINE=1` / `PERSATRIX_OLLAMA=1` — that
the factory checked *before* alias resolution and that overrode every agent's
configured provider. Anthropic and OpenAI, by contrast, are selected the
standard way: by the `provider` field on a model alias. So the four providers
were **not** chosen uniformly — two by a config alias, two by an env knob — and
there was no equivalent knob for OpenAI, which is why `make demo-openai` had no
natural shape.

This contradicts the release's own theme. *"Any Model, Any Provider"* and *"a
provider swap is a one-line edit"* are about a single, uniform selection
mechanism. Two of the four providers bypassing that mechanism via env flags is
the same single-vendor-assumption smell the
[2026-05-24 amendment](v0.3.4-plan-amendment-2026-05-24.md) set out to remove,
one layer down. This amendment removes the knobs so provider selection is
**purely config/alias-driven** for all four providers — consistent with the
pre-1.0 *prefer-evolvable-over-back-compat* stance, since the alias layer is
itself the clean refactor and the knobs never shipped in a tagged release.

## What changes

| # | Before | After |
|---|--------|-------|
| 1 | `create_provider` checks `PERSATRIX_OFFLINE` / `PERSATRIX_OLLAMA` (and a pre-resolve `provider: mock` special case) *before* alias resolution and force-routes every agent. | Those checks are removed. A provider is chosen **only** by the resolved `provider` field; `mock` and `ollama` are first-class alias providers dispatched through the same factory branch as `anthropic` / `openai`. |
| 2 | `OllamaProvider` carried a `force_model` substitution + `warn_if_forced_base_url_override`, used only by the forced path. | Removed. The factory resolves the physical model and threads it through like every other provider. `PERSATRIX_OLLAMA_MODEL` survives only as an optional model *configuration* override for ollama-routed agents (it keeps the demo's `ollama-pull` and the agents in lock-step) — not a selection knob. |
| 3 | `make demo-offline` / `make demo-ollama` set env knobs + a throwaway `ANTHROPIC_API_KEY` to satisfy the compose `:?` guard; no `make demo-openai`. | Each `make demo-*` mounts a per-provider alias config (`config/demo/optimization.{offline,ollama,openai}.yaml`) over the stack's `optimization.yaml` via a Compose overlay. No env knob, no throwaway key. `make demo-openai` is added on equal footing. |
| 4 | `docker-compose.yaml` plumbed only `ANTHROPIC_API_KEY` and hard-guarded it with `:?`. | Every provider key (`ANTHROPIC_API_KEY` / `OPENAI_API_KEY`) is plumbed into each agent optionally; the single-vendor `:?` guard is dropped. A config-only swap to a cloud-OpenAI alias authenticates in stock Docker (closes [MT execution report F-5](manual-tests/v0.3.4-execution-report.md#follow-ups)); an unset key for the configured provider logs a clear startup warning (`agents/llm_factory.py`) instead of failing first-run for everyone. |

None of this changes RFC 0033's resolver mechanics — the resolver already
treated `mock` / `ollama` as first-class providers (locality + pricing-guard
exemption). It removes the *bypasses* around the resolver so the resolver is the
single selection path.

## Relationship to the merged PR 1 MT execution report

The [v0.3.4 MT execution report](manual-tests/v0.3.4-execution-report.md)
([#439](https://github.com/mkhomutov/Persatrix/pull/439)) verified `MT-OFFLINE-001`
/ `MT-OLLAMA-001` live using the `PERSATRIX_OFFLINE` / `PERSATRIX_OLLAMA` knobs
and noted F-5 (the missing `OPENAI_API_KEY` plumbing). Those rows' **outcomes**
(offline $0 round-trip; Ollama real-tokens-$0-cloud; alias-routed cost on
`MT-ALIAS-001` / `MT-ALIAS-002`) are unchanged by this refactor — only the
*activation path* changes (an alias config the overlay mounts, instead of an env
flag), and F-5 is now closed by item 4. The live re-verification of the
config-driven demo paths is the
[release-prep PR 4 Docker smoke](v0.3.4-release-prep-plan.md#pr-4--final-pre-tag-verification--release-notes)
(alias-routed + one-line swap + offline + Ollama + `demo-openai`). The MT recipes
([`MT-OFFLINE-001`](manual-tests/MT-OFFLINE-001.md) / [`MT-OLLAMA-001`](manual-tests/MT-OLLAMA-001.md))
are updated to the config-driven activation as part of that re-verification.

## Acceptance additions

Append to [§Acceptance for v0.3.4](v0.3.4-plan.md#acceptance-for-v034), under the
**Provider parity** group:

- **One selection mechanism for all four providers.** `anthropic` / `openai` /
  `ollama` / `mock` are chosen only by the resolved alias `provider` field; no
  global env force-knob selects a provider. A removed-knob env var has no effect
  on routing (unit-asserted).
- **Demos are alias configs.** `make demo-offline` / `make demo-ollama` /
  `make demo-openai` each select their provider by mounting a per-provider alias
  config — verified live in the PR 4 Docker smoke.
