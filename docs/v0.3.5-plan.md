# v0.3.5 Plan — Session-Scoped Memory

**Status**: 🚧 Planning
**Target version**: v0.3.5 (RFC 0031 Phases 2–4 — the F-3 root-cause fix)
**Created**: 2026-05-28
**Branch prefix**: `feature/v035-`
**Target**: `main`
**Merge strategy**: Squash merge per [BRANCHING.md](BRANCHING.md)
**Codename**: *Session-Scoped Memory* (proposed — maintainer owns the final codename)

**Goal**: orchestrate v0.3.5 end-to-end. One user-facing story: **persona-memory recall becomes session-scoped** — a run reads only its own session, so it is isolated by choosing a session rather than `make reset`. This closes the **F-3** cross-run *recall* bleed; auto-isolating a *same-named* rerun is the **`epoch`** axis ([ISSUE-0085](issues/ISSUE-0085-epoch-axis-run-isolation.md)), folded into v0.3.5 as [Phase 3b](#phase-3b--rfc-0031-epoch-axis-issue-0085) — the *structural* half of the F-3 fix (maintainer scope decision 2026-05-31).

The umbrella RFC is [RFC 0031](rfcs/0031-per-session-namespacing-channels.md) (Per-Session Namespacing for Channels and Persona Memory). Phase 1 (the `sessions` table + `session_id` columns + `PERSATRIX_SESSION_ID` write-path threading) shipped in v0.3.1; v0.3.5 carries **Phases 2–4**:

- **Phase 2 — recall filtering** (the F-3 closer): default recall becomes session-scoped; cross-session recall is an explicit opt-in. Drafted in [`0031-phase2-pr-plan.md`](rfcs/0031-phase2-pr-plan.md).
- **Phase 3 — operator CLI**: `persatrix session new / use / list / archive / current`, the active-session pointer file, and `--session` on `chat` / `channel`. PR plan authored in this release.
- **Phase 4 — operator docs + closeout**: `docs/guides/sessions.md`, the `make reset` deprecation breadcrumb, and the [ISSUE-0051](issues/ISSUE-0051-per-session-memory-namespacing-channels.md) close-out.

**Out of scope** — not part of this story:

- [RFC 0033](rfcs/0033-model-alias-layer.md) **Phase 3** (raw-ID pass-through removal, `_infer_provider` retirement, schema bump to `"0.3"`). Gated on the `persatrix.llm.alias.raw_id_usage` counter reading zero in dogfood — observed state, not a date. A *different* story ("every model is an alias"), so it does not bundle in by default; see [§Conditional co-resident](#conditional-co-resident--rfc-0033-phase-3) for the ride-along condition and cleanup issues.
- [RFC 0030](rfcs/0030-multi-agent-conversation-governance.md) Phase 1, [RFC 0034](rfcs/0034-persona-conversational-working-memory.md) Phases 2–3, [RFC 0039](rfcs/0039-user-accounts-authentication.md) — `v0.3.x` candidates not on this contract.

## Amendment — scope-axes reframing

A post-Phase-2 review reframes session as room-continuity and moves run/test isolation to a new **epoch** axis (detail: [Memory Scope Axes](memory-scope-axes.md)); **what shipped stands** (Phase 2 closed the F-3 *recall* bleed). The reframing's three successors, dependency-ordered (no calendar):

1. **[ISSUE-0083](issues/ISSUE-0083-session-binding-sender-axis-fragments-multiparty-rooms.md)** — drop the sender axis (`(agent, channel, user)` → `(agent, channel)`). ✅ **Resolved 2026-05-30**, before Phase 3 PR 4 (channel-store schema v5).
2. **[ISSUE-0085](issues/ISSUE-0085-epoch-axis-run-isolation.md)** — add the `epoch` run/test-isolation axis; **after 0083.** **In scope for v0.3.5** (maintainer decision 2026-05-31): the *full* axis gates the release — it is the **structural** half of the F-3 fix (Phase 2 closed only the *recall* half). Sequenced as [Phase 3b](#phase-3b--rfc-0031-epoch-axis-issue-0085) with its own [PR plan](rfcs/0031-epoch-pr-plan.md).
3. **[ISSUE-0084](issues/ISSUE-0084-fact-scope-by-subject-not-uniform-session.md)** — fact scope by subject; **independent, deferred beyond v0.3.5** (low-severity continuity refinement, not a leak).

Both sequencing decisions are now **settled**: 0083 landed before PR 4; the epoch-operator-surface question (Phase 3 vs sibling phase, flagged in the [Phase 3 plan amendment](rfcs/0031-phase3-pr-plan.md#amendment--scope-axes-reframing)) is **resolved** — epoch ships as its own phase (3b) with an operator surface, and the `make reset` framing redirects at epoch rather than `session new --activate`.

## Why this plan exists

Three reasons RFC 0031 Phases 2–4 deserve an umbrella plan rather than a bare PR-plan execution:

1. **F-3 is still open after Phase 1.** Phase 1 (v0.3.1) tags every write with a `session_id`, but every read still surfaces every session's rows by design ([RFC §Phase 1](rfcs/0031-per-session-namespacing-channels.md#phase-1-sessions-table-column-additions-default-session-plumbing)). The plan makes "F-3 reproduction shows no carryover" a release-level gate so the half-finished state isn't mistaken for the fix.

2. **The fix must not break the dementia test.** Session-scoped recall and long-arc continuity are in tension; [OQ #1 resolution 1a](rfcs/0031-per-session-namespacing-channels.md#open-questions) (the arc shares one session id) reconciles them only if Phase 2's dementia-test bridge proves it — so the plan gates on that proof.

3. **Phase 3 needs a PR plan; Phase 4 closes a tracked issue.** Phase 2 is drafted in [`0031-phase2-pr-plan.md`](rfcs/0031-phase2-pr-plan.md); Phase 3 (operator CLI) needs its PR plan authored; Phase 4 carries the [ISSUE-0051](issues/ISSUE-0051-per-session-memory-namespacing-channels.md) close-out. Sequencing the three phases (intra-RFC ordering) is what an umbrella owns.

## Acceptance for v0.3.5

The promise — *recall is session-scoped; a run reads only its own session and is isolated by choosing that session* — is met when:

- **Default recall is session-scoped** across all four tiers (`episodes`, `relationships`, `facts`, `notes`) — active session plus the always-visible `legacy` carve-out; cross-session recall is the explicit `sessions=[…]` / `sessions="*"` opt-in per [RFC §D](rfcs/0031-per-session-namespacing-channels.md#d-recall-semantics). (Notes gained their `session_id` column in [Phase 2 PR 1](rfcs/0031-phase2-pr-plan.md#pr-1-featurev035-rfc0031p2-notes-coverage--notes-tier-session-coverage).)
- **F-3 reproduction shows no carryover** — re-running the [v0.3.0 F-3 repro](v0.3.0-test-findings-pr-plan.md) with the same channel name + `--user` under a new `PERSATRIX_SESSION_ID` surfaces none of the prior run's participants, topics, or facts.
- **The dementia test still passes** — [MT-MEMORY-005](manual-tests/MT-MEMORY-005-dementia-test.md) under one session id preserves continuity, a second does not bleed; `tests/integration/test_session_continuity.py` is the regression pin.
- **The operator surface exists** — `persatrix session new / use / list / archive / current`; the active-session pointer resolves per [RFC §E](rfcs/0031-per-session-namespacing-channels.md#e-operator-surface); `--session` overrides it on `persatrix chat` / `persatrix channel …`.
- **`make reset` kept**; **`docs/guides/sessions.md` ships**; [ISSUE-0051](issues/ISSUE-0051-per-session-memory-namespacing-channels.md) closed at the Phase 4 close-out. (The make-reset framing is **redirected at the epoch axis** by Phase 3b, superseding the Phase 4 `session new --activate` breadcrumb — a continuity room is not a clean slate.)
- **Same-named-rerun isolation works — the structural half of F-3** ([ISSUE-0085](issues/ISSUE-0085-epoch-axis-run-isolation.md), [Phase 3b](#phase-3b--rfc-0031-epoch-axis-issue-0085)): default recall and writes carry `epoch_id` (default `live`, strict equality, **no carve-out, no `"*"`**) across all five persona-memory tiers; a rerun reusing `--user alice` under a fresh `PERSATRIX_EPOCH` inherits none of the prior run's episodes, relationships, *or* person-facts — the bleed a fresh channel name alone cannot cure. `tests/integration/test_epoch_run_isolation.py` is the gate.

Out of acceptance: RFC 0033 Phase 3 (observed-traffic gated — see [§Conditional co-resident](#conditional-co-resident--rfc-0033-phase-3)); RFC 0030 Phase 1; RFC 0034 Phases 2–3; RFC 0039; [ISSUE-0084](issues/ISSUE-0084-fact-scope-by-subject-not-uniform-session.md) (fact-scope-by-subject — deferred beyond v0.3.5).

## Phase 3b — RFC 0031 epoch axis (ISSUE-0085)

**Branch prefix**: `feature/v035-issue0085-` / `feature/v035-epoch-`
**Goal**: ship the **structural** half of the F-3 fix — the `epoch` run/test-isolation axis ([ISSUE-0085](issues/ISSUE-0085-epoch-axis-run-isolation.md)) — executing [`docs/rfcs/0031-epoch-pr-plan.md`](rfcs/0031-epoch-pr-plan.md). Phase 2 stopped cross-run *reads* (session-scoped recall); this phase resets the underlying *state* so a rerun reusing `--user alice` under a fresh epoch inherits nothing — the bleed a fresh channel name alone leaves in the participant-keyed relationship/person-fact tiers. Modelled on the shipped `principal_id` axis: strict equality, no `legacy` carve-out, no `"*"` sentinel, `epoch_id` in the `relationships` primary key, on the same task-local contextvar + gRPC-header rail. Default `live`; production never changes it, CI bumps it per job. `make reset` stays the nuke; the operator-guide framing is **redirected at epoch** (superseding the Phase 4 `session new --activate` breadcrumb, which the reframing established is wrong).

**Why folded into v0.3.5** (maintainer decision 2026-05-31): F-3 is the load-bearing motivation of RFC 0031, and Phase 2 closed only its recall half. Shipping v0.3.5 with the structural half deferred would leave "isolate a rerun" still meaning `make reset` (volume wipe) rather than choosing an epoch — so the release gates on the full axis. This also resolves the [Phase 3 plan's open epoch-operator-surface decision](rfcs/0031-phase3-pr-plan.md#amendment--scope-axes-reframing) (epoch gets a surface).

**Acceptance**:

- All six PRs in [`0031-epoch-pr-plan.md`](rfcs/0031-epoch-pr-plan.md) merged (leaf → migration v12 + channel-store v6 → filter + per-tier wiring → gRPC rail → operator surface → closeout).
- `make test` passes; a row written under one epoch is invisible under another across all five persona-memory tiers; default-epoch (`live`) behaviour is byte-identical to pre-migration (single-world deployments unchanged).
- `epoch_id` is in the `relationships` primary key (an `ON CONFLICT` upsert under two epochs creates two rows, never bleeds trust); the strict-equality predicate has **no carve-out and no `"*"`** (AST-pinned in the leaf, predicate-pinned in the filter).
- `tests/integration/test_epoch_run_isolation.py` proves the structural F-3 fix: a rerun under a fresh `PERSATRIX_EPOCH` surfaces none of the prior run's episodes, relationships, or person-facts.
- The orchestrator emits `persatrix-epoch` per request (string-matching `agents.epoch_id.EPOCH_METADATA_GRPC_KEY`); the `channel.dispatch` span carries the resolved epoch (low-cardinality-on-span, per OQ #7).
- `make reset` operator-guide framing redirected at epoch; [ISSUE-0085](issues/ISSUE-0085-epoch-axis-run-isolation.md) closed at the Phase 3b close-out; RFC 0031 / [Memory Scope Axes](memory-scope-axes.md) status refreshed.

## Risk and mitigations

The per-PR implementation risks live in the [Phase 2 PR plan §Risk table](rfcs/0031-phase2-pr-plan.md#risk-and-mitigations). The release-level risks:

| Risk | Mitigation |
|------|------------|
| Session-scoped default recall silently breaks the dementia test (the OQ #1 tension). | OQ #1 resolution 1a + the Phase 2 dementia-test bridge: the arc shares one session id, so single-session default recall **is** the dementia-test path; `test_session_continuity.py` is the executable proof. |
| `sessions="*"` (cross-session debug recall) wired into a prompt context re-introduces F-3 against the fix being shipped. | The `"*"` sentinel is CLI/debug-only; the persona-runtime context path is pinned never to reach it. Phase 3 surfaces it only via the explicit `persatrix memory recall --all-sessions` flag. |
| Scope creep: RFC 0033 Phase 3 or the candidate fold-ins quietly expand the release past one story. | [§Candidate fold-ins](#candidate-fold-ins-maintainer-decision) and [§Conditional co-resident](#conditional-co-resident--rfc-0033-phase-3) make every addition an explicit maintainer opt-in; default is RFC 0031 alone. |
