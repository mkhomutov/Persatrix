# v0.4.0 Plan — Agent Organizations (define a team, lab or company with roles and hierarchy, and let it reason toward a decision)

**Status**: ⬜ Plan PR open
**Target version**: v0.4.0 (the organizations release — the first of the v0.4 line)
**Created**: 2026-10-20
**Branch prefix**: `feature/v040-`
**Target**: `main`
**Merge strategy**: Squash merge per `docs/BRANCHING.md`
**Codename**: *Agent Organizations*

**Goal**: Today every speaker counts the same to a persona, a persona has no
role, and nothing it chooses is kept as a decision. v0.4.0 lets an operator
define an organization — roles, a topology, who directs whom
([RFC 0012](rfcs/0012-protocols-organizations.md) Phases 1–3) — and lets a
persona weigh a directive by where it came from and decide through an
auditable decision engine, with a human approving the actions that need one
([RFC 0028](rfcs/0028-agent-decision-policy-engine.md) Phases 1, 2 and 2a).
Underneath it builds what those phases name: a society store
([RFC 0029](rfcs/0029-personal-society-storage-split.md) Phase 3), the
commitments tier ([RFC 0021](rfcs/0021-persona-temporal-awareness.md)
Phase 2), and agent capability tokens with an approval queue
([RFC 0009](rfcs/0009-security-sandboxing.md) Phases 3–4), checked on the
agents' own calls, which closes
[ISSUE-0152](issues/ISSUE-0152-one-quarantine-refuses-every-anonymous-caller.md),
[ISSUE-0140](issues/ISSUE-0140-agent-fleet-401-on-roster-fetch-under-auth.md)
and [ISSUE-0117](issues/ISSUE-0117-agent-ingress-close-knob.md).

Scope was ratified by `docs/v0.4.x-sequencing.md`
§[Amendment 2026-10-18 — v0.4.0's shape](v0.4.x-sequencing.md#amendment-2026-10-18--v040s-shape-its-prerequisites-its-cuts-and-the-end-of-the-v03x-line),

## The goal audit and the first strategy review

Ruling (g) asks how the release serves the goal, a society of AI agents that
works on hard tasks for as long as they take. Such a society needs structure
that outlasts one conversation: who may direct whom (RFC 0012), choices
recorded with a human approving the risky ones (RFC 0028), promises kept
across sessions (RFC 0021), and identities nobody can forge (RFC 0009). The
on-ramp serves it indirectly, which is why each item is cuttable.

The goal needs things this list lacks, proposed here and added only by an
amendment: RFC 0021 Phase 3, since a commitment that never fires a reminder is
inert; [ISSUE-0186](issues/ISSUE-0186-persona-memory-has-no-capacity-bound.md),
since a persona that lives for months reaches a memory bound nobody set;
ISSUE-0161, since a stalled autonomous turn stops a society meant to keep
working; and the [RFC 0027](rfcs/0027-reflection-driven-consolidation.md)
reflection engine. Whether a society keeps going where one agent stalls is
EXP-002's question.

The first strategy review is held with this plan's opening, in
[strategy §10](project-strategy.md#10-review-cadence-and-log) (ruling r). It
re-ran the evidence, re-verified the four reviews' findings, recorded that no
decision rule has fired, and made two rulings for the amendment that acts on
it to ratify: the goal replaces the product reading, and §4's licence default
applies.

## Acceptance

The release ships when **all** hold:

- **An organization is defined and loaded** — `config/organizations.yaml`
  passes `make validate` and loads into the society tables; a cycle or a second
  manager fails validation.
- **A directive is weighed by where it came from** — the accept / adapt /
  refuse evaluation runs at RFC 0028's pre-act checkpoint, a conflict resolves
  by `directs` precedence, a tie defers, and each outcome is a
  `DecisionRecord` with its reason.
- **An action that needs a human waits for one** — it is held, released only
  by a signed, scoped, expiring approval token that survives an orchestrator
  restart, and refused on replay.
- **ISSUE-0152, ISSUE-0140 and ISSUE-0117 are closed** — under
  `auth.mode: enabled` every agent route takes a valid token or the account
  role it needed before, an invented agent id cannot shut out anonymous
  callers, and the fleet fetches its roster; each with its regression test.
- **No migration lands after its consumer** — the society tables (A1),
  `channels.authority` (C2) and `commitments` (A2), each ahead of its reader,
  the society tables only after the benchmark passes.
- **The live arc passes** — `MT-ORG-AUTHORITY-001` on a live provider, the
  report recording verbatim:
  1. the manager's directive accepted and the peer's refused — both
     `DecisionRecord`s with their reasons, since a reply that merely complies
     does not show which rule decided;
  2. the tie escalated — the deferred record with `reason=authority_tie`;
  3. a held action released only by its token — the audit events from
     requested to approved, and the replayed token refused;
  4. a forged agent id refused — the refusal and its audit line.
- **With no organization and `auth.mode: disabled`, a v0.3.16 deployment
  behaves as before** — `make eval-replay` and the offline demo unchanged.
- **The coherence trade is stated, not discovered** — the release notes say
  that under `auth.mode: enabled` a fleet needs the enrollment secret to
  register, and re-registers after every orchestrator restart.
- **Every gate is green on the tag PR's head** — `make release-sweep RUN=1
  OPTIONAL=1`, plus the new suites under `internal/protocols/`,
  `agents/decision/` and the commitments tier.

## Implementation PRs

Order — each edge an RFC's own dependency: R1 and R2 before their phases;
A1's benchmark before any society table; A1 before A4, B3 and C1, whose data
lives there; A3 before A4; A2 before C2; B1 → B2 → B3; A4 before B3, whose
tokens release A4's pending approvals; C1 → C2 → C3, with A4 and B3 before C3.
The D rows have no edge with the core; D4 shares emission files with B1, so
whichever merges second rebases. Each PR plan settles its phase's open
questions from the defaults recorded on 2026-10-18.

- **A1** — Design: the RFC 0029 amendment. **Scope**: the benchmark, then the
  society-store interface and its tables in `data/channels.db`. **Migration**:
  channels store.
- **A2** — Design: RFC 0021 Phase 2 with RFC 0012 §E's fields. **Scope**:
  `agents/memory/commitments.py`, its tools, permissions and prompt block.
  **Migration**: memory store.
- **A3, A4** — Design: RFC 0009 Phases 3–4, open questions 9 and 10.
  **Scope**: argument schemas and resource limits; then tokens at
  registration, REST validation, the enrollment secret, the approval queue,
  and ISSUE-0152's steps 1–3 as one early Go PR. **Tests**: a forged id and a
  missing token refused on each route.
- **B1–B3** — Design: RFC 0028 §D–§H. **Scope**: `agents/decision/`, the
  checkpoints, the decision log; scoring and approval routing; the
  required-HITL registry and orchestrator-issued tokens with a persisted key
  and nonce record. Manual mode first, as RFC 0028 directs.
- **C1–C3** — Design: RFC 0012 §B–§F, less §G's clearance check and §H.
  **Scope**: `config/organizations.yaml` and its schema,
  `internal/protocols/`, the persona's role, a new organizations guide; the
  channel authority field and the two-factor rule; the evaluation at the
  checkpoint, and org-graph changes as a required-HITL class. **Migration**:
  C2's `channels.authority`.
- **D1–D4** — each as its RFC is written, under the cut clause. D4 starts from
  the drafts [#754](https://github.com/mkhomutov/Persatrix/pull/754) and
  [#755](https://github.com/mkhomutov/Persatrix/pull/755); D3 leaves the CLI
  out.

### Upgrade Notes

1. **Migrations** — the channels store gains the society tables and
   `channels.authority`; each memory store gains `commitments`. Forward only.
2. **Agent enrollment** — under `auth.mode: enabled`, set the fleet enrollment
   secret before upgrading; an agent without it cannot register, and agents
   re-register after an orchestrator restart.
3. **New configuration** — `config/organizations.yaml` and a channel
   `authority` field, both optional.
4. **What stays byte-identical** — a deployment with no organization and
   `auth.mode: disabled`.

### Known Gaps

| Gap | Owner | Bound |
|-----|-------|-------|
| The society backend is single-node SQLite | RFC 0029 | the benchmark; Postgres by amendment |
| The token key changes on every restart | RFC 0009 Phase 4 | a stale token is refused; the fleet re-registers |
| Role clearance is unchecked; egress above a channel's class is logged, not held | RFC 0012 §G, §H | RFC 0037's tripwire still logs it |
| Decision records are runtime-local | RFC 0028 §D | RFC 0029 Phase 5 stays unslotted |
| A commitment never fires a reminder | RFC 0021 Phase 3 | proposed by the goal audit |

## Risks

| Risk | Mitigation |
|------|------------|
| v0.4.0 is larger than any v0.3.x release, at about 40–55 core PRs. | Four cuttable rows under one clause; a PR plan before code; an amendment can split the release. |
| SQLite cannot hold the society tables. | The benchmark runs first. |
| Token checks break the fleet under auth. | A4 tests every route with and without a token; `MT-AUTH-001` v1.1; the Upgrade Notes. |
| The live arc passes while exercising nothing. | The peer's instruction contradicts the manager's, and the driver checks each `DecisionRecord`'s reason, not the reply text. |
| Hot files near 500 lines (`agents/base.py`, `prompt_assembly.py`, `memory_context.py`, `internal/server/server.go`). | Split at a real seam when a PR edits one (ruling e); 800 lines fails CI. |
