# v0.4.0 Plan — Agent Organizations (define a team, lab or company with roles and hierarchy, and let it reason toward a decision)

**Status**: 🔄 Phase 1 — implementation PRs (R1–R2 merged)
**Target version**: v0.4.0 (the organizations release — the first of the v0.4 line)
**Created**: 2026-10-20
**Branch prefix**: `feature/v040-`
**Target**: `main`
**Merge strategy**: Squash merge per `docs/BRANCHING.md`
**Codename**: *Agent Organizations*

**Goal**: Today every speaker counts the same to a persona, and nothing it
chooses is kept as a decision. v0.4.0 lets an operator define an organization
([RFC 0012](rfcs/0012-protocols-organizations.md) Phases 1–3), and lets a
persona weigh a directive by where it came from and decide through an
auditable decision engine, with a human approving what needs one
([RFC 0028](rfcs/0028-agent-decision-policy-engine.md) Phases 1, 2 and 2a).
Underneath: a society store
([RFC 0029](rfcs/0029-personal-society-storage-split.md) Phase 3), the
commitments tier ([RFC 0021](rfcs/0021-persona-temporal-awareness.md)
Phase 2), and agent capability tokens with an approval queue
([RFC 0009](rfcs/0009-security-sandboxing.md) Phases 3–4) on the agents' own
calls, which closes
[ISSUE-0152](issues/ISSUE-0152-one-quarantine-refuses-every-anonymous-caller.md),
[ISSUE-0140](issues/ISSUE-0140-agent-fleet-401-on-roster-fetch-under-auth.md)
and [ISSUE-0117](issues/ISSUE-0117-agent-ingress-close-knob.md).

Scope was ratified by `docs/v0.4.x-sequencing.md`
§[Amendment 2026-10-18 — v0.4.0's shape](v0.4.x-sequencing.md#amendment-2026-10-18--v040s-shape-its-prerequisites-its-cuts-and-the-end-of-the-v03x-line),

## The goal audit and the first strategy review

Ruling (g) asks how the release serves the goal, a society of AI agents that
works on hard tasks for as long as they take. It needs structure that outlasts
one conversation: who may direct whom (RFC 0012), recorded choices with a human
approving the risky ones (RFC 0028), promises kept across sessions (RFC 0021),
and identities nobody can forge (RFC 0009). The cuttable rows serve it
indirectly.

The goal needs more, proposed here and added only by an amendment: RFC 0021
Phase 3, since a commitment that never fires a reminder is inert;
[ISSUE-0186](issues/ISSUE-0186-persona-memory-has-no-capacity-bound.md), since
a persona that lives for months reaches a memory bound nobody set; ISSUE-0161,
since a stalled autonomous turn stops a society meant to keep working; [ISSUE-0157](issues/ISSUE-0157-persona-calls-share-one-workflow-budget.md)
and [ISSUE-0156](issues/ISSUE-0156-standing-timer-unbounded.md), since three
personas on stock budgets stop at about $10 of calls per orchestrator process,
and that budget is all that stops a runaway standing timer; and the
[RFC 0027](rfcs/0027-reflection-driven-consolidation.md) reflection engine.
ISSUE-0182 was weighed and is not proposed: it saves cost, which the goal does
not need.

The first strategy review is logged in
[strategy §10](project-strategy.md#10-review-cadence-and-log) (ruling r).

## Acceptance

The release ships when **all** hold:

- **An organization is defined and loaded** — `config/organizations.yaml`
  passes `make validate` and loads into the society tables; in a hierarchy, a
  cycle or a second manager fails validation.
- **A directive is weighed by where it came from** — the accept / adapt /
  refuse evaluation runs at RFC 0028's pre-act checkpoint, a conflict resolves
  by `directs` precedence, a tie defers, and each outcome is a
  `DecisionRecord` with its reason.
- **An action that needs a human waits for one** — it is held, released only
  by a signed, scoped, expiring approval token that survives an orchestrator
  restart, and refused on replay.
- **ISSUE-0152, ISSUE-0140 and ISSUE-0117 are closed** — under
  `auth.mode: enabled` each route an agent calls admits what the issues'
  2026-10-18 defaults set: an agent token (on recall, only for the persona the
  path names), the enrollment secret at registration, or the account role the
  route would need without the carve-out; in either mode an invented agent id
  cannot shut out anonymous callers; the fleet fetches its roster; each with
  its regression test.
- **No migration lands after its consumer** — the society tables (A1),
  `channels.authority` (C2) and `commitments` (A2), each ahead of its reader,
  the society tables only after the benchmark passes.
- **The live arc passes** — `MT-ORG-AUTHORITY-001` on a live provider, the
  report recording verbatim:
  1. the manager's directive accepted and the peer's refused — both
     `DecisionRecord`s with their reasons and issuing rooms, since a reply that
     merely complies does not show which rule decided;
  2. the tie escalated — the deferred record with `reason=authority_tie`;
  3. a held action released only by its token — the audit events from
     requested to approved, and the replayed token refused;
  4. a forged agent id refused — the refusal and its audit line.
- **With no organization and `auth.mode: disabled`, only the named changes
  show** — against v0.3.16: the `[Unreleased]` changes, A2's commitments tools,
  nudge and prompt block, D2's section if taken, and agents' ids on REST calls.
  `make eval-replay` pins the rest: A2 and D2 re-record the goldens once,
  naming the request hashes that moved; every other PR replays them unchanged.
- **The coherence trade is stated, not discovered** — the release notes carry
  Upgrade Notes 2 and 4.
- **Every gate is green on the tag PR's head** — `make release-sweep RUN=1
  OPTIONAL=1`, plus the new suites under `internal/protocols/`,
  `agents/decision/` and the commitments tier.

## Implementation PRs

Phase 3 plan; each R row before its phases; A1 before A4, B3 and C1, whose data
lives there; A3 before A4; A2 before C2; B1 → B2 → B3; A4 before B3, whose

B2 before D1. No core row waits on a D row; D4 shares emission files with B1,
so whichever merges second rebases. Each PR plan settles its phase's open
questions by the 2026-10-18 default where one exists, otherwise by a new

### Upgrade Notes

1. **Migrations** — the channels store gains a channel-time index, society
   tables and `channels.authority`; each memory store gains `commitments`.
   Forward only.
2. **Agent enrollment and the closed carve-out** — under `auth.mode: enabled`,
   set the fleet enrollment secret before upgrading; an agent without it cannot
   register, and agents re-register after an orchestrator restart. Anonymous
   channel reads and publish, the CLI's `channel send` included, need a
   sign-in; deregistration and convene need the operator role.
3. **New configuration and wire fields** — `config/organizations.yaml`, a
   channel `authority` (unset reads `observed`) and `dm_default_authority`,
   the commitments prompt budget, `hitl.enabled`, `resource_limits` and the
   decision policy settings; under `auth.mode: disabled`,
   `SECURITY_APPROVAL_SECRET`, without which nothing can be approved; additive
   `authority` and `org_graph_version` fields on `ChannelMessageEvent`, which
   older receivers ignore; the agent token in the registration response; new
   audit events, and decision metrics for agents that record decisions.
4. **What else changes** — the `[Unreleased]` notes since v0.3.16 ride into
   `[0.4.0]`; with no organization and `auth.mode: disabled`, only the
   differences Acceptance names.
