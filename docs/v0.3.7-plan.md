# v0.3.7 Plan — Conversations Worth Watching (realism: addressing + group working memory)

**Status**: 📋 Proposed
**Target version**: v0.3.7 (conversation realism — the first rung of the [usefulness ladder](v0.3.x-sequencing.md#the-usefulness-ladder))
**Created**: 2026-06-04
**Branch prefix**: `feature/v037-`
**Target**: `main`
**Merge strategy**: Squash merge per [BRANCHING.md](BRANCHING.md)
**Codename**: *Conversations worth watching* (proposed — maintainer owns the final codename)

**Goal**: orchestrate v0.3.7 end-to-end. One user-facing story: **a group channel reads like colleagues, not bots** — several personas see and build on the running transcript, the *right* people speak, and a question aimed at one persona is not answered by everyone. This is the realism rung that must land before usefulness (v0.3.8 brainstorm convergence) and before v0.4.0 organizations, per the [2026-06-04 sequencing amendment](v0.3.x-sequencing.md#amendment-2026-06-04--re-sequence-the-v03x-tail-for-conversation-realism--usefulness-ahead-of-v040).

Three workstreams, one release contract:

- **RFC 0034 Phase 2 — group-channel working memory** (the critical path). Extend the [Conversation Window](rfcs/0034-persona-conversational-working-memory.md) (shipped for DM channels in v0.3.1) to multi-peer channels: per-peer role mapping and the `[<peer_id>]: ` inline prefix so a persona sees *who said what* this round and can build on it. Without this, relevance judgment and "build on the transcript" have no substrate. Owned by [`0034-phase2-pr-plan.md`](rfcs/0034-phase2-pr-plan.md) (Phase 1 deliverable of this plan).
- **RFC 0030 relevance gate — Tier A eligibility + disposition reframe** (addressing-awareness; free, no LLM). A message `@`-mentioning a *different* agent no longer draws replies from every `always` member. Reframes the `respond_policy` enum as a **disposition** (`observer` / `addressed` / `participant`) with back-compat mapping. Owned by [`0030-amendment-relevance-gated-response-pr-plan.md`](rfcs/0030-amendment-relevance-gated-response-pr-plan.md) (Phase 1 deliverable). Per the [relevance amendment](rfcs/0030-amendment-relevance-gated-response.md).
- **Peer-voice prompt** (no RFC). A new `prompts/runtime/safety/` section that frames a persona in a group channel as a *peer/colleague*, not an assistant answering a user — complementing the existing [`reply-discretion.md`](../prompts/runtime/safety/reply-discretion.md) (silence is valid) and [`conversational-pacing.md`](../prompts/runtime/safety/conversational-pacing.md) (match register). The gate handles the cheap binary "may I speak"; the prompt carries the residual social judgment the gate cannot encode ([amendment §What is prompt, what is architecture](rfcs/0030-amendment-relevance-gated-response.md#what-is-prompt-what-is-architecture)).

The two structural workstreams already have RFC homes: [RFC 0034 §Phase 2](rfcs/0034-persona-conversational-working-memory.md#phase-2-group-channels-and-per-peer-prefixing) and the [RFC 0030 relevance-gated-response amendment](rfcs/0030-amendment-relevance-gated-response.md) (Tier A + disposition slice). Each gets a standalone PR plan opened as Phase 1 of this master plan; **this master plan wraps them** with the release contract + release-prep + tag phases.

**Out of scope** — explicitly deferred so they don't pressure the realism cut:

- **RFC 0030 relevance Tier B (cheap salience bid)** — v0.3.8. Tier B needs the in-round transcript that 0034 P2 provides; pairing it with the cost-ceiling / reply-budget / end-of-interaction layers is the v0.3.8 *"conversations that converge"* story. v0.3.7 ships Tier A alone (it is free and fixes the worst defect) per [amendment OQ #1](rfcs/0030-amendment-relevance-gated-response.md#open-questions).
- **Natural-language recipient parsing** ("question only to Iron Fox") — v0.3.8. v0.3.7 Tier A keys on **structured `@`-mentions only**; free-text addressing becomes a Tier-B salience signal once Tier B lands, per [amendment OQ #2](rfcs/0030-amendment-relevance-gated-response.md#open-questions). Decided 2026-06-04 (see [Open-question status](#open-question-status)).
- **The `chair` disposition** + Layer 5 bid-and-select / moderator — v0.3.8 (Tier B threshold semantics) and v0.4.0 (moderator). v0.3.7 ships the three core dispositions only; `chair`'s distinguishing behaviour (low threshold) has no meaning until Tier B exists.
- **Salience-threshold calibration** ([amendment OQ #3](rfcs/0030-amendment-relevance-gated-response.md#open-questions)) — belongs to Tier B; no threshold ships in v0.3.7.
- **RFC 0030 main Layers 1/2/4/5** (cost ceiling, reply budget, end-of-interaction votes, moderator) and their [OQ-1…10](rfcs/0030-multi-agent-conversation-governance.md#open-questions) — all v0.3.8+. None block v0.3.7.
- **RFC 0034 Phase 3** (instrumentation/tuning of `max_turns` / `max_tokens`, LRU cache bound) — a later v0.3.x patch per [0034 PR plan §Future Phases](rfcs/0034-pr-plan.md#future-phases).

The load-bearing companions are the two Phase-1 PR plans (see [Related documentation](#related-documentation)).

## Why this plan exists

The two PR plans (0034 Phase 2, the relevance-gate Tier A slice) could ship as independent RFC workstreams. Three reasons they get an umbrella:

1. **A patch release needs a release contract, not just PR sequences.** Per [ROADMAP §Version Map](../ROADMAP.md#version-map), a version is defined by what a user *can do*; v0.3.7's promise — "watch a group conversation that reads like colleagues" — is a release-level gate no single PR owns. It is jointly delivered by transcript-awareness (0034 P2), addressing-awareness (Tier A), and voice (the prompt); the acceptance bar is the *combined* manual-test outcome, not any one workstream's unit suite.

2. **The realism cluster is cross-cutting and must compose.** 0034 P2 supplies the in-round transcript; the peer-voice prompt shapes how a persona uses it; Tier A decides who reaches the turn at all. A regression in any one re-opens the v0.3.6 manual-test defect (personas answer questions aimed at someone else, pile on, talk like assistants). One plan owns the join.

3. **Two source documents are out of date and must be reconciled before implementation.** The [relevance amendment](rfcs/0030-amendment-relevance-gated-response.md) predates this sequencing: its status line reads *"not scheduled; open questions unresolved,"* and its body sequences the whole gate *"with the v0.3.8 patch"* and treats RFC 0034 P2 as v0.3.8 — but the active sequencing puts **0034 P2 and Tier A in v0.3.7, Tier B in v0.3.8**. Reconciling that (a doc-only fix in Phase 1) is a prerequisite so each PR plan cites a coherent target. This plan owns the reconciliation.

Same thin-orchestration shape as [v0.3.6-plan.md](v0.3.6-plan.md): the RFC PR plans own the internals; this doc owns which phases, in what order, by what release gate.

## Acceptance for v0.3.7

The promise — *watch a group channel read like colleagues: personas build on the transcript, the right people speak, a question to one isn't answered by everyone* — is met when:

- **Group-channel working memory is live (RFC 0034 P2).** On a multi-peer channel, a persona's LLM `messages` array carries the last-N turns with **every peer message prefixed `[<peer_id>]: `** and the persona's own turns mapped to `assistant` ([RFC §C](rfcs/0034-persona-conversational-working-memory.md#c-role-mapping)/[§G](rfcs/0034-persona-conversational-working-memory.md#g-group-channel-handling)). Integration test: two peers + one persona; the persona resolves a pronoun referring to *the other peer's* prior turn.
- **The window cache is correct for multi-persona channels.** The in-process `_WINDOW_CACHE` no longer assumes one persona per channel: it keys on the fetch limit (or bypasses for multi-persona channels) so a small-`max_turns` persona cannot serve an undersized window to a large-`max_turns` peer reacting to the same inbound message ([0034 PR plan §Future Phases carry-forward](rfcs/0034-pr-plan.md#future-phases)). (LRU/eviction stays a Phase 3 concern.)
- **Tier A eligibility fixes directedness (RFC 0030 amendment).** A message `@`-mentioning agent X does **not** admit `participant` agent Y; the sender-self and `observer` cases are always filtered; an un-addressed open-floor message admits all `participant`s (forwarded to the turn, since Tier B does not exist yet). The Trigger repro — `"how about you @ember-owl?"` draws **exactly one** reply (Ember Owl) — passes.
- **The disposition reframe ships with back-compat.** `respond_policy` accepts the disposition vocabulary (`observer` / `addressed` / `participant`) in `schemas/channel.schema.json`; existing configs keep working via `always → participant`, `when_mentioned → addressed`, `never → observer`. The demo personas are `participant`. `@here` / "everyone" disables the directed-elsewhere filter ([amendment OQ #5](rfcs/0030-amendment-relevance-gated-response.md#open-questions), default adopted).
- **The idle-cost invariant survives.** Tier A is free (no LLM, no recall) and runs before any provider call; the RFC 0023/0024 "uninvolved persona costs zero" guarantee is re-asserted by the existing cost-regression gate (no new LLM call introduced by Tier A; an idle persona still costs zero tokens).
- **The peer-voice prompt is in place and composes.** A new `prompts/runtime/safety/` section frames the persona as a peer/colleague in group channels (address people by name, build on prior turns, disagree or defer rather than perform "I'm an assistant"), wired through prompt assembly alongside `reply-discretion.md` and `conversational-pacing.md`; a prompt-assembly unit test asserts it is present for group-channel turns.
- **The combined story is documented and demonstrable.** `MT-CHANNEL-RELEVANCE-001` (directedness + no-pile-on-on-directed-messages, structured-mention scope) and the 0034-P2 group-channel continuity manual test are authored and pass live; CHANGELOG `[0.3.7]` describes the realism win and the `respond_policy → disposition` config note (additive, back-compat); `docs/guides/` channel/persona docs name the new vocabulary.

Out of acceptance: Tier B salience bid; natural-language recipient parsing; the `chair` disposition; threshold calibration; RFC 0030 Layers 1/2/4/5; RFC 0034 Phase 3 (all v0.3.8+ per the **Out of scope** list above).

## Risk and mitigations

The per-PR implementation risks live in the two Phase-1 PR plans (authored in Phase 1). The release-level risks:

| Risk | Mitigation |
|------|------------|
| 0034 P2 is the critical path; if it slips, the realism story slips. | Tier A + the peer-voice prompt ship as standalone quick wins with **no** 0034 dependency, so v0.3.7 has visible value (directedness fixed, colleague voice) even if P2 takes longer. The sequencing amendment names this fall-back explicitly. |
| The multi-persona window-cache bug ships latent if treated as a Phase-3 concern. | It is pulled **into v0.3.7 acceptance** (correctness, not capacity) — distinct from the Phase-3 LRU/eviction work. The 0034 P2 PR plan must carry the cache-key fix + its regression test as a gate. |
| Tier A re-architects a code-review-able invariant (response-gate admission); a regression silently re-opens the v0.3.6 "everyone answers everything" defect. | `MT-CHANNEL-RELEVANCE-001` + the Trigger repro are release-prep gates re-run live on HEAD; the cost-regression gate asserts no new LLM-call origin and idle-cost-zero preserved. |
| The disposition reframe touches schema + config; an existing channel config breaks on upgrade. | Back-compat mapping (`always`/`when_mentioned`/`never` → disposition) + a back-compat load test; the per-disposition threshold field is reserved/no-op until v0.3.8 so no behaviour rides on it yet; CHANGELOG frames it as additive. |
| Three workstreams in one patch read as scope creep vs. one bundle. | Each is part of a single user-facing story (realism) per the [Version Map contract](../ROADMAP.md#version-map); bundling Tier B / convergence would *blur* it. [§Candidate fold-ins](#candidate-fold-ins-maintainer-decision) makes every addition an explicit opt-in; default is the realism three. |
| The peer-voice prompt alone is mistaken for the directedness fix. | The amendment records that a peer-framing prompt alone does **not** fix directedness (that is structural, in the gate). The prompt is scoped to *voice/social judgment*; Tier A owns directedness. Both ship; acceptance separates their gates. |
